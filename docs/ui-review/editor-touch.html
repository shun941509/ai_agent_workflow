320px 편집기 연결도

내 자료로 안내하기 실습의 블록 6개와 연결 8개를 같은 320 × 568px Chrome 화면에서 비교했다. 줌은 수정 전 30%, 수정 후 30%다.

전체 보기 전후

직접 눌러 확인한 결과

  • 그림에 있는 블록 6개와 연결점 5개의 중심을 누르면 각각 속성 패널과 연결 추가 창이 열렸다. 중심에서 가로·세로로 각각 10px 벗어난 네 모서리가 의도한 단추에 들어간 경우는 수정 전 2/44, 수정 후 44/44였다.
  • 수정 후에는 네 모서리 44곳과 화면에 보이는 둥근 소켓 5곳을 Chrome의 터치 입력으로 직접 눌렀다. 49곳 모두 해당 버튼에서 실제 터치 이벤트를 받았고 예상한 창이 열렸다. 여섯 블록의 이름 전체가 표시됐다.
  • 다섯 경로를 화면에서 눌러 각각의 연결을 선택했다. 한 경로에 함께 표시한 실행과 데이터, 별도로 보이는 참조를 범례에서 차례로 강조했다. SVG 경로의 양 끝과 화면에 그려진 소켓 중심의 최대 차이는 0.01 CSS px였다.

접근성과 화면 폭

axe-core 4.10.3로 전체 화면을 검사했다. WCAG 2.2 AA의 대상 크기 지적은 320px에서 8건 → 0건, 390px에서 7건 → 0건, 1440px에서 0건 → 0건이었다. 수정 후 세 화면의 axe 위반 합계는 0건이었다.

세 너비에서 페이지 가로 넘침과 예상 밖 콘솔 오류는 없었다. 검증 후 저장된 실제 블록과 연결이 처음과 일치했다. 터치 검증 환경은 Windows Chrome의 모바일 터치 모드다.
