## 화면별 추가 수정

- **홈·가이드** — 목적별 실습을 선택한 채 창 너비를 바꿀 때 사라지던 키보드 포커스를 현재 선택 항목으로 이어 주고 강제 색상용 체크 표시를 추가했다. 그림을 1배↔2배 바꿀 때 읽던 위치를 보존한다. 검색 결과가 없을 때 필터를 지울 수 있게 했다. 재방문 홈의 그래프는 입력이 같은 동안 연결선 배치를 재사용한다.
- **편집기** — 반복 입력 삭제 후 포커스가 본문으로 빠진 문제, 작성 중 JSON 입력 재서식, 원문·MCP·Workflow 버전·자동 시작 읽기 실패의 재시도를 개선했다. 내보내기 결과의 스크롤 영역에 이름과 키보드 접근을 제공한다.
- **자료·실행** — 등록, 상세, 수정과 취소 후 포커스를 복원한다. 긴 실행 제목은 홈과 같은 컴포넌트로 두 줄 표시와 전체 이름 펼치기를 제공한다.
- **개발 시안** — 좁은 화면에서 숨었던 실습·템플릿·작업실 경로에 접근할 수 있게 했다. 블록을 선택하면 속성으로, 결과를 닫으면 실행 버튼으로 포커스가 돌아온다.
- **게시 판단** — 저장 중인 판단과 근거가 요청 도중 바뀌었다가 화면에서 사라지지 않도록 입력 상태를 고정했다. 응답을 지연한 회귀 시험으로 확인한다.

## 독립 검토에서 다시 수정한 항목

- 게시판의 공개 범위를 바꿔 ‘게시’를 선택하고 원래 범위로 돌아왔을 때, 제출할 수 없는 ‘게시’ 선택과 안내가 남았다. 현재 범위에 허용되지 않는 판단만 초기화하도록 수정했다. 동일한 브라우저 조작에서 입력한 근거가 보존되고 제출 버튼이 비활성인 것을 확인했다.
- 긴 자료의 관리 동작과 본문을 같은 화면에서 사용할 수 있게 원문 읽기 영역을 조정했다.
- 블록을 끌지 않고 포인터만으로 위치를 바꿀 수 있도록 속성에 좌표 입력과 방향 버튼을 추가했다. 동일한 편집 이력과 저장 경로를 사용한다.
- 개발 시안의 프로덕션 경로에서 404 본문이 표시된 뒤 브라우저 탭이 개발 시안 제목으로 바뀌었다. 개발 콘텐츠와 스타일을 인증된 개발 경로에서만 불러오고 프로덕션의 제목은 404 메타데이터를 쓰도록 수정했다. 최종 검토는 프로덕션의 404뿐 아니라 개발 서버의 홈·편집·실행 화면을 포함한다.

### 첫 실습의 진입점과 캡처

첫 화면에 도서관 예제의 시작 버튼과 완성할 결과를 배치했다. 편집기의 시험 실행 버튼, 회원증 질문과 질문 실행 버튼, 신분증을 안내한 완료 답변을 실제 제품 캡처에서 잘라 500×230px WebP 세 장으로 저장했다. 그림의 조작 위치와 설명은 단계별 안내로 연결된다. 준비물 확인, 새 대화로 변경한 지시 다시 시험하기, 내 업무 예제로 넘어가는 경로도 첫 화면에서 찾을 수 있다. [가이드 전후 비교](ui-review/guide.html) · [실습 사용법](FIRST_WORKFLOW_GUIDE.md)

모델 미연결·첫 방문 상태의 React 렌더링에서 소개·결과·세 단계 안내가 공백 포함 약 436자였다. FAQ를 닫은 채 내비게이션과 다음 실습까지 포함한 첫 페이지는 약 1,430자였다. 1~2분은 첫 작업을 파악하는 예상 읽기 시간이다. 실제 사용자의 읽기 속도나 모델 실행 대기시간을 측정한 수치는 없다. [첫 화면 본문](../src/ui/guide/FirstGuideStart.tsx) · [질문 예시](../src/ui/guide/FirstGuideQuestions.tsx)

### 복사 요청이 늦게 끝나는 경우

- 이전 검증 빌드에서 최신 게시판 주소의 복사 권한 응답을 보류하고 고정판 입력란을 선택했다. 거부 응답이 오자 포커스가 최신판으로 되돌아갔다. 자료함과 Agent 공유 화면에 읽기 전용 입력을 복사하는 공통 처리를 적용했다. 현재 입력값, 화면에 연결된 입력란, 마지막 요청을 확인하고 사용자가 이동한 포커스를 보존한다. [공통 처리](../src/ui/use-copy-field.ts) · [자료함 회귀 시험](../tests/resource-library-browser.ts)
- 자동 시작을 해제했다가 재활성화한 뒤 이전 성공 응답을 보내자 새 이벤트 토큰에 복사 완료가 표시됐다. 가이드에서는 사용자가 시험 질문을 선택한 뒤 지시 복사가 거부됐을 때 지시 문장이 다시 선택됐다. 새 토큰의 표시 상태와 본문 선택 범위를 각각 보호했다. 같은 브라우저 절차로 재검사한 결과를 보관했다. [수정 전 관찰](../.local/ui-continuous/nov27-copy-controls-controls-before.json) · [수정 후 관찰](../.local/ui-continuous/nov27-copy-controls-novice-after.json)

가이드 개편 이후의 전체 검증에는 실제 화면 이동, 회귀 명령, 반응형과 접근성 검사를 포함한다. 측정값과 도구 한계는 [QA 보고서](QA-REPORT.md)에서 확인할 수 있다.

### 가이드 그림에서 실제 동작까지

- 도서관 질문과 이용규정, 신분증 답변의 순서를 FigJam에 그렸다. ImageGen으로 만든 개념 삽화를 1050×375px WebP로 변환하고 한글 설명을 웹 텍스트로 붙였다. [FigJam](https://www.figma.com/board/UfGEEVFYyMVIeMgi7Obst1) · [개념과 실제 활용 사례](../src/ui/guide/GuideVisualConcepts.tsx)
- 격리된 작업실에서 **새 Agent**로 이름을 입력하고 입문 템플릿을 골라 사본을 만들었다. 그 화면에서 촬영한 다섯 장에 번호·화살표와 버튼 이름을 붙였다. 시험 실행 세 단계와 FAQ의 막힌 상태도 같은 방식으로 확대해 읽을 수 있다. [생성 과정](../src/ui/guide/GuideCreationVisual.tsx) · [문제 해결 그림](../src/ui/guide/GuideHelpVisual.tsx)
- 문서 정리와 반복 업무의 미리보기에서 돌아왔을 때 선택한 사례와 링크의 포커스를 복원하도록 수정했다.
- 편집기에서 **실습 안내**를 열 때도 일반 업무 사례가 먼저 나타나 게시 실습의 단계가 뒤로 밀렸다. 해당 실습에서 들어온 경우에는 원래 실습의 목표와 순서를 먼저 보여 준다. 처음부터 **목적별로 만들기**를 연 경우에는 업무 사례를 고를 수 있다. 기존 브라우저 시험이 확인하던 첫 번째 단계 목록과 게시 사본 선택 조건을 유지했다. [실습 안내 순서](../src/ui/WorkflowGuide.tsx) · [기존 회귀 시험](../tests/browser-smoke.ts)

### 승인안 인계 검증

엔진과 내보내기 변경을 포함한 루트 빌드를 새 데이터베이스 두 개에서 검토했다.

필수 단계와 선택 실습의 목록을 구별하고, 출력이 여럿인 분류 블록에서 연결 대상을 선택하는 실제 절차를 회귀 시험으로 대조했다. 최종 빌드에서 브라우저 스크립트 35개가 모두 통과했다. 단위·통합 시험은 390개 통과, 실패·취소·건너뜀 0개였다. 타입 검사 두 방식과 프로덕션 빌드도 성공했다. [최종 QA](QA-REPORT.md) · [화면 전후 비교](ui-review/index.html) · [첫 실습 가이드](ui-review/guide.html)
