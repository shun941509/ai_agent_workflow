# 도서관 첫 실습 가이드의 화면과 검증 기준

작업실 왼쪽 메뉴에서 **가이드 → 처음 시작하기 → 예제로 시작하기**를 선택하면 ‘질문에서 답변까지’ 실습 사본이 열린다. 작은 화면에서는 먼저 **메뉴 열기**를 누른다. 같은 브라우저와 계정에서 **예제 편집기 열기**를 누르면 작업하던 사본으로 돌아간다.

## 단계별 원본 화면

| 단계 | 실제 제품에서 확인할 것 | 원본 PNG |
| --- | --- | --- |
| 1. 준비 확인 | 작업실 홈의 가이드 위치와 상단 모델 상태 | [가이드 진입](../public/guide/captures/01-start.png) |
| 2. 예제 열기 | 가이드의 시작 버튼을 눌러 내 편집기 사본을 연다. 질문 입력에서 도서관 안내 Agent를 거쳐 답변 전달로 이어지는 세 블록과 이용규정 블록을 찾는다. | [시작 버튼](../public/guide/captures/02-start-example.png) · [예제 편집기](../public/guide/captures/02-editor.png) |

| 5. 지시 바꾸기 | 도서관 안내 Agent의 작업 지시만 수정한다. 실행 기록에서 새 대화를 열어 같은 질문을 보낸 뒤 두 답변을 비교한다. | [작업 지시](../public/guide/captures/05-instruction.png) · [다시 받은 답변](../public/guide/captures/05-compare.png) |

각 단계의 **이 단계에서 막혔을 때**에는 안내가 바로 보인다. **문제 해결**을 누르면 1단계는 모델 설정, 2단계는 블록·연결선 찾기, 3단계는 질문 실행 불가, 4단계는 실행 실패, 5단계는 작업 지시 확인으로 이동한다. 다른 문제를 선택하거나 그 문제를 새 탭에서 열어도 **N단계로 돌아가기**는 실습을 시작한 단계로 이어진다.

5단계에서는 **작업 지시 복사**를 누르고 예제 편집기를 열어 지시를 바꾼다. 첫 답변이 아직 없으면 편집기 안내에서 먼저 회원증 질문을 실행할 수 있다. **시험 질문 복사**로 같은 질문을 새 대화에서 실행한 뒤 변경 전후 답변을 비교한다. 편집기의 **전체 가이드**는 현재 작업을 설명하는 단계로 이어진다.

## 목적별로 만들기에서 업무나 템플릿 고르기

**가이드 → 목적별로 만들기**에서 ‘업무 문서 만들기’를 찾는다. 할 일 앱 요구사항은 **내 사본으로 시작**을 누른다. 회의록·업무 보고와 반도체·제조 보고는 **이 업무로 설계하기**에서 자신의 메모나 CSV를 넣을 수 있다. [업무별 입력과 출력 예시](WORKFLOW_USE_CASES.ko.md)

도서관 템플릿을 고르면 기존 블록 배치, **입력 예시**, **실행 조건**, **출력 예시**가 보인다. 그림을 누르면 원본 크기나 2배로 블록과 연결선을 볼 수 있다. 사본을 만들려면 **이 템플릿 열기**를 누른다.

| 템플릿 | 블록 배치와 실습에서 확인할 결과 |
| --- | --- |
| 입문 · 질문에서 답변까지 | [도서관 안내 Agent와 규정](../public/guide/captures/terms-workflow.png)을 보고 지시를 바꾸면, 준비물 답변에 근거 문장이 붙는다. |
| 초급 · 내 자료로 안내하기 | [안내 파일을 만드는 블록](../public/guide/captures/goal-beginner.png)을 따라 수정한 대출 한도가 화면과 대출안내.txt에 함께 반영되는지 본다. 선택 실습에서는 ‘도서관 이용규정’ 속성의 **내 참고 자료로 저장**으로 5권 규정을 보관한다. 새 초급 사본은 3권으로 시작한다. 새 사본의 같은 블록에서 **속성 → 이름·자료판 설정 → 연결할 자료**로 저장한 규정을 선택한 뒤, 새 대화의 답변과 대출안내.txt에 5권 규정이 인용되는지 확인한다. |
| 중급 · 근거 찾기와 추가 질문 | [질문이 나뉘는 두 지점](../public/guide/captures/goal-intermediate.png)을 찾고, 분실물 안내문을 추가했을 때 대기 중인 답변이 어떻게 완성되는지 본다. |
| 중급 · 도서관 방문 준비하기 | [운영시간·예약·규정을 읽는 블록](../public/guide/captures/goal-library-visit.png)을 찾고 수령 규정의 판에 따라 준비물 안내가 달라지는지 본다. |
| 고급 · 두 담당자에게 병렬로 맡기기 | [팀의 위치](../public/guide/captures/goal-parallel.png)와 [두 담당자의 내부 배치](../public/guide/captures/goal-parallel-team.png)를 보고, **회원증 담당 안내문 → 회원증 담당 자료 검색** 참조선에서 **연결선 삭제**를 누른다. 같은 질문을 다시 보내면 토요일 운영시간은 유지되고 준비물만 미확인으로 바뀐다. |
| 고급 · 동료 Agent와 초안 검토하기 | [검토 팀](../public/guide/captures/goal-peer-review.png)의 [초안 교환과 검토 기록](../public/guide/captures/goal-peer-review-team.png)을 따라 최종 안내문의 교정 근거를 확인한다. 선택 실습에서는 팀에 **교정 사유 표시 Skill**을 연결하고 **사실 검토 담당의 동료 검토 → 전달받을 상위 Skill**에서 선택한다. 같은 초안을 다시 검토하면 두 담당자 모두 폐관 시각을 6시에서 4시로 바로잡고, 사실 검토 담당의 기록에만 교정 사유 한 줄이 붙는다. |
| 전문가 · 지점 조사팀의 생성 한도와 실패 처리 설계 | [지점별 담당자 생성](../public/guide/captures/goal-dynamic.png)과 [담당자 한 명의 작업](../public/guide/captures/goal-dynamic-team.png)을 보고, 일부 지점이 미완료일 때 결과를 모으는 경우와 중단하는 경우를 비교한다. 선택 실습에서는 결과 수집 정책으로 ‘중앙도서관, 강변도서관’을 먼저 조사한 뒤 **지점별 조사 담당 생성 → 도구 및 자료 → 참고 자료**에서 **강변도서관 보완 안내문**을 추가한다. 같은 질문으로 다시 실행하면 중앙의 평일 오전 9시 인용은 유지되고, 강변의 근거 부족이 평일 오전 11시 개관 원문으로 바뀐다. |
| 전문가 · 규정 변경 검증·게시·복구 | [후보판의 블록과 규정](../public/guide/captures/goal-release.png)을 보고 게시·보류·복구 결정에 따라 새 대화와 기존 대화에서 어느 판의 답을 받는지 확인한다. |

실제 캡처의 설명과 번호 위치는 [목적별 캡처 목록](../src/ui/guide/goal-captures.ts)에서, 조건별 결과 설명은 [템플릿별 안내](../src/ui/guide/template-outcomes.ts)에서 관리한다.

지점 조사 실습에서는 선택한 정책에 맞는 완료 기준을 읽는다. 기본 자료와 네 지점 질문에서 총 2명·동시 1명으로 결과 수집을 선택하고 중앙과 강변을 고르면 중앙은 확인, 강변은 근거 부족, 호수와 숲은 선택 제외가 된다. 총 4명으로 같은 질문을 실행하면 선택 제외는 0곳이다.

중단 정책을 비교할 때는 회신하기 전에 **조사 순서**를 확인한다. 동시 1명에서 강변을 먼저 고르면 강변의 근거 부족으로 다음 지점 조사를 시작하기 전에 멈춘다. 실행 기록에서 중단한 지점과 사유를 확인할 수 있다. 동시 3명 이상으로 바꾼 사본은 자유 실험이며, 기본 실습으로 돌아가려면 **지점별 조사 담당 생성 → 고급 설정**에서 동시 실행 상한을 2명 이하로 맞춘다.

초급 사본에 파일 생성 블록이 없으면 화면의 3권·5권 답변과 인용을 비교한다. 파일을 내려받는 실습은 **수준별 템플릿 → 초급 → 내 자료로 안내하기 → 내 사본으로 시작**에서 연다. 같은 이름의 자료가 보이면 원문과 판을 확인한 뒤 **이 판 연결**을 누른다.

초급에서 이전 시험 기록을 연 뒤 이용규정을 고쳤다면 **시험에 사용할 원문**을 확인한다. **현재 원문 · 새 대화**로 5권 규정을 시험하거나, **이전 원문 · 같은 대화**를 골라 그 대화의 3권 규정으로 계속 질문할 수 있다. 중급에서 추가 안내문을 쓰다가 실습 안내를 열었을 때는 **편집으로 돌아가기**로 대기 중인 회신을 이어 쓴다.

‘규정 변경 검증·게시·복구’를 **내 사본 만들기**로 복사했다면 **프로젝트 메뉴 → 버전 → 현재 초안 버전 저장**에서 첫 판을 만든다. 기준판과 후보판, 시험 사례 세 개, 게시 판단 기록까지 준비된 실습은 사본의 **실습 안내 → 기준판·후보판이 준비된 실습 열기**에서 시작한다.

**기능·용어 → 그림으로 볼 용어**에서 이름을 선택하면 뜻과 실제 편집기 화면이 함께 바뀐다. 그림을 누르면 번호가 표시된 부분을 확대할 수 있다.

## 블록과 메뉴 사용법 찾기

가이드 상단에는 **처음 시작하기**, **목적별로 만들기**, **기능·용어**, **문제 해결**, **블록·자료 찾아보기**, **메뉴별 사용법**이 같은 탭 목록에 있다. **처음 시작하기**를 다시 선택하면 읽던 실습 단계로 돌아온다.

**블록·자료 찾아보기**에는 편집기의 블록 32개가 처음 추천하는 수준별로 보인다. 검색창에 이름이나 하려는 일을 입력하거나 **블록 추천 수준**에서 수준을 고르면 목록이 좁혀진다. 자료 4종은 검색어로 찾을 수 있고, 각 설명에는 ‘도서관 방문 준비하기’에서 그 자료를 사용하는 블록이 표시된다. 작은 화면에서는 **자료 설명으로 이동**을 눌러 자료를 바로 볼 수 있다.

`MCP`를 검색하면 **MCP 연결**에서 **사용하는 블록 · 도구 사용(중급)**의 정의를 열 수 있다. **검색 결과로 돌아가기**를 누르면 원래 검색어와 추천 수준을 그대로 사용한다.

**메뉴별 사용법**은 작업실 왼쪽 메뉴와 같은 순서로 아홉 메뉴의 아이콘·이름·설명을 보여준다.

## 첫 실행과 비교 실행

두 실행에는 **회원증을 만들려면 무엇을 준비해야 하나요?**라는 같은 질문과 같은 자료를 사용했다. 샘플 계정의 첫 실습 사본에서 실제 OpenAI 모델을 호출한 결과는 다음과 같았다.

- **첫 실행**에서 신분증을 준비하라는 답변과 ‘완료’ 상태를 확인했다.
- **비교 실행**에서는 작업 지시를 “답을 쓰고 다음 줄에 안내문의 근거 문장을 그대로 인용하세요.”로 바꿨다. 새 대화에서 다시 보내자 신분증 안내 다음에 “회원증을 처음 만들 때는 신분증을 가져오세요.”라는 원문이 나왔다.

이 실습의 성공 기준은 준비물과 규정이 맞는지, 지시를 바꾼 뒤 근거 문장이 추가되는지다. 위 답변의 말투는 실행마다 달라질 수 있다. 가이드는 읽던 단계를 기억한다. 실제 실습 결과는 사용자가 편집기에서 확인하고 직접 표시한다.

- [가이드 페이지](../src/ui/guide/GuidePage.tsx)는 읽던 단계와 실습 확인을, [단계별 안내](../src/ui/guide/GuideWalkthrough.tsx)는 이미지·조작 순서와 문장 복사를 담당한다. [스타일](../src/ui/guide/GuidePage.module.css)은 작은 화면에 맞게 배치를 조정한다. [확대 보기](../src/ui/guide/GuideFigure.tsx)는 실제 PNG 위에 설명용 번호와 테두리를 그린다.
- [단계별 문구](../src/ui/guide/content.ts)에는 조작 순서와 완료 기준이, [캡처 목록](../src/ui/guide/captures.ts)에는 원본 크기·대체 설명·캡션·강조할 위치가 있다. 제품 화면이 바뀌면 해당 단계의 원본과 위치를 함께 교체한다.
- [작업실](../src/ui/Studio.tsx), [공통 메뉴](../src/ui/WorkspaceNav.tsx), [편집기](../src/ui/editor/Editor.tsx)는 가이드 주소와 실제 사본 열기·복귀를 담당한다. [입문 템플릿](../src/domain/templates.ts)과 [편집기 실습 안내](../src/ui/editor/practice-steps.tsx)는 같은 회원증 질문을 쓴다.
- [가이드 브라우저 시험](../tests/workflow-guide-browser.ts)은 데스크톱과 모바일 크기에서 가이드와 편집기를 오가며 조작을 검사한다. 반복 시험의 답변에는 테스트용 모델을 쓴다. 이 문서에 연결된 답변 캡처 두 장은 실제 모델을 호출해 따로 확보했다.

## 검증 환경과 도구

제품 확인·캡처, 학습 문구, UI 구현, 브라우저 검증을 나누어 진행했다. `grill-me`와 Product Design의 `audit`로 첫 답변을 얻는 데 필요한 조작을 추렸고, `frontend-design`으로 작업실의 글꼴과 색을 사용해 화면을 구성했다. UI Consistency의 `accessibility`로 키보드 동선과 대비를 점검했다. 페이지 이동과 이미지 표시에는 프로젝트에 설치된 Next.js 문서를 참고했다.

Chrome과 Playwright로 1440×900과 390×844에서 첫 예제의 생성·실행·결과 비교, 다시 열기, 키보드 복귀를 확인했다. 320×568에서도 시작 버튼 전체가 첫 화면에 들어오고 이미지 확대와 단계 이동이 가능했다. 모바일 검증에는 터치 화면 에뮬레이션을 사용했다.
