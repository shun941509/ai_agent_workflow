# 통합 개발 목표와 인수 기준

Windows에서 웹, 실행기, 도서관 MCP를 한 명령으로 시작할 수 있어야 한다. 코딩 경험이 없는 이용자도 웹에서 Agent를 만들고 수정하고 공유할 수 있어야 한다. 설정, 저장 후 다시 열기, 실제 실행의 성공과 실패를 모두 확인해 완료 여부를 판정한다. 오프라인 회귀 시험과 실제 OpenAI 모델 검증은 따로 기록한다.

## 제작과 편집

- 한 문장으로 새 설계를 제안받거나, 빈 캔버스에서 직접 만들거나, 템플릿을 사본으로 연다. 사용자는 기존 설계에 대한 AI 변경안의 기준 초안과 변경 대상 블록·연결을 확인한 뒤 변경안을 한 번에 적용할 수 있다. 필요하면 적용한 변경 전체를 되돌릴 수 있다. 기존 블록의 위치와 사용자가 직접 설정한 권한을 보존한다. 실제 출력과 제공된 예시를 구별한다.
- 왼쪽에는 탐색과 블록 팔레트의 **추천**, **전체 32종**, **즐겨찾기 블록**, 가운데에는 캔버스, 오른쪽에는 선택한 블록의 속성을 배치한다. 초기 시안에서 이 배치를 A로, 블록 카드와 연결선 디자인을 B로 구분했다. 필수 설정을 먼저 표시하고 입출력과 고급 설정은 필요할 때 펼칠 수 있게 한다. 카드 요약은 설정을 반영한다. 상위 캔버스에서는 팀을 하나의 블록으로 표시한다. 팀을 열면 내부 담당자와 연결을 편집할 수 있다.
- 실행선은 실선, 데이터선은 파선, 참조선은 점선으로 표시한다. 출발 블록과 도착 블록이 같은 선을 화면에서 묶어도 각 연결의 종류와 출발·도착 포트의 식별자는 따로 저장한다. 연결선을 선택하면 분기 이름과 어느 출력이 다음 블록의 어느 입력으로 이어지는지 확인할 수 있어야 한다. 끌어서 연결할 때와 목록 또는 키보드로 연결할 때 같은 규칙이 적용된다. 오류 위치로 이동해 수정할 수 있으며 미완성 초안도 저장할 수 있다.
- 자동 저장, 복제, 삭제, 배치, 자동 정렬, 내보내기, 가져오기를 제공한다. 편집을 되돌리거나 되돌린 편집을 다시 적용할 수 있다. 이전 시안에서 가져온 블록의 식별자, 이름, 작업 방식, 위치와 연결을 보존한다. 지원하지 않는 코드 블록과 용도가 불분명한 연결선은 초안에서 고칠 수 있게 한다.

## 기능 목록

팔레트는 아래 32종 블록 메뉴를 제공해야 한다. 고급의 **사람 검토**와 전문가의 **문맥 정리·압축**은 각각 별도 블록으로 제공한다. 캔버스에서 검토할 결과와 요약의 길이 제한을 확인할 수 있어야 한다.

| 처음 추천하는 수준 | 추가되는 블록 수 | 블록 메뉴 |
|---|---:|---|
| 입문 | 4 | 사용자 입력, AI 작업, 답변 전달, 자료 가져오기 |
| 초급 | 4 | 입력 양식·추가 질문, 파일 입력, 문서 내용 읽기, 파일 만들기 |
| 중급 | 10 | AI 분류, 조건 분기, 자료 검색, 근거·출처 확인, 도구 사용, 행동 승인, 값 변환, 데이터 검증, 오류 처리, 민감정보 검사·처리 |
| 고급 | 11 | Agent 팀, Agent에게 작업 전달, 병렬 작업, 결과 모으기, Workflow 재사용, 사람 검토, 기억 읽기·쓰기, 시작 조건, 반복 처리, 담당자·작업 선택, 결과 평가 |
| 전문가 | 3 | 필요한 Agent 만들기, 지식 저장소 관리, 문맥 정리·압축 |

입문 수준의 **추천**에서 **AI 작업**을 새로 추가하면 **한 번 답하기**로 시작한다. 사용자가 **목표까지 반복**을 직접 선택하면 해당 방식을 적용한다.

**작업 지침·Skill**과 **MCP 연결**은 블록 속성에서 참조로 연결한다. 실행기는 이전 **종료·중단**, **회신 기다리기**를 포함해 41개 유형을 지원한다. **입력 양식·추가 질문**에서는 입력 항목과 회신 기한을 함께 설정할 수 있다.

| 블록 | 속성에서 선택할 수 있는 방식 |
|---|---|
| 답변 전달 | 답변 반환, 완료 안내, 실행 중지, 실패 처리 |
| 오류 처리 | 후속 단계로 계속, 중단 |
| AI 작업 | 한 번 답하기, 목표까지 반복 |
| Agent에게 작업 전달 | 결과 돌려받기, 담당 넘기기 |
| Workflow 재사용 | 정해진 단계에서 호출, Agent가 도구로 호출 |

전문가 추천 또는 **전체 32종**을 열면 **도구 사용**의 작업 방식으로 **보상 작업**을 선택할 수 있다. 변경을 되돌릴 때 호출할 도구와 인자를 지정한다. **담당자·작업 선택**의 **담당자 한 명 선택**은 이름 하나를, **작업 순서 정하기**는 후속 블록이 사용할 작업 순서 목록을 반환한다. 이전 설계의 **보상 작업**, **작업 조정**, **후보 탐색·선택** 블록은 저장된 방식으로 열린다.

## 엔진과 자산

- 같은 실행기로 단독 Agent와 팀 내부의 하위 Agent를 실행한다. 미리 연결한 작업을 병렬로 실행하거나 입력 대상마다 담당자를 만들어 실행할 수 있어야 한다. 실행 한도와 허용 도구는 하위 역할에도 적용한다. 실행 기록에서 도구를 선택하거나 호출한 Agent와 단계별 입력·결과를 확인할 수 있어야 한다. **병렬 작업**은 연결한 경로들을 동시 실행 한도 안에서 시작한다. 모든 경로가 성공하면 각 경로를 한 번씩 실행한 결과가 **결과 모으기**에 모여야 한다. 일부 경로가 실패할 때도 확인한다. **성공 결과 수집**과 **미확인 항목과 함께**를 선택하면 완료한 항목과 실패 내역을 구분해 반환해야 한다. **전체 중단**을 선택하면 실패가 발생한 차수 뒤에 새 작업을 시작하지 않아야 한다.
- RAG는 자료 준비부터 색인, 버전 고정, 질문별 검색, 근거 확인과 인용까지 지원한다. 설계자가 **자료 검색** 블록을 배치하거나 Agent가 검색 도구를 선택하게 할 수 있다. 검색된 문서의 버전, 원문 위치, 발췌문을 기록한다. 해당 구절이 질문에 답할 근거가 되는지 확인하고, 근거 상충과 근거 부족, 검색 오류를 구분한다. 검색, 모델로 전달, 출처 표시에는 모두 자료 접근 권한을 적용한다.
- 자료는 답변 근거를, Skill은 작업 지침을 제공한다. MCP는 허용된 도구를 호출하는 데 사용한다. 양식에 직접 작성하거나 `SKILL.md` 파일 한 개, 폴더 또는 ZIP을 올려 Skill을 등록할 수 있다. 부속 파일을 가져올 때는 `scripts/`, `references/`, `assets/` 아래의 상대 경로를 유지한다. 코드는 미리 볼 수 있다. 스크립트 실행이 필수라고 표시한 Skill 버전을 연결하면 Agent 실행과 게시를 막고 그 이유를 안내해야 한다. Skill 코드는 서버에서 자동 실행하지 않는다.
- 도서관 MCP는 예약 조회·생성·취소를 처리한다. 실제 사용에서 이용자는 본인 계정의 도서 예약만 조회·생성·취소할 수 있다. 로그인한 이용자는 공개 Agent에 질문할 수 있다. 공유받은 Agent로 시험 예약을 하려면 내 사본을 만든 뒤 **시험 데이터**로 실행한다. 외부 HTTP MCP는 운영자가 등록하며 연결별로 허용 도구, 시험 환경, 자격 증명을 관리한다. 자료나 도구 응답에 들어 있는 지시는 Agent의 도구 실행 권한을 바꾸지 않는다.

## 계정·버전·공유·시험

- 작업실과 공유 주소는 로그인 후 열 수 있다. 아이디·비밀번호로 로그인하거나 새 계정을 만든 뒤 처음 요청한 화면으로 이동한다. 이 브라우저에 이전 게스트 작업이 남아 있으면 새로 가입한 계정으로 옮긴다. 기존 계정으로 로그인할 때는 이 작업을 가져올지 선택할 수 있다. 모델은 서버에서 호출하며 이용자는 개인 API 키를 입력하지 않는다.
- Agent와 자료·Skill·MCP 정의에는 **나만 사용**, **비밀 링크**, **모두에게 공개** 중에서 공유 범위를 설정한다. 비밀 링크는 철회할 수 있다. 게시 버전과 초안은 분리하며 공개 목록에는 공개 항목만 표시한다. 사본은 원본과 독립적이다. 자격 증명은 복사하거나 노출하지 않는다. 공유받을 사람이 연결된 자료 버전을 읽을 수 없으면 게시를 막고 이유를 안내해야 한다. 제작자는 대상 이용자가 읽을 수 있는 자료 버전을 연결한다. 민감정보를 가려야 한다면 별도 버전을 만들어 공유한다. 연결을 바꾼 뒤에는 새 Agent 버전을 저장해 게시한다.
- 공유 범위를 유지하고 링크를 새로 발급하지 않으면, 게시 버전을 교체하거나 이전 버전으로 복구한 뒤에도 기존 공유 주소를 사용할 수 있어야 한다. 진행 중인 대화와 승인 대기 중인 실행은 시작할 때 고른 설계, 자료, Skill, 색인의 버전을 유지한다. 재개할 때는 현재 접근 권한도 확인한다. 공유 주소에서 새 대화를 시작하면 그 시점에 게시된 버전을 사용한다. 대화 간 기억은 설계에 포함된 **기억 읽기·쓰기**를 통해서만 공유한다.
- 개인 실행의 입력·출력·근거·도구 호출 내역은 실행자만 볼 수 있어야 한다. 제작자는 자신의 상세 실행 기록을 볼 수 있고, 프로젝트 전체 실행은 완료·실패·대기·중지 등 상태별 건수로 확인할 수 있어야 한다.
- 개인 시험 사례는 입력, 자료, 기대 결과를 포함한다. 같은 사례로 버전을 비교할 때 각 실행은 같은 초기 상태에서 시작하며 독립된 시험 데이터를 사용한다. 시험 예약은 실제 예약과 분리한다. 시험 전용 환경이 없는 커넥터는 시험 중 실서비스를 호출하지 않는다. 설계 구조나 권한이 올바르지 않으면 게시를 차단한다. 품질 시험 결과를 보고 게시할지는 제작자가 결정한다.
- 승인은 승인한 이용자, 도구, 실제 인자와 요청 식별자에 연결한다. 인자가 바뀌면 새 승인이 필요하다. 실행을 중지하면 아직 전송하지 않은 작업을 보내지 않고 대기 중인 승인을 종료한다. 재시도는 새 실행에서 진행한다. 외부 변경 요청의 응답을 받지 못했다면 요청 식별자로 이전 처리 결과를 먼저 확인한다. 조회할 수 없으면 미확인 상태로 보존한다.

## 수준별 도서관 실습 8개

| 실습 | 할 일과 확인할 결과 |
|---|---|
| 입문 · 답변 지시 | 회원증 준비물을 묻고 첫 답변을 확인한다. **작업 지시**를 바꿔 답변 다음 줄에 안내문 한 문장을 그대로 인용하도록 한다. 수정한 지시를 적용한 뒤 새 시험 대화에서 같은 질문을 보낸다. 답변에 신분증이 필요하다는 안내가 있고, 다음 줄의 인용이 원문과 일치하는지 확인한다. |
| 초급 · 내 자료 | **현재 초안**으로 예시 질문을 보내 답변과 인용에서 대출 한도 3권을 확인한다. 같은 사본의 규정을 5권으로 바꾸고 **변경 적용**을 누른다. **현재 원문 · 새 대화**에서 처음 질문을 다시 보낸 뒤 새 답변의 **대출안내.txt 내려받기**를 누른다. 화면과 파일에서 같은 답변과 원문 인용을 확인하고, 새 사본의 3권 규정과 비교한다. |
| 중급 · 검색과 추가 질문 | 네 번의 시험은 각각 새 대화에서 시작한다. 먼저 대출 한도를 묻고 답변에서 3권이라고 명시한 규정 문장을 찾는다. 다음 두 대화에서는 분실물 보관 기간을 묻는다. 추가 질문에 14일이 적힌 안내문을 보내면 그 기간을 인용하고, 지점명만 보내면 보관 기간을 확인할 수 없다고 답하는지 확인한다. 마지막 새 대화에서 “제가 신청한 도서 예약 목록을 조회해 주세요.”라고 묻고 **내 예약 조회 → 예약 조회 결과**로 진행하는지 확인한다. |
| 중급 · 도서관 방문 준비하기 | 지식 저장소에서 토요일 운영시간을 찾고, 참고 자료에서 수령 규정을 읽고, 도서관 MCP에서 시험 예약을 조회한다. 첫 답변이 Skill에서 정한 방문 시간·준비물·예약 내역 순서인지 확인한다. **수령 규정** 블록의 **고정할 자료 버전**만 1판에서 2판으로 바꾸고 저장한 다음 같은 시험 사례를 다시 실행한다. 준비물 안내가 ‘회원증이 필요합니다.’에서 ‘모바일 회원증도 가능합니다.’로 바뀌고, 방문 시간과 시험 예약 내역은 같은지 확인한다. |
| 고급 · 병렬 분담 | 두 하위 Agent가 도서관 운영시간과 회원증 발급 준비물을 각각 조사한다. 회원증 자료가 빠져도 운영시간과 출처를 보존해 최종 답변 한 건을 만든다. |
| 고급 · 동료 검토 | 캔버스의 연결선을 따라 각 초안이 어느 동료에게 전달되는지 찾고, 최종 안내문 아래 두 기록에서 누가 누구의 초안을 검토했는지 확인한다. 두 검토자 모두 토요일 폐관 시각을 오후 6시에서 오후 4시로 고쳤는지, 근거로 인용한 문장이 도서관 원문과 일치하는지 확인한다. |
| 전문가 · 동적 생성 | 조사 후보는 네 지점이며 동시에 조사할 수 있는 담당자는 최대 두 명이다. 학습자는 전체 생성 한도, 동시 실행 한도, 일부 조사를 끝내지 못했을 때의 처리 방식을 정한다. 각 차수의 담당자 수와 지점별 원문 근거를 확인한다. 자료가 없는 지점, 조사에 오류가 난 지점, 선택하지 않은 지점을 구별한다. |
| 전문가 · 버전 검증·복구 | 승인된 변경은 대출 한도를 3권에서 5권으로 높이는 것뿐이다. 비공개 기준판과 후보판에 같은 질문을 보내 대출 한도를 비교하고, 일요일 휴관 안내가 유지되는지, 규정에 없는 분실물 보관 일수를 추측하지 않는지 확인한다. 이 결과를 근거로 후보판의 게시 또는 보류를 결정하고 이유를 기록한다. 새 버전을 게시한 뒤에는 그 상태를 유지할지 이전 버전으로 복구할지 판단한다. |

버전 실습에서 방문자 대화도 비교할 때는 같은 비밀 링크에서 다음을 확인한다.

1. 후보판의 게시 여부를 결정하기 전에 1판을 게시한다. 방문자 계정으로 대출 한도를 물어 3권 답변을 받는다.
2. 2판을 보류했다면 기존 대화와 새 대화가 모두 3권을 안내해야 한다. 2판을 게시했다면 1판에서 시작한 대화와 게시 후 새로 시작한 대화에 같은 질문을 보낸다. 기존 대화는 3권, 새 대화는 5권이라고 답해야 한다.
3. 복구를 시험하려면 5권 답변을 받은 방문자 대화를 남겨 둔 뒤 1판으로 복구한다. 같은 대출 질문을 다시 보내면 2판 대화는 5권을, 복구 후 새로 시작한 대화는 3권을 안내해야 한다.

## 출시 전 확인

1. Windows에서 의존성을 아직 설치하지 않았고 데이터베이스도 없는 소스 사본을 준비한다. 그 사본에서 `start.cmd`를 실행해 웹, 실행기, 도서관 MCP가 모두 시작되는지 확인한다.
2. 빈 캔버스에서 직접 만들거나 AI 제안, 기존 설계, 템플릿, 이전 형식에서 가져온 파일로 시작해 완성한 설계가 모두 같은 검사기와 실행기를 사용하는지 확인한다.
3. 실제 모델을 연결한 서버에 새 회의 메모를 보내 실행을 완료한다. 보낸 메모와 실행 기록의 답변을 대조해 결정사항과 담당자 이름이 일치하고, 담당자가 정해지지 않은 항목은 ‘미정’으로 표시됐는지 확인한다.
4. 병렬 도서관 실습에서 회원증 담당의 자료 연결만 해제한다. 운영시간 답변과 인용이 그대로 유지되고, 회원증 준비물은 확인할 수 없다고 안내하는지 확인한다.
5. 도서관 MCP가 예약을 저장한 직후 응답을 끊고 해당 Workflow 실행을 중지한다. MCP를 재시작한 뒤 중지한 문답에서 **원래 요청의 처리 결과 다시 확인**을 눌러 예약이 처리됐는지 확인한다. 같은 문답에서 **같은 입력으로 새 실행**을 눌러 재시도하고 예약을 승인한다. 예약은 한 건이어야 하며 중지한 실행에서는 후속 도구 호출이 발생하면 안 된다.
6. 로그인하기 전에는 작업실과 공유 링크가 로그인 화면으로 이어지는지 확인한다. 로그인한 두 계정으로 공개 항목과 비밀 링크에 접근한 뒤 철회한 링크는 열 수 없는지 확인한다. 사본이 원본과 독립적인지, 방문자가 게시 버전만 사용하며 다른 사람의 예약과 실행 기록을 읽을 수 없는지 확인한다.
7. 데스크톱과 모바일에서 편집, 연결, 실행, 대기 중 응답, 다시 열기를 확인한다. 키보드만으로도 이 작업을 모두 완료할 수 있어야 한다. 수동 관찰, 격리 회귀 시험, 실제 외부 서비스 결과를 구분해 기록한다.
