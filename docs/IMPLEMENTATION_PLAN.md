# 통합 개발 목표와 인수 기준

Windows에서 한 명령으로 시작한 실제 웹·실행기·MCP에서 비전문가가 Agent를 만들고 수정하고 공유한다. 완료 판정은 설정, 저장·재열기, 실제 실행, 성공과 실패의 관찰을 함께 확인한다. 오프라인 회귀 시험과 실제 OpenAI 검증을 별개로 기록한다.

## 제작과 편집

- 한 문장으로 새 설계를 제안받거나, 빈 캔버스에서 직접 만들거나, 템플릿을 사본으로 연다. 기존 설계에 대한 AI 변경안은 기준 초안·수정할 블록과 연결을 확인한 뒤 한 번에 적용·되돌린다. 기존 위치와 직접 설정한 권한을 보존한다. 실제 출력과 제공된 예시를 구별한다.
- 탐색·추천/전체/즐겨찾기 팔레트, 중앙 캔버스, 오른쪽 속성의 A 배치에 B 블록·선 디자인을 적용한다. 블록의 필수 설정을 먼저 보여 주고, 입출력과 고급 설정은 펼친다. 카드 요약은 설정을 반영한다. 팀은 상위 한 블록으로 보고 들어가서 실제 협업 그래프를 편집한다.
- 진행 실선·데이터 파선·참조 점선을 사용한다. 같은 방향 연결은 화면에서 묶되 실제 순서와 안정적인 포트 식별자 기반 값 전달을 별도로 저장한다. 분기 이름과 전달값을 펼쳐 확인한다. 끌기와 목록/키보드 연결이 같은 규칙을 사용한다. 오류의 위치로 이동해 고칠 수 있고 미완성 초안 저장을 허용한다.
- 자동 저장, 복제·삭제·배치·자동 정렬, 되돌리기·다시 실행, 내보내기·가져오기를 제공한다. 이전 시안의 식별자·이름·모드·B 좌표·연결을 보존하고, 미지원 코드 블록과 모호한 선은 초안에서 고칠 수 있게 한다.

## 기능 목록

Workflow 설계의 블록 메뉴는 아래 32종으로 확정한다. **사람 검토**(고급)와 **문맥 정리·압축**(전문가)은 각각 독립 블록으로 유지해, 캔버스에서 검토할 결과와 길이 제한이 적용되는 요약 단계를 바로 확인할 수 있게 한다.

| 첫 소개 | 블록 메뉴 |
|---|---|
| 입문 4 | 사용자 입력, AI 작업, 답변 전달, 자료 가져오기 |
| 초급 4 | 입력 양식·추가 질문, 파일 입력, 문서 내용 읽기, 파일 만들기 |
| 중급 10 | AI 분류, 조건 분기, 자료 검색, 근거·출처 확인, 도구 사용, 행동 승인, 값 변환, 데이터 검증, 오류 처리, 민감정보 검사·처리 |
| 고급 11 | Agent 팀, Agent에게 작업 전달, 병렬 작업, 결과 모으기, Workflow 재사용, 사람 검토, 기억 읽기·쓰기, 시작 조건, 반복 처리, 담당자·작업 선택, 결과 평가 |
| 전문가 3 | 필요한 Agent 만들기, 지식 저장소 관리, 문맥 정리·압축 |

입문 수준의 **추천**에서 **AI 작업**을 새로 추가하면 **한 번 답하기**로 시작한다. 사용자가 **목표까지 반복**을 직접 선택하면 해당 방식을 적용한다.

편집기는 32개 메뉴와 두 종류의 참조를 제공한다. 답변 전달에서 답변 반환·완료 안내·실행 중지·실패 처리를 선택한다. 오류 처리는 후속 단계로 계속하거나 중단할 수 있다. 실행기는 기존 종료·중단과 회신 대기를 포함해 41개 유형을 지원한다. 입력 양식·추가 질문에서 입력 항목과 회신 기한을 함께 설정할 수 있다. AI 작업은 1회/목표 반복, 작업 전달은 부모에게 결과 반환/담당 인계, Workflow 재사용은 직접 호출/Agent 선택 도구를 지원한다. Skill과 MCP 서버는 Agent 속성에서 연결한다.

전문가 수준의 **도구 사용 → 보상 작업**에서는 되돌리기에 쓸 도구와 인자를 지정한다. **담당자·작업 선택**의 **담당자 한 명 선택**은 이름 하나를, **작업 순서 정하기**는 후속 블록이 사용할 순서 목록을 반환한다. 이전 설계에서 사용하던 보상 작업, 작업 조정, 후보 탐색·선택 블록은 저장된 방식으로 열린다.

## 엔진과 자산

- 단일·팀·하위·병렬·동적 Agent를 같은 실행기로 구동한다. 실행 한도와 허용 도구는 하위 역할에도 적용한다. 누가 제안한 도구인지, 어느 단계의 입력·결과인지 관찰할 수 있어야 한다. 병렬 작업은 선택된 경로를 각각 한 번 처리하고 합류한다. 미확인·일부 실패 항목과 성공한 항목을 구분한다.
- RAG는 자료 준비·색인·버전 고정·질문별 검색·근거 확인·인용까지 다룬다. 명시적 검색 단계와 Agent가 선택한 검색 도구를 제공한다. 검색된 문서의 판본·원문 위치·발췌문을 기록한다. 후보가 실제 주장을 지지하는지 확인하고 상충·부족·검색 오류를 구분한다. 검색·모델 전달·출처 표시 모두 자료 접근 권한을 따른다.
- 자료는 근거, Skill은 지침, MCP는 허용된 작업을 담당한다. Skill 등록은 양식·단일 SKILL.md·폴더·ZIP을 지원하며 scripts/references/assets 상대 경로를 보존한다. 코드 미리보기를 제공하며 필수 스크립트가 있으면 실행 전 미지원 상태를 알린다. Skill 코드를 서버에서 자동 실행하지 않는다.
- 도서관 MCP는 실제 예약 조회·생성·취소를 처리한다. 실제 회원 예약은 실행자 본인 소유로 제한한다. 로그인한 사용자는 공개 Q&A와 시험 예약을 체험한다. 외부 HTTP MCP는 운영자가 등록하고, 연결별 허용 도구·시험 환경·자격증명을 관리한다. 자료나 도구 출력의 문장으로 행동 권한을 얻을 수 없다.

## 계정·버전·공유·시험

- 작업실과 공유 주소는 로그인 후 열 수 있다. 아이디·비밀번호로 로그인하거나 새 계정을 만든 뒤 처음 요청한 화면으로 이동한다. 이전 게스트의 작업은 가입할 때 승계하며 기존 계정에 로그인할 때는 가져올지 선택할 수 있다. 서버 측 모델을 사용하며 이용자는 개인 API 키를 입력하지 않는다.
- Agent와 각 자료·Skill·MCP 정의는 개인/공개/철회 가능한 비밀 링크로 공유한다. 게시 버전과 초안은 분리하고 공개 목록에는 공개 항목만 노출한다. 사본은 원본과 독립적이다. 자격증명은 복사·노출하지 않는다. 수신자에게 보여 줄 수 없는 의존성은 공유판이나 가림판으로 교체해야 한다.
- 공개 주소는 게시·복구 중 유지한다. 진행 중인 대화와 대기 중 승인은 시작한 설계·자료·Skill·색인 판을 사용하며 재개할 때 현재 권한도 확인한다. 새 대화는 새 게시판에서 시작한다. 설계한 기억 블록을 통해서만 대화 간 기억을 공유한다.
- 개인 실행의 입력·출력·근거·도구 내용을 실행자에게만 제공한다. 제작자에게는 자신의 기록과 다른 사용자에 대한 성공·실패 집계를 제공한다.
- 개인 시험 사례는 입력·자료·기대 결과를 포함한다. 버전마다 동일한 초기 상태의 독립된 시험 데이터를 사용하고 실제 예약과 분리한다. 시험 전용 환경이 없는 커넥터는 시험 중 실서비스를 호출하지 않는다. 잘못된 구조·권한은 게시를 차단하며, 품질 시험에 따른 게시 여부는 제작자가 결정한다.
- 승인 주체·도구·실제 인자·요청 식별자를 결합한다. 인자 변경 시 재승인한다. 중지는 미전송 작업과 대기 승인을 닫고, 재시도는 새 실행에서 진행한다. 응답이 유실된 외부 쓰기는 기존 영수증을 먼저 확인한다. 조회 수단이 없으면 미확인 상태로 보존한다.

## 5수준 8실습

| 실습 | 사용자가 변경하고 확인할 결과 |
|---|---|
| 입문 · 답변 지시 | 회원증 질문에 답한 다음, 작업 지시를 원문 한 문장을 다음 줄에 인용하는 지시로 교체한다. 같은 질문을 다시 보내 신분증 안내와 인용을 대조한다. |
| 초급 · 내 자료 | 사본의 규정을 3권에서 5권으로 바꾸고 ‘대출안내.txt’를 내려받는다. 화면과 파일에서 같은 답변과 원문 인용을 확인하고, 새 사본의 3권 규정과 비교한다. |
| 중급 · 검색과 추가 질문 | 대출 한도 질문으로 3권의 원문을 찾는다. 분실물 질문에 14일이 적힌 안내문을 회신한 경우와 지점명만 회신한 경우를 비교한다. 내 예약 목록 질문으로 예약 조회 경로를 확인한다. |
| 중급 · 도서관 방문 준비하기 | 지식 저장소에서 토요일 운영시간을 찾고, 참고 자료에서 수령 규정을 읽고, 도서관 MCP에서 시험 예약을 조회한다. Skill이 정한 방문 시간·준비물·예약 내역 순서로 답변을 확인한 뒤 수령 규정만 2판으로 바꿔 같은 사례를 다시 시험한다. |
| 고급 · 병렬 분담 | 두 하위 Agent가 시간과 회원증을 조사한다. 회원증 근거가 없더라도 운영시간과 출처를 보존하여 최종 답변 한 건을 낸다. |
| 고급 · 동료 검토 | 각 초안에서 상대 검토자로 향하는 선을 따라간다. 최종 안내문 아래 두 검토 기록에서 검토자, 상대 초안, 교정 전후 문장과 근거 원문을 대조한다. |
| 전문가 · 동적 생성 | 네 지점과 동시 실행 두 자리라는 조건에서 학습자가 총 생성 한도, 동시 실행 한도, 조사 미완료 시 계속·중단을 정한다. 생성 차수와 지점별 원문을 대조하고, 자료가 없는 지점·담당 작업 오류·선택에서 제외된 지점을 구별한다. |
| 전문가 · 버전 검증·복구 | 비공개 기준판과 후보판에서 대출·휴관일·근거 부족 사례를 비교하고 게시·보류 및 유지·복구를 판단한다. 방문자 대화까지 검증할 때는 1판을 비밀 링크로 게시하고 미리 대출 질문을 보낸다. 같은 주소에서 기존 대화와 새 대화를 비교해 각 대화에 적용된 판을 확인한다. |

## 출시 전 확인

1. 깨끗한 Windows 설치에서 웹·실행기·MCP가 한 명령으로 기동한다.
2. 빈 캔버스·AI 초기 제안·기존 설계 수정·템플릿·이전 파일이 같은 검사기와 실행기를 사용한다.
3. 처음 입력하는 회의 내용에서 결정·담당자를 뽑고, 담당자가 없는 항목은 미정으로 표시한다. 실제 모델이 실행했다는 증거가 있어야 한다.
4. 도서관 병렬 RAG에서 회원증 근거를 제거해도 운영시간과 원문은 정확하고, 근거 없는 준비물을 단정하지 않는다.
5. 외부 예약 저장 직후 응답을 끊고 중지·재시작·재시도한다. 외부 예약은 한 건, 중지 후 다음 작업은 0건이어야 한다.
6. 로그인 전에는 작업실과 공유 링크가 로그인 화면으로 이어지는지 확인한다. 로그인 후에는 두 계정으로 공개·비밀 링크·철회·사본·초안·게시 버전·다른 사람의 예약과 기록을 검사한다.
7. 데스크톱·모바일·키보드에서 편집·연결·실행·대기 응답·재열기를 확인한다. 수동 관찰, 격리 회귀 시험, 실제 외부 서비스 결과를 구분해 기록한다.
