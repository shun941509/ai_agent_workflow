# Agent 내보내기 ZIP과 Studio 실행 비교

2026-11-26 · 팔레트 32종, 작업 방식과 참조를 포함한 내부 블록 유형 41종

**32개 메뉴의 지침은 모두 ZIP에 들어간다. 가장 먼저 고칠 부분은 단계 사이에 전달하는 값, 실행 가능한 도구의 범위, 실패했을 때 갈 경로다.** 예를 들어 AI 분류에서 ‘예약’ 경로를 택해도 다음 블록이 받는 값은 사용자의 원래 질문이다. 현재 ZIP에는 ‘예약’ 경로가 표시되지만 ‘원래 질문을 그대로 반환한다’는 규칙이 빠져 있다.

번호는 편집기의 블록 사용 안내서와 같다. ‘환경 연결’은 수신자의 클라이언트나 외부 서비스가 있어야 완료할 수 있는 부분이다.

| 번호 | 블록 | ZIP에서 확인한 내용 | 개선하거나 검증할 동작 |
|---:|---|---|---|
| 01 | 사용자 입력 | 시작 블록과 예시 질문, 다음 연결 | 실제 요청을 예시보다 우선한다. 최상위에서 첨부와 함께 온 질문, 하위 설계로 전달한 구조화된 값을 구분한다. |
| 02 | AI 작업 | 단발·반복 모드, 목표·지시·완료 기준, 도구·횟수 설정 | 단발 도구 0개, 반복형의 실효 허용 목록, 마지막 판단까지 답을 얻지 못했을 때의 실패를 명시한다. 검색 결과가 입력이면 원문으로 최종 인용을 검증한다. |

| 04 | 자료 가져오기 | 선택한 원문·판·사용 단계, 제외한 원문의 재연결 안내 | 본문 데이터와 출처 메타데이터를 구분한다. 문서의 원래 ID를 쓰는 후속 단계까지 같은 값을 받는지 확인한다. |
| 05 | 입력 양식·추가 질문 | 질문·필드·회신 기한·응답 객체. 기존 회신 기다리기 방식도 출력 | 필수값이 빠지면 같은 요청으로 보완한다. 요청 시각·만료·기한 내 접수 기준과 오류 경로, 다음 문답에 남길 필드의 범위를 정의한다. |

| 11 | 자료 검색 | 검색어·검색 방식·상한·자료판과 결과 구절 필드 | 원문 행과 위치, 결과 0건, 식별자를 보존한다. 문자 그대로 검색하는 방식의 정규화와 관련도순의 점수·동점 순서를 재현할 수준을 정한다. |

| 13 | 도구 사용 | 일반 호출·보상 작업 이름과 인자, 외부 변경 전 승인 | 판과 역할별 도구 범위, 읽기 전용 여부, 내장 도구의 수신 측 연결을 명시한다. 변경이나 보상 처리 여부를 모르면 재호출 전에 확인한다. |
| 14 | 행동 승인 | 연결·도구·인자 제시, 한 번의 승인, 승인·거절 경로 | `{approved, approvalId, args}`를 전달하고 다음 호출이 승인된 정확한 대상과 인자를 사용하게 한다. 거절·인자 변경·응답 유실을 각각 시험한다. |
| 15 | 값 변환 | 선택·이름 바꾸기·텍스트 변환과 경로 | 없는 경로는 오류, 존재하는 빈 값은 유효한 값으로 구분한다. 이름 변경 시 새 객체의 모양, 여러 값의 문자열 변환 순서를 명시한다. |
| 16 | 데이터 검증 | 필수 필드와 형식 표 | JSON 문자열을 객체로 검사하고 통과한 값을 보존한다. 중첩 경로·누락·빈 문자열·null·배열을 구분하고 실패를 연결된 오류 처리로 넘긴다. |
| 17 | 오류 처리 | 계속·중단, 안내 문구, 연결선 | 성공 시 ‘작업 후’로 실행되는 것처럼 보이는 연결을 바로잡는다. 실제 실패한 단계와 사유만 전달하고 여러 실패의 순서, 대체 문구 적용, 중단을 구분한다. |

| 20 | Agent에게 작업 전달 | 명시적 위임·인계에 공통 역할 원문과 세 클라이언트 등록 파일, 작업 번호 | 위임의 결과 반환과 인계한 책임의 지속은 유지한다. 담당자가 다른 두 경로의 합류 후 책임자와, 하위 설계가 없는 역할의 도구 사용 범위를 보완한다. |
| 21 | 병렬 작업 | 동시 실행 상한, 하위 Agent 호출 ID, 미완료 호출 대기, 일부 실패 정책 | 실행선과 값 전달을 구분한다. 병렬 시작 전의 값과 별도 데이터선의 값이 다를 때 후자를 받는지, 중지 후 새 외부 작업을 시작하지 않는지 시험한다. |
| 22 | 결과 모으기 | 시작된 경로 대기, 연결 순서, 실패 처리, 목록·텍스트·제목/본문 형식 | 실제 실패와 `error` 필드를 가진 정상 업무 데이터를 구분한다. 실패한 경로에 데이터선이 없거나 결과가 하나뿐일 때도 상태·형식이 설계와 맞아야 한다. |
| 23 | Workflow 재사용 | 고정된 하위판, 단계 호출과 Agent가 선택하는 도구 호출 | 도구 호출 종료는 호출했던 Agent의 다음 판단으로 돌려보낸다. 같은 정의를 여러 곳에서 호출해도 호출자별 입력·자료·도구 권한을 이어받게 한다. |
| 24 | 사람 검토 | 초안을 보여 주고 직접 회신을 기다린 후 의견을 전달 | 같은 대화에서의 기본 동작은 충실하다. 동시에 여러 초안을 검토하거나 대화를 재개할 때 어느 초안·경로에 대한 회신인지 식별한다. |
| 25 | 기억 읽기·쓰기 | 읽기·쓰기와 기억 이름 | **환경 연결.** Studio는 이용자·프로젝트·시험/실사용별로 저장한다. 사용할 저장소, 키 범위, 값 없음·재조회 동작을 정하고 새 대화에서 확인한다. |

| 27 | 반복 처리 | 항목별 하위 호출, 순서대로 결과 수집, 반복 상한 | 입력 두 개에 상한 1이면 Studio는 첫 항목도 실행하지 않고 오류를 낸다. 시작 전 검사, 오류 처리선, 빈 배열·단일 입력의 결과를 명시한다. |

## Skill·MCP와 큰 역할 문서

- **상위 Agent의 MCP를 쓰는 도구형 Workflow.** 정상 설계에서 Studio는 호출자의 MCP 1판을 하위 도구에 전달하고 완료했다. 같은 ZIP에는 서버 설정이 있는데도 하위 호출의 도구 이름이 ‘연결이 필요한 MCP 도구’로 바뀌었다. 내보내기가 도구를 정의한 위치에서만 하위 단계를 작성하기 때문이다. 하나의 도구형 Workflow를 여러 Agent가 각자의 자료·도구 범위로 부를 수 있으므로, 호출자가 판과 도구 이름을 하위 단계에 전달하고 결과를 돌려받는 절차가 필요하다. [호출자 기준 검사](../src/server/run-assets.ts) · [ZIP 하위 그래프 방문](../src/server/agent-zip.ts)
- **Skill.** 선택한 Skill 원문·부속 파일과 Claude용 참조 경로는 보존됐다. 필수 스크립트가 있다고 등록한 Skill은 Studio의 실행 준비 검사에서 거절됐지만 ZIP에는 원문과 부속 파일이 들어갔다. 어떤 단계가 스크립트를 요구하는지 내보내기 전에 알려야 한다. 이번 점검에서 스크립트를 실행하지 않았다. [자료판 검사](../src/server/assets.ts) · [Skill ZIP 경로](../src/server/agent-skill-export.ts)
- **MCP.** 첫 미리보기에서 MCP는 선택 해제돼 있고, 선택한 원격 서버는 세 클라이언트의 설정에 들어간다. 수동 연결만 가능한 서버는 README에 안내된다. Codex 설정에는 서버의 허용 도구 목록도 들어가지만, 생성된 Claude Code·OpenCode 설정에는 이에 해당하는 필터가 없다. 역할 등록 파일도 개별 도구 제한을 강제하지 않는다. 서버가 제공하는 전체 도구, 설계가 허용한 도구, 호스트가 강제하는 제한을 구분해 보여 줄 필요가 있다. [미리보기](../src/ui/editor/AgentExportDialog.tsx) · [MCP 설정](../src/server/agent-mcp-export.ts) · [역할 등록](../src/server/agent-role-files.ts)
- **큰 역할 문서.** 긴 지시를 같은 QA 역할에 12번 배정한 표본에서 루트는 9,442바이트였지만 QA 역할 원문은 52,840바이트였다. 역할을 여는 시점에 모든 배정이 한 파일에 들어온다. 길어진 역할만 작업 번호별 문서로 나누고 현재 배정으로 직접 연결하면 작은 설계의 간결함을 유지할 수 있다. [역할 문서 생성](../src/server/agent-delegation.ts)
- **재개와 전체 실행 한도.** Studio는 단계·모델 호출·도구 호출·생성 Agent의 실행 전체 횟수를 기록하고 완료된 작업을 재개할 때 다시 차감하지 않는다. ZIP에는 개별 블록 한도가 표시된다. 긴 설계를 중단했다가 다시 열 때에는 남은 한도, 완료한 단계, 대기 중인 호출과 승인 상태를 확인할 방법이 필요하다. 호스트에서 확인할 수 없는 외부 작업의 처리 상태는 ‘미확인’으로 남기는 편이 안전하다. [Studio 세션](../src/engine/session.ts) · [ZIP 공통 지침](../src/server/agent-zip.ts)
- **반복형 AI의 완료 판정.** 점검 중 갱신된 Studio 구현은 완료 기준에 대해 충족·미충족·확인 필요를 판정한다. 읽기 도구 실패와 변경 도구 실패의 후속 처리도 다르다. ZIP에는 작성자가 넣은 완료 기준과 횟수가 보이므로, 결과를 받은 뒤 이 판정을 언제 하고 어떤 경우에 재시도하거나 종료하는지까지 단계에 추가할 수 있다. [모델을 호출하는 단계](../src/engine/operations.ts)

## 권장 검증 순서

1. **같은 입력의 다음 단계 값을 대조한다.** 41개 내부 유형별로 정상·실패 사례를 두고 Studio의 출력값·선택 포트·실패 상태를 기록한다. ZIP의 단일·분할 지침에 같은 입력·출력 구조·중단 규칙이 있는지 확인한다. 먼저 분류 → 원래 질문, 파일 생성 → 본문 변환, 자료 검색 → 문서 ID, 한도 초과 → 대상 선택을 고정한다.
2. **잘못된 외부 작업이 나가지 않는지 확인한다.** 단발 AI의 도구 0개, 읽기만 허용한 역할, MCP 판 충돌, 승인 거절, 전송 후 응답 유실, 민감정보 차단을 검사한다. 실제 변경을 일으키지 않는 관찰용 도구로 호출 수와 인자를 확인한다.
3. **세 클라이언트의 대표 설계를 끝까지 실행한다.** 각각 ‘실제 첨부 → 파싱 → 결과 파일’, ‘조건 분기 → 병렬 위임 → 합류’, ‘승인 → 도구 → 응답 유실 후 재개’, ‘Agent가 Workflow를 도구로 호출 → 결과로 다음 판단’의 최종값과 호출 기록을 대조한다. Markdown과 호스트가 제공하는 기능으로 수행하고, 예약·영속 기억·자료판 변경처럼 연결이 필요한 단계는 실제 연결 여부도 기록한다.
