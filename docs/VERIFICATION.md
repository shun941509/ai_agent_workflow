## 실제 OpenAI 모델 시험 결과

2026년 11월 21일, 프로젝트의 24시간 키를 연결하고 기본 작업실을 재시작했다. OpenAI의 `gpt-6-astra` 모델 조회에서 HTTP 200을 확인했다. 첫 실행은 `credit_balance_exhausted`로 종료됐다. 크레딧 지급 후 같은 입문 실습에서 “회원증을 처음 만들 때 무엇을 가져가나요?”라고 묻자 “회원증을 처음 만들 때는 신분증을 가져오시면 됩니다.”라는 실제 답변과 `completed` 상태를 확인했다.

같은 날 Windows에서 임시 데이터베이스, 별도 웹 서버·실행기·도서관 MCP를 시작하고 같은 모델로 설계 제안·수정과 일곱 실습을 실행했다. 당시 `pnpm test:live`의 8개 시나리오가 모두 통과했다. 이후 두 전문가 실습을 학습자가 직접 정책과 게시 여부를 결정하도록 바꿨고, 변경한 두 시나리오를 실제 모델로 다시 실행해 모두 통과했다. [실제 서비스 인수 시험](../tests/live-service.ts)

**설계 제안·수정** — 빈 설계에서 회의록 입력, AI 작업, 답변 전달 블록을 생성했다. 초안은 담당자가 정해진 항목만 출력했다. 처음에는 담당자가 없는 항목을 ‘미정’으로 표시하도록 고쳐도 홍보 항목이 누락됐다. 수정 요청의 예외와 기존 포함·제외 조건을 블록의 완료 기준에 우선순위대로 저장하도록 고친 뒤 같은 원문을 다시 실행했다. 결과에는 확정된 ‘자료집 23권’과 담당자 ‘민걙’, 별도 항목 ‘다음 달 홍보 담당자는 정해지지 않았음’과 담당자 ‘미정’이 함께 나왔다. | 전문가 | 지점 조사팀의 생성 한도와 실패 처리 설계 | 총 4명·동시 2명에서 두 차수로 네 곳을 조사했다. 총 2명·동시 1명에서 강변과 중앙을 선택하자 수집 정책은 강변의 근거 부족, 중앙의 확인 결과, 선택에서 제외된 호수·숲을 구별했다. 같은 선택에 중단 정책을 적용하자 강변에서 멈추고 다음 담당자 생성과 최종 정리를 생략했다. |
| 전문가 | 규정 변경 검증·게시·복구 | 대출·일요일 운영·분실물 사례를 비교해 일요일에 연다고 답한 후보판을 보류했다. 휴관 안내를 고친 3판의 게시·유지와 1판 복구를 수행하고 대상 판·판단 근거를 다시 열어 확인했다. 같은 비밀 링크에서 방문자의 새 대화는 3권 → 5권 → 3권, 기존 대화는 시작 당시의 한도를 안내했다. |

위임·인계·동적 생성 때 지정된 역할이 모델에 전달되도록 실행기도 수정했다. 위임·동적 생성은 결과를 기존 담당자에게 돌려주고, 인계는 새 담당자가 후속 단계를 맡는지 실행기 회귀 시험에서 별도로 확인했다. [역할 처리](../src/engine/operations.ts) · [실행기 시험](../tests/engine.test.ts)

전문가 실습 변경 후 Windows Chromium에서 동적 정책을 고르기 전에는 사본을 만들 수 없고, 한도를 낮추면 허용 범위를 벗어난 동시 실행 수를 다시 선택하게 되는지 확인했다. 게시 실습에서는 1·2판의 같은 시험 사례를 비교할 수 있고, 보류·게시·복구 이유가 공유 설정을 닫았다 다시 열어도 남는지 확인했다. [브라우저 시험](../tests/browser-smoke.ts)

초급과 고급 동료 검토의 블록 배치를 변경한 뒤 두 실습을 실제 OpenAI 모델로 다시 실행했다. 초급에서는 규정을 수정한 사본이 5권, 원본과 별도 사본이 3권을 안내했고 각 파일에는 해당 답변과 인용이 그대로 담겼다. 동료 검토에서는 각 담당자가 상대 초안을 받아 토요일 폐관 시각을 원문에 따라 오후 4시로 고쳤다. 최종 답변에서 두 담당자의 이름, 실제 검토 대상과 각 검토 의견을 확인했다. 시험 모델로는 두 검토자가 동일한 의견을 쓰고 최종 정리 담당자가 검토자 이름을 모두 생략한 경우에도 두 기록이 각자의 제목 아래 남는 것을 확인했다. [실제 모델 시험](../tests/live-service.ts) · [검토 기록 시험](../tests/engine.test.ts)

### 2026년 11월 22일 · 블록 변경 후 실습과 하위 Agent 재검증

격리한 작업실에서 OpenAI `gpt-6-astra`로 위 일곱 실습을 모두 실행했다. 입문·초급은 지시와 원문을 바꿔 전후 답변을 비교했고, 중급은 안내문을 보낸 회신에서만 분실물 보관 기간 14일을 확인했다. 고급에서는 자료를 해제한 담당자와 자료가 있는 담당자의 결과를 비교하고, 서로의 초안을 고친 두 검토 기록을 확인했다.

동적 Agent의 첫 결과에서는 호수·숲도서관을 선택에서 제외하고도 모델이 그 이유를 확인해야 한다고 답했다. 생성 블록이 한도 때문에 이용자가 고른 지점 수와 요청한 지점 수를 후속 블록에 전달하도록 수정했다. 재시험에서 네 곳 중 두 곳을 선택한 이유, 강변도서관의 근거 부족, 호수·숲도서관의 선택 제외가 최종 답변에 따로 표시됐다. 게시 실습에서는 2판의 잘못된 일요일 10~16시 개관을 발견해 보류했다. 휴관으로 고친 3판을 게시하고 1판으로 복구한 뒤, 새 대화와 기존 대화의 대출 한도를 각각 확인했다. [두 전문가 실습의 검증 코드](../tests/live-service.ts)

상위 Skill 수신자를 회원증 담당과 운영시간 담당 사이에서 바꿔 두 차례 실행했다. 팀 목표에만 적은 임의의 행사표기는 두 담당자의 실제 답변에 모두 나왔다. Skill에만 적은 확인문구는 지정한 담당자에게서만 나왔고, 선택하지 않은 담당자는 모두 ‘지정 없음’이라고 답했다. 세 번째 실행에서는 인계 담당자와 동적으로 생성된 중앙도서관 담당자가 각자의 내부 Workflow에서 같은 행사표기와 자신이 받은 Skill의 문구만 답했다. 세 팀 실행에서 담당자 답변 여섯 개를 확인했다. [담당자별 실제 모델 시험](../tests/live-team-inheritance.ts)
