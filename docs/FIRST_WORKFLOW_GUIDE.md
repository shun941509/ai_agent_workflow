# 도서관 예제로 첫 Workflow 실행하기

작은 화면에서는 먼저 **메뉴 열기**를 누른다. 작업실 왼쪽 메뉴에서 **가이드**를 열고 **처음 시작하기** 탭에서 **예제로 시작하기**를 누르면 ‘질문에서 답변까지’ 실습 사본이 편집기에서 열린다. 같은 브라우저와 계정에서 **예제 편집기 열기**를 누르면 작업하던 사본으로 돌아간다.

**내 자료로 질문에 답하는 AI 만들기**에서 예제 질문과 완성할 결과를 먼저 확인할 수 있다. **예제를 연 뒤 따라 할 세 단계**의 화면을 누르면 편집기의 시험 실행, 질문 보내기, 답변 확인 방법으로 각각 이동한다. **질문을 구체적으로 쓰는 법**에서는 방문 목적을 밝혔을 때 어떤 준비물을 답할 수 있는지 보여 준다. **첫 실습에서 자주 묻는 질문**을 펼치면 문제 상황에 맞는 도움말을 열 수 있다. **모델 설정 필요**인 경우에도 예제와 자료를 열 수 있으며, 실제 AI 답변은 모델 연결 후 시험한다.

## 그림을 골라 보기

- **처음 시작하기**의 **Agent와 일반 채팅은 어떻게 다른가요?**를 펼치면 회원증 질문, 안내원이 읽는 규정과 답변을 차례로 볼 수 있다.
- **기능·용어**에서는 설계, 시험, 자료, 공유를 언제 쓰는지 확인한다. **목적별로 만들기**에서는 업무 도우미, 문서 정리, 정보 조사, 반복 업무 중 하나를 골라 입력과 결과를 대조한다.
- 화면이 예상과 다르면 첫 실습 FAQ에서 상황을 선택한다. **크게 보기**로 세부 내용을 읽고 **닫기** 또는 Escape로 돌아온다.

## 첫 실습 단계와 화면

작업실 홈의 **예제로 배우기**에서는 수준별 템플릿을 골라 실습 순서와 완료 기준을 볼 수 있다. 초급 **내 자료로 안내하기**는 예시 질문 실행, 이용규정 수정, 답변과 파일 비교 순서로 진행한다. 휴대폰 편집기는 처음에 블록 목록을 연다. **전체 보기**를 누르면 실행 경로와 자료·참조 연결을 함께 볼 수 있고, **편집기로 돌아가기**를 누르면 편집을 계속할 수 있다.

| 단계 | 실제 제품에서 확인할 것 | 원본 PNG |
| --- | --- | --- |

5단계에서 작업 지시를 바꾸기 전에 첫 답변을 확인한다. 아직 답변이 없다면 편집기에서 **시험 실행**을 열고 회원증 질문을 보낸다. 첫 답변을 확인한 뒤 가이드에서 **작업 지시 복사**를 누른다. **예제 편집기 열기**로 돌아가 **도서관 안내 Agent → 속성 → 작업 지시**의 기존 내용을 복사한 문장으로 바꾼다.

가이드의 **시험 질문 복사**로 회원증 질문을 복사해 편집기의 새 대화에 붙여 넣고 **질문 실행**을 누른다. 두 답변을 비교할 때는 **실행 기록**에서 첫 답변을 다시 열 수 있다. 편집기 실습 안내에서 **전체 가이드**를 누르면 현재 작업을 설명하는 단계가 열린다.

## 첫 실행과 비교 실행

샘플 계정의 첫 실습 사본에서 실제 OpenAI 모델로 두 번 실행했다. 두 실행 모두 ‘회원증을 만들려면 무엇을 준비해야 하나요?’라는 질문과 같은 도서관 이용규정을 사용했다. 두 번째 실행 전에 작업 지시만 바꿨다.

- **첫 실행**에서 신분증을 준비하라는 답변과 ‘완료’ 상태를 확인했다.
- **비교 실행**에서는 작업 지시를 “답을 쓰고 다음 줄에 안내문의 근거 문장을 그대로 인용하세요.”로 바꿨다. 새 대화에서 같은 질문을 보내자 Agent는 신분증 안내 다음 줄에 “회원증을 처음 만들 때는 신분증을 가져오세요.”를 인용했다.

첫 답변의 상태가 **완료**이고 준비물로 신분증을 안내하면 가이드 4단계의 **완료 기준**에서 **실제 편집기에서 직접 확인했어요**에 체크한다. 비교 답변까지 받으면 두 답변이 모두 신분증을 안내하고 두 번째 답변이 규정 원문을 인용하는지 확인한다. 말투는 실행마다 달라질 수 있다. 비교를 마치면 5단계의 같은 항목에 체크한다.

## 목적별로 만들기에서 업무나 템플릿 고르기

**가이드 → 목적별로 만들기**에서 ‘업무 문서 만들기’를 찾는다. 할 일 앱 요구사항을 만들려면 **내 사본으로 시작**을 누른다. 회의록·업무 보고나 반도체·제조 보고를 만들려면 **이 업무로 설계하기**를 눌러 내 메모나 CSV를 입력한다. [업무별 입력과 출력 예시](WORKFLOW_USE_CASES.ko.md)

도서관 템플릿을 고르면 블록 배치, **입력 예시**, **실행 조건**, **출력 예시**가 보인다. 그림을 눌러 확대 창을 연다. 창 크기에 따라 **원본 크기로 보기** 또는 **화면에 맞추기**가 표시되며, 더 크게 보려면 **2배로 확대**를 누른다.

**이 템플릿 열기**를 누르면 **수준별 템플릿**의 상세 화면이 열린다. 지점 조사팀 템플릿에서는 먼저 **내 사본의 조사 정책** 세 항목을 선택한다. **내 사본으로 시작**을 누르면 선택한 템플릿의 사본이 열린다.

### 바꾼 대출 규정을 다시 쓰기

이미 만든 초급 사본에 **대출 안내 파일 만들기** 블록이 없으면 화면에서 3권·5권 답변과 인용을 비교한다. 파일을 내려받으려면 **수준별 템플릿 → 초급 → 내 자료로 안내하기 → 내 사본으로 시작**에서 새 사본을 만든다.

대출 규정을 5권으로 고친 사본에서 **실행 기록**을 열고 **현재 초안**으로 3권 답변을 받았던 첫 대화를 고른다. **시험에 사용할 원문**에서 **이전 원문 · 같은 대화**를 고르면 그때의 3권 규정으로 질문을 이어 간다. **현재 원문 · 새 대화**를 고르면 새 대화에서 고친 5권 규정으로 같은 질문을 시험할 수 있다.

선택 실습에서는 5권으로 바꾼 **도서관 이용규정**의 속성에서 **내 참고 자료로 저장**을 누른다. 새 초급 사본은 3권에서 시작한다. 새 사본의 같은 블록에서 **속성 → 이름·자료판 설정 → 연결할 자료**를 열고 저장한 자료를 고른다. 이름이 같으면 자료 번호를 확인한다. 미리보기에서 원문과 저장한 판을 확인한 뒤 **이 판 연결**을 누른다. 새 대화의 답변과 **대출안내.txt**에 5권 규정이 인용됐는지 확인한다.

### 검토 담당자 한 명에게 교정 사유 지시하기

먼저 예시 질문을 실행해 최종 안내문 아래에 두 담당자의 검토 기록이 보이는지 확인한다. 예전 사본에서 두 기록이 보이지 않으면 **수준별 템플릿 → 고급 → 동료 Agent와 초안 검토하기 → 내 사본으로 시작**으로 새 사본을 만든다.

팀 속성의 **도구 및 자료 → 팀에 연결할 Skill**에서 **교정 사유 표시 Skill**을 연결한다. **팀 열기**를 누른 뒤 **사실 검토 담당의 동료 검토** 블록을 선택하고 **전달받을 상위 Skill**에서 그 Skill을 체크해 저장한다. 같은 초안을 새 대화에서 검토하면 두 담당자 모두 토요일 폐관 시각을 오후 6시에서 오후 4시로 바로잡고, 사실 검토 담당의 기록에만 교정 사유 한 줄을 남긴다.

### 지점별 조사 순서와 중단 정책 비교하기

사본을 만들 때 **총 생성 한도**는 2명, **동시 실행 한도**는 1명으로 정한다. **지점 조사 실패 시**에는 **확인한 지점 결과를 보존하고 계속**을 고른다. 사본에서 ‘중앙도서관, 호수도서관, 숲도서관, 강변도서관’을 입력해 실행한다. 조사 대상으로 중앙도서관과 강변도서관을 고르면 중앙도서관은 근거 원문을 찾고 강변도서관은 근거 부족으로 표시된다. 호수도서관과 숲도서관은 이번 조사에서 제외된다.

편집기에서 **지점별 조사 담당 생성 → 고급 설정 → 전체 생성 상한**을 4명으로 늘린 뒤 새 대화에 같은 네 지점을 입력한다. 이번에는 별도의 선택 없이 네 지점을 모두 조사한다.

중단 정책을 비교하려면 같은 고급 설정에서 **전체 생성 상한**을 다시 2명, **동시 실행 상한**을 1명으로 맞춘다. **담당자 일부 미완료 시**에는 **새 담당자 생성과 후속 정리 중단**을 고른다. 새 대화에 네 지점을 입력하고 강변도서관, 중앙도서관 순으로 선택한다. **조사 순서**를 확인하고 회신한 뒤 실행 기록을 연다. 강변도서관의 근거가 부족해 중앙도서관 조사를 시작하기 전에 멈췄는지 확인한다.

인원 한도가 기본 실습 범위를 벗어나면 사본에 ‘자유 실험’이 표시된다. 기본 실습으로 돌아오려면 **지점별 조사 담당 생성 → 고급 설정**에서 **전체 생성 상한**을 1~4명으로 정한다. **동시 실행 상한**은 전체 생성 상한을 넘지 않도록 1명 또는 2명으로 정한다.

선택 실습에서는 **전체 생성 상한**을 2명 이상으로 두고 **확인된 결과와 미완료 사유 수집**을 고른다. 먼저 ‘중앙도서관, 강변도서관’ 두 곳만 입력해 중앙도서관의 평일 오전 9시 개관과 강변도서관의 근거 부족을 확인한다. **지점별 조사 담당 생성 → 도구 및 자료 → 참고 자료**에서 **강변도서관 보완 안내문** 1판을 골라 **이 판 연결**을 누른다. 생성 블록에 보완 안내문과 기존 **지점별 안내**가 함께 연결됐는지 확인하고 저장한다. 새 대화에 같은 두 지점을 입력한다. 이번에는 중앙도서관은 평일 오전 9시, 강변도서관은 평일 오전 11시에 문을 연다는 원문을 각각 인용하는지 확인한다.

### 시험한 규정 판을 게시하고 답변 비교하기

공유 화면에서 ‘규정 변경 검증·게시·복구’를 **내 사본 만들기**로 복사했다면 **프로젝트 메뉴 → 버전 → 현재 초안 버전 저장**에서 첫 판을 만든다. 기준판·후보판과 시험 사례 세 개가 준비된 별도 사본에서 실습하려면 **실습 안내 → 기준판·후보판이 준비된 실습 열기**를 누른다. 템플릿 상세 창에서 **내 사본으로 시작**을 선택한다.

방문자 답변은 기준판과 후보판이 준비된 실습 사본에서 다음 순서로 비교한다. 비교하는 동안 공유 범위는 **비밀 링크**로 유지한다.

1. 편집 창의 **공유 설정**에서 기준판인 1판을 비밀 링크로 게시한다. 시크릿 창에서 공유 주소를 열고 방문자 계정으로 로그인한다. **Agent 사용**에서 대출 한도를 물어 3권 답변을 받은 뒤 창을 열어 둔다.
2. 편집 창에서 2판의 시험 결과를 보고 게시 여부와 근거를 기록한다. **게시 보류**를 골랐다면 방문자 창의 1판 대화와 같은 주소에서 시작한 새 대화에 대출 한도를 묻는다. 두 대화 모두 3권을 안내한다. **게시**를 골랐다면 1판 대화에서는 3권, 새 대화에서는 2판의 5권을 안내하는지 확인한다.
3. 2판을 게시했고 복구도 시험하려면 방금 5권 답변을 받은 대화를 남겨 둔다. 편집 창의 **공유 설정**에서 대상 버전으로 1판을 고르고 **이전 판으로 복구**를 선택한 뒤 근거를 적어 **판단 적용 및 기록**을 누른다. 방문자 창에서 2판 대화를 이어 가면 5권, 복구 후 같은 주소에서 새로 시작한 대화에서는 3권이라고 답하는지 확인한다.

## 블록과 메뉴 사용법 찾기

가이드 상단 탭에서 **처음 시작하기**, **목적별로 만들기**, **기능·용어**, **문제 해결**, **블록·자료 찾아보기**, **메뉴별 사용법**을 열 수 있다. 다른 탭에서 **처음 시작하기**를 누르면 그 탭을 열기 전의 단계가 다시 보인다. 1단계 개요가 열렸다면 **읽던 N단계 이어 보기**를 눌러 마지막에 읽은 단계로 이동한다.

**블록·자료 찾아보기**에서는 편집기 블록 32개와 자료 유형 네 가지를 검색할 수 있다. 이름이나 하려는 일을 입력하면 검색어에 맞는 블록과 자료 유형이 표시된다. **블록 추천 수준**을 고르면 블록 목록만 해당 수준으로 좁혀진다. 각 자료 설명에는 ‘도서관 방문 준비하기’에서 해당 유형을 사용하는 블록이 표시된다. 작은 화면에서 블록과 자료가 모두 검색되면 **자료 설명으로 이동**을 눌러 자료 목록으로 갈 수 있다.

`MCP`를 검색하고 **MCP 연결**에서 ‘사용하는 블록 · 도구 사용(중급)’을 누르면 해당 블록의 설명이 펼쳐진다. **검색 결과로 돌아가기**를 누르면 설명이 접히고 키보드 초점은 방금 누른 ‘사용하는 블록 · 도구 사용(중급)’ 버튼으로 돌아온다. 검색어와 추천 수준은 그대로 유지된다.

**메뉴별 사용법**은 작업실 왼쪽 메뉴와 같은 순서로 아홉 메뉴의 아이콘·이름·설명을 보여준다.

### 브라우저 검증

Playwright로 Chrome을 열어 1440×900px과 390×844px에서 시험했다. 예제 사본 만들기, 회원증 질문 실행과 두 답변 비교, 기존 사본 다시 열기, 가이드로 돌아온 뒤 키보드 초점 복귀를 확인했다. 320×568px에서도 첫 화면에 시작 버튼 전체가 표시됐고 이미지를 확대하거나 다음 단계로 이동할 수 있었다. 모바일 시험에서는 터치 화면을 에뮬레이션했다.

자동 시험은 테스트용 모델 응답으로 가이드와 편집기 사이의 이동 및 조작을 검사한다. 이 문서의 답변 캡처 두 장은 실제 OpenAI 모델을 별도로 호출해 확보했다. [가이드 브라우저 시험](../tests/workflow-guide-browser.ts)

### 가이드 제작 기록

당시 `grill-me`와 Product Design의 `audit`로 실습에 필요한 조작을 추렸다. `frontend-design`을 참고해 작업실의 글꼴과 색으로 화면을 구성했고, UI Consistency의 `accessibility`로 키보드 이동과 대비를 점검했다. 페이지 이동과 이미지 표시는 프로젝트에 설치된 Next.js 문서를 참고했다.
