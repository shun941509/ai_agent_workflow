# Workflow Studio로 만드는 세 가지 업무 문서

**가이드 → 목적별로 만들기 → 업무 문서 만들기**에서 세 업무 중 하나를 선택한다. 회의록과 제조 보고는 **이 업무로 설계하기**를 누르면 설계 요청문과 입력 자료가 채워진다. 자신의 메모나 CSV로 교체한 후 **기본 설계로 시작**하거나, 모델을 연결한 작업실에서는 **초안 제안받기**를 선택할 수 있다. [작업실 시작 방법](../README.md)

## 1. 할 일 앱 요구사항

**할 일 앱 요구사항 → 내 사본으로 시작**을 선택한다. ‘사용자 요청을 기능 요구사항으로 바꾸기’의 블록이 내 프로젝트에 복사된다. 입력 블록에는 “할 일 앱에서 끝낸 항목을 잠깐 숨겼다가 다시 보고 싶어요.”가 들어 있다. [요구사항 템플릿](../src/domain/sw-starter-templates.ts)

**작업 지시 예시**

> 개발자가 목록 화면을 구현할 수 있도록 사용자의 조작과 그때 표시할 항목을 설명해 주세요.

**요구사항 예시.** 사용자가 ‘완료 항목 숨기기’를 켜면 목록에 미완료 항목만 표시한다. 끄면 완료 항목도 다시 표시한다. 개발팀은 이 문장을 기능 설명으로 사용하고, 변경 이력을 사용자용 공지로 정리할 때는 초급의 ‘변경 기록으로 업데이트 안내 만들기’를 활용할 수 있다.

## 2. 회의록·업무 보고

**설계 요청문**

> 회의 메모에서 확정한 업무를 업무·담당·기한 표로 정리해 주세요. 회의록 작성 Skill에 따라 미결 제안을 따로 적고, 이번 결정과 다음 회의 안건을 두 문장으로 요약해 주세요.

**입력 메모**

```text
시범 운영용 안내문 12부를 인쇄하기로 했다. 민지가 맡는다.
신규 참석자에게 안내 메일을 보내기로 했다. 담당자와 발송일은 아직 미정이다.
안내문을 20부 더 인쇄하자는 의견이 있었다. 다음 회의에서 결정한다.
```

**회의록 예시**

| 확정 업무 | 담당 | 기한 |
|---|---|---|
| 시범 운영용 안내문 12부 인쇄 | 민지 | 미정 |
| 신규 참석자 안내 메일 발송 | 미정 | 미정 |

**업무 보고 예시.** 안내문 12부를 인쇄하고 신규 참석자에게 안내 메일을 보내기로 했다. 안내문 20부 추가 인쇄는 다음 회의에서 결정한다.

개발팀은 확정 업무 표를 담당자 인계에 쓴다. 같은 계정의 다음 회의록에도 자동 연결되는 **회의록 작성 Skill**에는 담당·기한이 비어 있을 때의 표기 규칙을 둔다. [업무 문서와 작성 규칙](../src/domain/work-documents.ts)

## 3. 반도체·제조 보고

**설계 요청문**

> 웨이퍼 정렬 오차 CSV에 연결된 기준표의 허용 범위를 적용해 주세요. 적용한 범위와 단위, 전체 측정 건수, 초과 건수와 중복을 뺀 해당 LOT 수를 적고, LOT·웨이퍼·부호가 있는 측정값을 표로 보여 주세요.

**입력 CSV**는 한 행이 웨이퍼 한 번의 측정을 나타내는 가상 자료다.

```csv
lot,wafer,offset_nm
L7,W01,-4
L7,W02,5
L7,W03,-7
L8,W01,6
L9,W01,-2
L9,W02,1
```

**생산 보고 예시.** 웨이퍼 6건 중 정렬 오차가 ±4 nm 범위를 벗어난 측정은 3건이다. L7에서는 W02(+5 nm)와 W03(−7 nm), L8에서는 W01(+6 nm)이 해당한다. 영향을 받은 LOT는 2개다.

개발팀은 LOT와 웨이퍼 식별자를 함께 전달해 담당자가 원자료에서 측정값을 찾을 수 있게 한다. 기본 연결은 **웨이퍼 정렬 오차 기준표 1판**이다. 개정 시 ‘도구 및 자료’에서 새 판을 저장한 뒤 적용할 Agent에서 연결할 자료판을 바꾼다. [자료 버전 연결](../src/server/run-assets.ts)
