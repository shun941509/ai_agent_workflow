# UI 개선 계획

이 문서는 2026년 11월 UI 개선 당시의 계획과 검수 자료다. 이후 개발과 리뷰에는 [Windows PC 브라우저 인수 기준](IMPLEMENTATION_PLAN.md)을 적용한다.

## 세부 조작의 인수 기준

| 사용자 작업 | 확인 방법 |
|---|---|
| 편집기 전체 보기에서 블록과 출력을 선택한다. | 열린 속성 이름 또는 연결 출발점을 저장된 블록·연결과 대조한다. |
| 여러 종류의 블록이 밀집된 도면에서도 다른 블록을 잘못 열지 않는다. | 41종 도면에서 얻은 선택한 위치와 열린 블록·출발점을 대조한다. 주 도면의 이름과 실행·데이터·참조선도 함께 확인한다. |
| 크기가 다른 다이얼로그를 작은 화면부터 데스크톱까지 사용한다. | 생성·삭제·설정·선택·원본 확대를 열고 제목, 본문, 확인 버튼의 위치를 잰다. Tab·Shift+Tab, Escape, 원래 버튼 복귀, 배경 스크롤을 시험한다. |
| 초보자가 가이드를 보고 실제 서비스를 조작한다. | 13개 실습과 가이드 그림의 번호·강조 위치를 제품과 대조한다. 첫 방문, 프로젝트 재개, 실습 시작, 질문 실행, 오류 복구를 독립 계정에서 확인한다. |
| 변경 효과를 재현한다. | 같은 프로덕션 빌드에서 1024·1280·1440px로 두 차례 점검한다. Chrome 직접 조작, 접근성 자동 검사, 타입·단위·브라우저 시험과 프로덕션 빌드 결과를 구분해 남긴다. |

## 2026-11-27 추가 인수 기준

### 그림만으로 따라가는 가이드

첫 화면에서 예제를 바로 시작할 수 있도록 유지하고, 개념과 기능은 해당 장에서 필요할 때 펼친다. 그림에는 실제 질문, 사용한 자료, 기대하는 답과 확인할 버튼을 한글로 적는다. 생성·시험 과정은 실물 캡처와 대조한다. 목적별 사례는 현재 템플릿과 연결하고, 문제 해결 그림은 막힌 상태와 다음 조작을 함께 보여 준다.

각 그림은 원본 크기에서 글자가 읽혀야 하고, 확대 후 키보드로 내용을 살펴본 다음 열었던 곳으로 돌아갈 수 있어야 한다. FAQ와 사례에서 제공하는 상태·권한·자료 이름은 실제 제품과 맞춘다. 처음 사용한 사람이 이해하는 데 걸린 시간은 실사용자 측정 여부를 구분해 기록한다. [FigJam에서 설계한 도서관 예제 흐름](https://www.figma.com/board/UfGEEVFYyMVIeMgi7Obst1)

일반 사용자용 가이드를 우선한다. 첫 방문자가 첫 화면에서 예제를 열고, 실제 버튼이 표시된 세 그림으로 질문과 답변 확인까지 따라갈 수 있어야 한다. 자료를 바탕으로 답하는 사용 예, 넓은 질문과 구체적인 질문의 차이, 자주 막히는 상황과 도움말을 같은 진입 화면에서 찾을 수 있어야 한다. 모델이 연결되지 않았을 때 실제로 할 수 있는 작업도 구분한다.

| 대상 | 인수 기준 |
|---|---|
| 게시 주소 | 시스템 클립보드를 허용하거나 거절했을 때 현재 게시 주소를 받을 수 있다. 권한 응답을 기다리는 동안 닫기·공유 철회가 가능하며 이전 요청의 결과가 새 게시 주소에 표시되지 않는다. |
| 자료판·이벤트 토큰·가이드 복사 | 자료의 판이나 토큰을 바꾸거나 다른 문장을 선택한 후에는 이전 복사 결과가 새 항목에 성공으로 표시되거나 사용자의 선택을 덮어쓰지 않는다. |
| 공유 Agent에서 화면 이동 | 사본 생성 응답 전에 뒤로 가면 200과 503 모두 사용자가 선택한 목록에 머문다. 성공했을 때만 실제 사본 하나가 목록에 나타난다. |
| 통신 오류와 복원 | 서버 응답을 받을 수 없는 경우 한국어로 확인할 곳을 안내한다. 로그인 입력값을 보존하고 연결 회복 뒤 같은 폼으로 다시 제출할 수 있다. |
| 검증 자료 | 대표 화면 전후 비교를 저장소 파일만으로 열 수 있고, 캡처의 기준 날짜와 화면 크기를 식별할 수 있다. |

### 첫 방문 가이드의 인수 절차

1. 새 계정으로 가이드를 열어 첫 작업, 예시 질문, 예상 답변과 사용한 자료를 찾는다. 예제를 시작하고 돌아온 뒤 같은 계정의 사본으로 이어지는지 확인한다.
2. 세 그림의 실제 레이블을 편집기·실행창과 대조한다. 키보드로 각 단계 설명에 이동해 제목 포커스를 확인한다.
3. 회원증 질문의 답을 이용규정과 비교하고, 질문 입력·답변 근거·지시 변경의 세 도움말을 연다. 모델 설정이 필요한 상태에서도 예제를 열 수 있는지 확인한다.
4. 링크 복사 권한 응답을 지연한 뒤 판 변경·재발급·다른 문장 선택을 먼저 마친다. 현재 주소, 포커스, 선택 영역과 안내를 대조한다. 이 절차와 가이드가 포함된 소스에서 마지막 두 차례 전체 검토를 수행한다. [가이드 전후 비교](ui-review/guide.html) · [가이드 회귀 시험](../tests/workflow-guide-browser.ts) · [최종 검증 결과](QA-REPORT.md)

## 공통 우선순위

| 우선순위 | 사용자에게 미치는 영향 | 인수 기준 |
|---|---|---|
| 높음 | 작업이 막히거나 다른 사용자의 자료·초안에 영향을 줄 수 있는 문제 | 원래 계정·데이터·버전·입력으로 같은 작업을 재현하고 수정 후 회귀 시험을 통과한다. |
| 중간 | 키보드 포커스 유실, 화면 구분 실패, 오류 후 복구·작은 화면 조작 어려움 | 동일 상태에서 키보드로 문제 동작을 재현하고 결과를 비교한다. |
| 낮음 | 첫 방문에 내려받는 코드, 오래된 스타일 및 안내 문구 | 실제 전송량, 사용 여부 또는 안내와 실제 버튼의 차이를 확인하고 수정한다. |

공통 작업실·계정, 편집기, 자료·실행, 홈·실습으로 나누어 동시에 조사한다. 수정 뒤에는 프로덕션 빌드에서 반응형·실제 데이터 흐름·회귀 시험을 수행한다. 새 문제가 나오면 이력을 추가하고 수정된 상태에서 최종 검토를 다시 시작한다. 최종 결과와 검증 제약은 [QA 보고서](QA-REPORT.md)에 기록한다.

| 우선순위 | 처리한 항목 | 확인 기준 |

| 높음 | 미게시 Agent 실행·사본, 긴 제목에서 실행창 본문 소실 | 소유자는 초안으로 시험하고 사본을 열며, 작은 화면에서 질문 입력과 결과를 이용한다. |
| 중간 | 키보드 포커스, 오류 복구, 긴 원문 읽기, 확대창, 편집기 속성 내부 넘침, 캔버스 조작 | 다시 읽기·원래 항목 복귀·단일 포인터 이동·동등 연결 조작을 끝낸다. |

| 낮음 | 탭 제목, 빈 검색 결과, 첫 방문 로드, 폐기된 스타일 | 화면 전환과 뒤로 가기에서 이름을 식별하고 검색을 초기화한다. 첫 홈의 스크립트와 사용하지 않는 선택자가 줄었다. |

11월 26일 소스에서 진행한 두 차례 화면 검토는 당시 회차의 결과다. 11월 27일 추가한 가이드와 복사 동작까지 포함한 소스의 회차별 결과는 [QA 보고서](QA-REPORT.md)에 기록한다.

## 승인안의 구현과 검수 자료

| 승인 항목 | 실제 화면에서 확인할 동작 | 비교 자료 |
|---|---|---|
| A · 공통 작업실 | 첫 방문자는 만들기와 예제를 선택하고, 재방문자는 자신의 설계를 이어서 연다. 실행 결과는 시험한 초안과 함께 읽는다. | [서비스 개편 전후](ui-review/index.html) |
| B · 실습 상세 | 13개 실습의 목표·순서·완료 기준을 읽고 개인 사본을 연다. 편집기에서 **실습 안내**로 돌아가면 진행하던 실습을 먼저 확인한다. | [실습과 가이드](ui-review/guide.html) |
| C · 편집기 전체 보기 | 저장된 블록과 실행·데이터 연결을 따라간다. | [편집기 전체 보기](ui-review/index.html#map) |
| 오류 후 작업 복귀 | 로그인 연결 장애, 복사 권한 응답 지연, 사본 생성 중 뒤로 가기에서 현재 입력·선택·경로를 확인한다. | [복구 전후](ui-review/recovery.html) |

검수 명령의 실행 결과, 브라우저 화면별 관찰, 외부 모델 등 직접 측정하지 않은 항목은 [QA 보고서](QA-REPORT.md)에 기록했다.
