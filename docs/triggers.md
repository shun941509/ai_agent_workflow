# Workflow 자동 시작과 재사용

## 자동 시작

1. 편집기의 최상위 캔버스에 **시작 조건** 블록을 추가하세요. **예약**을 고르면 **실행 일정**에 `매일 09:00`(한국 시간), `매 15분` 또는 시간대를 포함한 ISO 형식의 미래 시각(예: `2027-01-01T09:00:00+09:00`)을 입력하세요. **이벤트**를 고르면 **이벤트 이름**을 입력하세요. **시작 조건**에서 다음 블록으로 실행선을 연결하고, 시작할 때 받은 입력값은 데이터선으로 넘기세요. 마지막 단계는 **답변 전달**에 연결하세요.
2. 프로젝트 버전을 저장하고 게시하세요. 다른 이용자에게 Agent를 공유할 필요가 없으면 공유 범위를 **나만 사용**으로 설정해 게시하세요. 토큰으로 인증한 외부 이벤트도 자동 시작을 등록한 소유자의 계정에서 실행됩니다.
3. 편집기의 **시험 실행 → 실행 설정 → 자동 시작**에서 **시작할 때 전달할 입력**을 채우고 **게시한 버전으로 활성화**를 누르세요. 자동 시작을 설정하거나 해제하려면 소유자 계정으로 로그인하세요. 다른 버전을 게시하거나 이전 판으로 복구하면 기존 예약이 즉시 일시 중지됩니다. 현재 게시판에서 일정과 시작 입력을 확인하고 **게시한 버전으로 예약 재개**를 누르면 다음 실행 시각이 표시됩니다. 이벤트의 이전 설정이 켜져 있으면 해제한 뒤 새로 게시한 버전으로 활성화하세요.

### 예약 실행

실행기가 동작하는 동안에는 모델이 다른 질문을 처리하고 있어도 예약 시각마다 실행을 한 건씩 접수합니다. 실행기를 껐다 켜면 중단 중 놓친 예약은 설정마다 한 번씩 접수합니다. 이후 `매 15분`은 재시작 시각부터 15분 간격으로 접수하고, `매일 09:00`은 다음 한국 시각 오전 9시에 접수합니다.

### 이벤트 보내기

패널의 **기본 입력으로 이벤트 보내기**를 누를 때마다 게시 버전의 실제 실행이 소유자 계정으로 한 건씩 접수됩니다. 외부 서비스에서 이벤트를 보내려면 활성화 화면에 표시된 **이벤트 주소**로 HTTP POST 요청을 보내세요. 다음 헤더와 JSON 본문을 사용합니다.

- `Content-Type` 헤더에 `application/json`을 지정합니다.
- `Authorization` 헤더에 `Bearer <이벤트 토큰>`을 지정합니다.
- JSON 본문 예시는 `{"eventId":"도착-42","input":"새 자료 요약"}`입니다. `eventId`는 150자 이하의 필수 문자열입니다. `input`을 직접 보낼 때는 40,000자 이하의 문자열을 사용하세요. 두 값 모두 공백을 제외한 문자가 하나 이상 있어야 합니다. `input`을 생략하면 설정한 기본 입력을 사용합니다. JSON 본문 전체의 한도는 80,000바이트입니다.

활성화 직후 **토큰 복사**를 누르고, 이벤트를 보낼 서비스의 인증 설정에 붙여 넣어 저장하세요. 자동 복사 권한이 없으면 **토큰 표시**를 눌러 선택된 값을 직접 복사한 다음 **토큰 숨기기**를 누르세요. 화면을 닫은 뒤 토큰이 다시 필요하면 자동 시작을 해제하고 재활성화해 새 토큰을 받으세요.

이벤트를 접수하면 HTTP 202와 실행 ID(`runId`)를 반환합니다. 같은 자동 시작 설정과 게시 버전에서 같은 이벤트 ID와 입력을 다시 보내면 이전 실행의 `runId`를 반환합니다. 같은 설정과 버전에서 같은 이벤트 ID에 다른 입력을 보내면 HTTP 409를 반환합니다.

### 실행 확인

자동 시작으로 실행된 작업은 **실제 사용 · 게시 버전** 실행으로 기록됩니다. 도서 예약 생성처럼 승인이 필요한 작업은 해당 호출에 유효한 승인이 없으면 대기합니다. 소유자 계정에서 **실행 기록**을 열고 대기 중인 실행을 선택하세요. 해당 문답에 표시된 도구와 인자를 확인한 뒤 **이 작업 승인** 또는 **거절**을 누르세요.

## 다른 Workflow 재사용

**Workflow 재사용** 블록의 **호출할 Workflow**에서 프로젝트를 고르세요. **Workflow 버전**에서 내 프로젝트는 저장한 버전 중 하나를, 다른 사람이 공유한 프로젝트는 현재 게시한 버전을 선택할 수 있습니다. 버전을 나중에 자동으로 정하려면 **자동으로 버전 선택**을 고르세요. **이 블록 내부에 설계하기**를 선택하면 별도의 프로젝트를 연결하지 않고 이 블록 안에 설계를 작성할 수 있습니다.

- **정해진 단계에서 호출**은 이 블록이 실행될 때 연결한 Workflow를 호출합니다.
- **Agent가 도구로 호출**은 **목표까지 반복**으로 설정한 **AI 작업**에 참조선으로 연결합니다. Agent가 해당 도구를 선택하면 연결한 Workflow를 실행합니다.

**Workflow 버전**에서 **자동으로 버전 선택**을 선택하면, 상위 설계를 버전으로 저장할 때 하위 Workflow의 게시 버전을 자동으로 고정합니다. **현재 초안**으로 새 시험 대화를 시작하면 실행을 준비하는 시점의 하위 게시 버전을 자동으로 고정합니다. 두 경우 모두 내가 소유한 하위 Workflow에 게시 버전이 없으면 가장 최근에 저장한 버전을 사용합니다.

대화가 시작되면 그 대화에서 쓸 자료와 하위 Workflow 버전을 고정합니다. 실행을 재개할 때는 현재 접근 권한을 다시 확인합니다. 상위 Agent를 **비밀 링크**로 게시하려면 하위 Workflow도 **비밀 링크**나 **모두에게 공개**로 게시한 버전을 연결하세요. 상위 Agent를 **모두에게 공개**로 게시하려면 하위 Workflow도 **모두에게 공개**로 게시한 버전이어야 합니다. Workflow가 자기 자신이나 이미 호출 경로에 있는 상위 Workflow를 다시 호출하면, 버전을 저장하거나 시험 실행을 시작할 때 순환 호출 오류가 표시됩니다.
