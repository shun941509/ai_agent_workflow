# Workflow Studio의 업무별 AI 활용

## 가이드에서 업무 문서 만들기

**가이드 → 목적별로 만들기 → 업무 문서 만들기**에서 만들 문서를 고른다. 입력 원문과 출력 예시를 나란히 볼 수 있다. 데스크톱에서는 왼쪽 목록, 모바일에서는 선택 메뉴를 사용한다. [업무별 입력과 출력 예시](WORKFLOW_USE_CASES.ko.md)

| 만들 문서 | 시작 방법 | 결과물 |
|---|---|---|
| 할 일 앱 요구사항 | **내 사본으로 시작**을 눌러 기존 요구사항 템플릿의 블록을 편집한다. | 완료 항목을 숨기거나 다시 표시하는 동작을 설명한 요구사항 |
| 회의록·업무 보고 | **이 업무로 설계하기**에서 메모와 요청문을 바꾼다. | 확정 업무·담당·기한 표, 미결 안건, 두 문장 보고 |
| 반도체·제조 보고 | **이 업무로 설계하기**에서 웨이퍼 정렬 오차 CSV와 요청문을 바꾼다. | 허용 범위를 벗어난 측정 건수, 해당 LOT 수, 웨이퍼별 측정값 |

## 내 업무에 적용하기

1. 회의록과 제조 보고에서 **초안 제안받기**를 누르면 AI가 요청문과 기본 예시를 바탕으로 블록 구성을 제안한다. 제안을 선택하거나 **기본 설계로 시작**을 누르면 내가 입력한 메모나 CSV가 새 Agent의 입력 블록에 저장된다. 기본 설계는 모델 연결 전에도 편집할 수 있다. 문서를 생성하는 AI 작업에는 모델 연결이 필요하다.
2. 같은 계정에서 만든 회의록 Agent들은 **회의록 작성 Skill**을 재사용한다. 확정 업무의 담당자나 기한을 알 수 없을 때 ‘미정’으로 쓰는 규칙을 여기서 관리한다.
3. 제조 보고는 **웨이퍼 정렬 오차 기준표**의 1판으로 시작한다. 1판에서는 −4 nm와 +4 nm도 허용 범위에 포함된다. 기준이 바뀌면 ‘도구 및 자료’에서 새 판을 저장하고, 적용할 Agent의 기준표 블록에서 **고정할 자료 버전**을 바꾼다. 다른 Agent는 각자 연결한 판을 사용한다. [자료와 Skill 연결 방법](PROJECT_SKILLS.md)

## 개발팀의 AI 활용

| 변경 요청 | AI에 줄 맥락 | 수정할 위치 |
|---|---|---|
| 완료 목록의 동작을 명확히 하고 싶다 | 사용자 발화와 ‘숨기기 켜기·끄기’ 각각의 기대 표시 항목 | 요구사항 템플릿의 작업 지시. 가이드와 수준별 템플릿이 같은 블록 정의를 사용한다. |
| 회의록을 인계 문서로 쓰고 싶다 | 확정 업무와 제안이 섞인 메모, 담당·기한 열과 미정 표기 규칙 | 문서별 출력 순서는 Agent의 작업 지시, 여러 문서에 공통인 표기 방식은 Skill |
| 개정한 제조 기준을 적용하고 싶다 | nm 단위, LOT와 웨이퍼 식별자, 경계값 포함 여부가 적힌 기준표 | 기준표의 새 자료판과 적용 대상 Agent의 참조 블록 |

업무용 요청문·기본 자료·미리보기의 출력 행은 한 파일에서 관리한다. 새 업무를 수정할 때는 여기서 시작한다. [업무 문서 정의](../src/domain/work-documents.ts) · [요구사항 템플릿](../src/domain/sw-starter-templates.ts) · [목적별 목록](../src/ui/guide/TemplateGallery.tsx)
