# Workflow Studio로 만드는 세 가지 업무 문서

**가이드 → 목적별로 만들기 → 업무 문서 만들기**에서 문서 유형을 고른다. ‘회의록·업무 보고’나 ‘반도체·제조 보고’에서 **이 업무로 설계하기**를 누르면 예시 요청문과 자료가 들어 있는 설계 창이 열린다.

예제를 시험할 때는 미리 채워진 메모나 CSV를 그대로 둔다. 내 업무에 적용하려면 자료를 바꾸고, 원하는 결과에 맞게 요청문을 고친다. 그런 다음 시작 방법을 고른다.

- 기본 구성을 쓰려면 **기본 설계로 시작**을 누른다. **모델 설정 필요**가 보이면 작업실 운영자에게 모델 연결을 요청한다. 기다리는 동안에도 기본 설계의 블록을 편집할 수 있다.
- 작업실에 **모델 설정됨**이 표시되고 AI의 제안을 받고 싶다면 **초안 제안받기**를 누른다. AI는 요청문과 기본 예시를 참고해 블록 구성을 제안한다. 설계 검사를 통과하면 **내 Agent로 만들기**를 누른다. 수정할 항목이 표시되면 **초안으로 열어 수정**을 눌러 편집기에서 고친다.

기본 설계를 쓰거나 AI 제안을 적용하면 설계 창의 메모나 CSV가 새 Agent의 입력 블록에 저장된다. 작업실에 **모델 설정됨**이 표시되면 편집기에서 **시험 실행**을 연다. **시험 질문**의 자료를 확인하고 **질문 실행**을 누른다. 생성된 문서는 **답변**에서 확인한다. [작업실 시작 방법](../README.md)

## 1. 할 일 앱 요구사항

**할 일 앱 요구사항 → 내 사본으로 시작**을 선택하면 ‘사용자 요청을 기능 요구사항으로 바꾸기’ 템플릿으로 만든 새 프로젝트가 편집기에서 열린다. 입력 블록에는 “할 일 앱에서 끝낸 항목을 잠깐 숨겼다가 다시 보고 싶어요.”가 들어 있다. [요구사항 템플릿](../src/domain/sw-starter-templates.ts)

편집기에서 **요구사항 작성 Agent**를 선택하고 **속성 → 작업 지시**의 기존 문장을 다음 예시로 바꾼다.

> 개발자가 목록 화면을 구현할 수 있도록 사용자가 ‘완료 항목 숨기기’를 켤 때와 끌 때 각각 어떤 항목이 표시되는지 설명해 주세요.

작업 지시를 바꾼 뒤 **시험 실행**에서 입력 블록에 있던 할 일 앱 요청을 보낸다. 이미 원래 지시로 시험했다면 **실행 기록 → ＋ 새 대화**에서 같은 요청을 보내 두 답변을 비교한다.

**요구사항 예시.** ‘완료 항목 숨기기’를 켜면 목록에 미완료 항목만 표시된다. 이 설정을 끄면 완료 항목도 다시 표시된다. 개발팀은 이 두 문장을 완료 항목 표시 기능의 요구사항으로 쓸 수 있다. 변경 이력을 사용자용 공지로 정리하려면 **수준별 템플릿 → 초급 → 변경 기록으로 업데이트 안내 만들기**를 연다.

## 2. 회의록·업무 보고

**설계 창의 ‘맡길 일과 원하는 결과’에 넣을 예시**

> 회의 메모를 읽고 확정된 업무를 골라 ‘확정 업무’, ‘담당’, ‘기한’ 열로 정리해 주세요. 회의록 작성 Skill에 따라 미결 제안을 따로 적고, 이번 결정과 다음 회의 안건을 두 문장으로 요약해 주세요.

**입력 메모**

```text
시범 운영용 안내문 12부를 인쇄하기로 했다. 민지가 맡는다.
신규 참석자에게 안내 메일을 보내기로 했다. 담당자와 발송일은 아직 미정이다.
안내문을 20부 더 인쇄하자는 의견이 있었다. 다음 회의에서 결정한다.
```

**회의록 예시**

| 확정 업무 | 담당 | 기한 |
|---|---|---|
| 시범 운영용 안내문 12부 인쇄 | 민지 | 미정 |
| 신규 참석자 안내 메일 발송 | 미정 | 미정 |

**다음 회의 안건.** 안내문을 20부 추가로 인쇄할지 결정한다.

**업무 보고 예시.** 안내문 12부를 인쇄하고 신규 참석자에게 안내 메일을 보내기로 했다. 안내문 20부 추가 인쇄는 다음 회의에서 결정한다.

개발팀은 업무를 인계할 때 확정 업무 표를 함께 전달한다. 같은 계정에서 회의록 Agent를 새로 만들면 **회의록 작성 Skill** 1판이 연결된다. 이 Skill은 원문에 담당자나 기한이 없을 때 ‘미정’으로 표시하도록 정한다. 개정판을 적용할 프로젝트에서 **회의록 작성 Skill** 블록을 선택하고 **고정할 자료 버전**을 새 판으로 바꾼다. [업무 문서와 작성 규칙](../src/domain/work-documents.ts)

## 3. 반도체·제조 보고

**설계 창의 ‘맡길 일과 원하는 결과’에 넣을 예시**

> Agent에 연결된 기준표로 CSV의 웨이퍼 정렬 오차가 허용 범위에 드는지 판단해 주세요. 적용한 범위와 단위, 전체 측정 건수, 범위를 벗어난 측정 건수를 적어 주세요. 한 LOT에서 여러 건이 벗어나도 LOT는 한 번만 세어 주세요. 범위를 벗어난 행마다 LOT·웨이퍼·측정값을 표에 적고, 측정값에 부호와 단위를 표시해 주세요.

**입력 CSV**에는 가상의 웨이퍼 정렬 오차 측정 결과를 한 행에 한 건씩 담았다.

```csv
lot,wafer,offset_nm
L7,W01,-4
L7,W02,5
L7,W03,-7
L8,W01,6
L9,W01,-2
L9,W02,1
```

**제조 보고 예시.** 정렬 오차 측정 6건 중 3건이 허용 범위(−4 nm 이상 +4 nm 이하)를 벗어났다. 허용 범위를 벗어난 측정값은 L7과 L8, 두 LOT에서 나왔다.

| LOT | 웨이퍼 | 정렬 오차 |
| --- | --- | --- |
| L7 | W02 | +5 nm |
| L7 | W03 | −7 nm |
| L8 | W01 | +6 nm |

LOT와 웨이퍼 식별자를 함께 기록하면 보고서를 받은 사람이 원본 CSV에서 측정값을 찾을 수 있다. 새 제조 보고 Agent에는 **웨이퍼 정렬 오차 기준표** 1판이 연결된다. 기준이 바뀌면 **도구 및 자료**에서 새 판을 저장하고, 적용할 Agent의 기준표 블록에서 **고정할 자료 버전**을 바꾼다. **시험 실행 → 실행 기록 → ＋ 새 대화**에서 같은 CSV를 보내 이전 보고서와 허용 범위·범위를 벗어난 측정 건수를 비교한다. [편집기의 자료 버전 선택](../src/ui/editor/Panels.tsx#L659) · [실행 시 자료 버전 처리](../src/server/run-assets.ts)
