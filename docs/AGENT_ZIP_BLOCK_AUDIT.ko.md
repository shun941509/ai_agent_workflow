## ZIP에서 어떤 파일을 읽는가

| 대상 | 확인한 파일과 동작 |
|---|---|
| 공통 지침 | 모든 표본에 `AGENTS.md`, `CLAUDE.md`, `README.md`가 있었다. `CLAUDE.md`는 `@AGENTS.md`를 참조한다. 공통 지침이 16 KiB 또는 200줄을 넘으면 `workflow/step-*.md`로 상세 단계를 나눈다. ZIP에서 `runtime/`은 발견되지 않았다. |

| 명시적으로 위임한 역할 | `agents/<역할>.md`에 배정 내용을 담고 세 클라이언트의 프로젝트별 Agent 등록 파일이 이를 참조한다. 108개 표본에서 역할 원문 26개와 등록 파일 참조 78개를 대조했다. 병렬의 실행 상한·대기와 합류 순서는 해당 단계에 있다. |

## 32종 블록별 대조

32종은 편집기의 번호와 이름을 따른다. 현재 유효 설계에서 관찰한 정상 동작과 이전에 재현해 추적 중인 경계 조건을 함께 볼 수 있다. 외부 클라이언트 열에 해당하는 검증 대상은 실제로 해제한 ZIP 파일이다.

| 번호 | 블록 | 이번 Studio 실행 | ZIP에서 확인 | 남은 개선과 검증 결과 |
|---:|---|---|---|---|
| 01 | 사용자 입력 | 질문을 후속 단계에 전달 | 시작 블록·예시 질문·실행 연결 | 같은 JSON을 직접 붙이면 전문 문자열을 넘겼고 실제 첨부의 사용자 입력은 질문만 넘겼다. 같은 실행의 수동 시작 조건은 파일명·본문·질문이 든 문자열을 넘겼다. 질문이 빈 첨부도 포함해 시작점별 후속 입력을 표시한다. |

| 21 | 병렬 작업 | 두 독립 역할 실행, 중첩 실패 정책 비교 | 블록·하위·전체 상한, 역할 호출·회신 재개 | 전체 4개, 현재 블록의 설정, 클라이언트의 더 낮은 상한과 회신 후 잔여를 안내한다. 하위 병렬 ‘전체 중단’에서는 상위 호출의 오류 처리기도 실행되지 않았다. ZIP에 중단 범위를 명시해야 한다. |

## 세 클라이언트에서 확인할 공통 항목

- **권한과 연결 준비.** Codex의 생성 설정에는 허용 도구 이름 목록이 들어간다. Claude Code·OpenCode의 생성 설정에는 같은 필터가 없고 역할 등록 파일만으로 개별 도구 제한을 보장할 수 없다. MCP의 읽기 전용 여부와 수동 연결의 인증 필요 여부를 단계에서 확인할 수 있게 한다. Studio 내장 서비스, 예약, 기억·지식 저장소는 사용하는 단계에서 받는 환경의 기능과 연결해야 한다. [MCP 설정](../src/server/agent-mcp-export.ts) · [역할 설정](../src/server/agent-role-files.ts) · [준비 항목](../src/domain/export-design-preparation.ts)
- **긴 역할 문서와 재개.** 공통 진입 문서가 분할돼도 같은 역할의 여러 배정은 한 원문에 쌓인다. 앞선 12회 배정 표본에서 역할 원문은 52,840바이트였다. 긴 역할은 배정 번호별로 열 수 있게 하고, 재개 시 현재 항목·대기 중인 호출·승인·남은 전체 실행 한도를 이어 준다. [역할 문서](../src/server/agent-delegation.ts) · [실행 상태](../src/engine/session.ts)
- **다음 회귀 시험.** 단일·분할 양쪽에 같은 입력을 주고 다음 단계 값, 선택한 출구, 대기·실패 상태와 최종 파일을 비교한다. 외부 호스트에서는 ‘실제 첨부 → CSV → 파일’, ‘병렬 인계 → 역순 회신 → 합류’, ‘두 호출자 → 같은 하위 Workflow’, ‘승인 → 전송 → 응답 유실 후 재개’를 우선 시험한다. 자료 검색과 철회에는 발행본·다음 초안이 함께 있는 표본을 쓴다. ## 앞선 점검에서 반영된 항목

최초 표본에서는 준비가 있는 ZIP 74개 모두 공통 진입점에서 준비 README를 안내하지 않았다. 당시 후속 검사에서는 74개 모두 그 안내와 단계별 연결을 제공했다. 전체 시험은 단계별 준비·결과 파일 변경 시점에 318개, 공유 저장판·원문 대조 반영 시점에 336개, 이번 승인안 반영 직전에는 337개가 통과했다. 단발 AI의 도구 0개, 여러 MCP 판의 선택 시점, 시험 파일과 실제 첨부, `outputs/`의 이름 충돌, 실패 시에만 오류 처리기로 이동하는 연결, 도구형 Workflow의 분할 종료·실패·중지도 확인했다.
