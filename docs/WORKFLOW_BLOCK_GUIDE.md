# Workflow 설계 블록 32종 사용 안내서

도서관에 “토요일에 문을 여나요?”라는 질문이 들어왔다고 생각해 보세요. **사용자 입력**이 질문을 받고, **AI 작업**이 **자료 가져오기**로 연결한 운영 규정을 읽어 답을 작성하고, **답변 전달**이 이용자에게 보여 줍니다. 캔버스의 블록 하나는 이처럼 입력을 받거나, 작업을 수행하거나, 다음에 일어날 일을 정하는 한 단계입니다.

## 원하는 수준부터 찾아보기

초안에 의견을 받으려면 고급 수준의 **사람 검토**를 추가하세요. 다음 담당자에게 길이 제한이 있는 요약을 넘기려면 전문가 수준의 **문맥 정리·압축**을 추가하세요.

| 수준 | 이 수준에서 추가되는 블록 수 | 추천 블록 수 | 이 수준에서 설계할 수 있는 일 |
|---|---:|---:|---|
| [입문](#introductory) | 4 | 4 | 질문을 받고 자료를 참고해 답하기 |
| [초급](#beginner) | 4 | 8 | 추가로 질문하고, 첨부 파일을 읽어 결과를 파일로 내려받기 |
| [중급](#intermediate) | 10 | 18 | 경로 나누기, 근거 찾기, 도구 오류 처리와 민감정보 가리기 |
| [고급](#advanced) | 11 | 29 | 담당자 선택, 병렬 협업, 팀 결과 평가와 자동 시작 |
| [전문가](#expert) | 3 | 32 | 입력에 따라 담당자 만들기, 검색용 자료집의 버전 관리, 긴 문맥 요약 |

팔레트의 **추천**에는 기본적으로 선택한 수준까지의 블록이 나옵니다. 이름을 검색하면 더 높은 수준의 블록도 찾을 수 있습니다. **전체 32종**에서는 모든 메뉴를 찾을 수 있습니다. **AI 작업**, **도구 사용**, **Agent에게 작업 전달**, **Workflow 재사용**, **담당자·작업 선택**은 속성의 **작업 방식**에서 두 가지 방식 중 하나를 고릅니다. **도구 사용**의 **보상 작업**은 전문가 수준을 고르거나 **전체 32종**을 열면 선택할 수 있습니다. **답변 전달**은 **종료 방식**에서 네 가지 중 하나를 고릅니다. **작업 지침·Skill**과 **MCP 연결**은 블록 속성에서 연결하는 참조입니다. Skill은 작업 절차를, MCP 연결은 사용할 도구가 등록된 서버를 지정합니다.

**연결선 읽는 법** · 연결 설정에서 **실행 순서**는 다음 블록을 언제 실행할지, **전달할 값**은 다음 블록이 어떤 내용을 받을지 정합니다. 예를 들어 검색이 끝나면 AI가 답하도록 실행선을 연결하고, 찾은 구절은 AI의 **입력값**으로 보냅니다. 답변을 작성할 때 처음 질문도 함께 참고하려면 사용자 입력 블록의 결과를 AI의 **원래 질문**에 연결합니다. 도면에서 실행선은 실선, 데이터선은 파선, 자료·지침·도구를 연결하는 참조선은 점선입니다. 같은 두 블록 사이의 연결은 한 선으로 묶일 수 있습니다. 선을 선택하면 각 항목을 확인할 수 있습니다.

캔버스 아래 범례에서 **실행 순서**, **전달할 값**, **참조**를 눌러 해당 종류의 선을 강조할 수 있습니다. 선에 마우스를 올리거나 키보드로 초점을 옮기면 범례 옆이나 아래에 출발 블록, 도착 블록, 연결 종류가 표시됩니다. 선을 클릭하면 오른쪽 속성 패널에서 선택한 연결을 확인할 수 있습니다.

## 입문

**첫 입력 연결하기** · **답변 전달**을 먼저 놓았다면 속성의 **입력값 받기**를 누르세요. 값을 보낼 블록이 없을 때 **사용자 입력 추가 및 연결**을 누르면 질문을 받는 블록과 답변으로 가는 연결이 생깁니다. 연결 창을 취소하거나 `Esc`로 닫으면 **입력값 받기**에서 키보드 작업을 이어갈 수 있습니다.

### 01. 사용자 입력

이용자가 실행을 시작하며 보낸 질문이나 요청을 다음 블록에 전달합니다.

- **설정과 결과** · 현재 초안으로 새 시험 대화를 열면 최상위 캔버스에서 ‘예시 질문’이 적힌 첫 번째 **사용자 입력** 블록의 질문이 표시됩니다. 예시 질문이 없으면 실습에 지정된 질문을 사용합니다. 입력칸에서 문장을 고치면 고친 내용으로 실행합니다. 첨부한 파일의 본문은 **파일 입력**으로 받을 수 있습니다.
- **예시** · 이용자가 “회원증을 만들려면 무엇을 가져가나요?”라고 보내면 그 문장이 다음 AI 작업의 입력이 됩니다.

### 02. AI 작업

질문, 참고 자료, 작업 지시를 모델에 전달해 답변이나 초안을 만듭니다. 입문 **추천**의 기본 목록에서 **AI 작업**을 추가하면 **한 번 답하기**로 시작합니다. **목표까지 반복**으로 시작하려면 그 이름을 검색해 추가하세요. 이미 추가한 블록은 속성의 **작업 방식**에서 바꿀 수 있습니다.

- **설정과 결과** · **한 번 답하기**는 초안을 한 번 작성합니다. 검색 결과를 인용해 답할 때는 원래 질문, 답변과 근거를 대조하는 모델 판정이 추가됩니다. **목표까지 반복**은 허용된 도구를 사용하고 제작자의 목표와 완료 기준을 충족할 때까지 **최대 판단 횟수** 안에서 답변을 보완합니다. 조회 실패나 빈 검색 결과에는 한 번 다시 시도할 수 있습니다. 승인한 작업이 처리된 뒤 최종 답변 작성에 실패하면 실행 결과에서 확인된 작업과 영수증을 읽을 수 있습니다.
- **예시** · 규정 한 문장을 읽고 회원증 준비물을 알려줄 때는 **한 번 답하기**를 씁니다. 문의 내용에 따라 예약 조회가 필요할 때는 **목표까지 반복**을 선택하고 조회 도구를 허용합니다.
- 새 Agent의 초안 미리보기에 **도구 연결 필요**와 도구 이름이 표시되면 **초안으로 열어 수정**을 누르세요. 편집기에서 해당 블록의 **허용할 도구**를 설정하세요. 작업에 필요하지 않은 도구는 **이 제안 제외**로 정리할 수 있습니다.

### 03. 답변 전달

경로 마지막에 놓고 결과를 어떻게 전달할지 정합니다. 팀이나 하위 Workflow 안에서 반환한 결과는 호출한 쪽이 받습니다.

**표시 형식**에서 텍스트, JSON 또는 Markdown을 고릅니다. JSON은 문자열의 따옴표와 줄바꿈까지 직렬화합니다. Markdown 답변은 제목, 목록, 코드, 강조, 웹 링크를 실행 화면에서 읽을 수 있습니다.

| 종료 방식 | 실행 결과 |
|---|---|
| **답변 반환** (기본) | 이 블록이 실행되면 데이터선으로 받은 답변을 반환합니다. |
| **완료 안내** | 설정한 문구로 경로를 마칩니다. 문구가 비어 있으면 받은 값을 반환합니다. |
| **실행 중지** | 전체 실행을 중지 상태로 끝냅니다. |
| **실패 처리** | 설정한 안내를 오류 메시지로 기록합니다. 이 오류를 처리하는 경로가 없으면 실행이 실패로 끝납니다. |

- **예시** · 예약 승인 경로에서는 **답변 반환**으로 예약 내역을 돌려주고, 거절 경로에서는 **완료 안내**로 “예약을 변경하지 않았습니다.”를 표시합니다. 이전 설계에 저장된 **종료·중단** 블록을 열면 저장 당시의 종료 방식과 연결을 확인할 수 있습니다.

### 04. 자료 가져오기

설계자가 정한 원문을 다른 블록이 읽을 수 있게 합니다. 여러 이용자가 같은 규정을 참고해야 할 때 유용합니다.

- **설정과 결과** · 블록에 원문을 적거나 자료함에서 항목과 버전을 고릅니다. 참조선으로 연결하면 다음 블록이 자료의 제목과 버전, 본문을 참고합니다. 데이터선으로 연결하면 본문을 입력값으로 받습니다.
- **원문 편집** · 직접 적은 원문은 이 브라우저에 임시 보관되어 프로젝트를 다시 열면 이어 쓸 수 있습니다. 수정을 마치면 **변경 적용** 또는 **프로젝트 메뉴 → 저장**을 누르세요. 수정한 원문을 확인하려면 **현재 초안**으로 새 시험 대화를 열고 같은 질문을 보내세요. 초급 **내 자료로 안내하기**에서 도서관 이용규정을 바꾼 뒤 이전 초안 시험 대화를 다시 열었다면, **시험에 사용할 원문**에서 **현재 원문 · 새 대화**를 고를 수 있습니다. 이 선택란은 이전 시험에서 별도 원문을 지정하지 않았을 때 나타납니다.
- **예시** · **자료 가져오기**에서 ‘도서관 이용규정’ 1판을 고른 뒤 **AI 작업**에 참조선으로 연결합니다. AI가 규정에 적힌 운영 시간을 근거로 답합니다.

## 초급

### 05. 입력 양식·추가 질문

실행이 이 블록에 도달하면 이용자에게 질문하고, 답이 오면 같은 실행을 이어갑니다. 정보가 부족할 때만 물으려면 **조건 분기**에서 해당 경로를 연결하거나 **근거·출처 확인**의 **근거 부족** 출구를 이 블록에 연결하세요.

**다음 문답에 남길 회신 항목**에 `수령 지점`을 적으면 같은 대화에서 다음 질문을 받을 때 그 값을 기억합니다. 여러 항목은 쉼표로 구분합니다. 자유 서술 회신 전체를 남길 때는 `*`를 사용합니다. 병렬 경로가 여러 질문을 보내면 각 카드의 마감 시각을 보고 원하는 순서로 회신할 수 있습니다. 오래된 대기 요청은 **실행 기록 → 응답 필요**에서 엽니다.

- **설정과 결과** · 질문 문구만 설정하면 회신한 글이 다음 입력이 됩니다. ‘입력 항목’에 이름을 추가하고 필수 여부를 정하면 이용자에게 항목별 입력칸이 열립니다. 빠진 필수 항목은 같은 실행에서 보완하고, 다음 블록은 항목 이름과 값이 담긴 객체를 받습니다.
- **문서 입력** · 각 입력 항목의 **여러 줄**을 선택하면 문단과 Markdown 표의 줄바꿈을 보존합니다. 장비 반납 고급 실습에서는 중급 용어집과 판단 규칙표를 서로 다른 입력칸에 붙여 넣습니다.
- **질문지 전달** · ‘질문지 내려받기 파일명 (.md)’을 지정하면 응답 대기 화면에서 **질문지 내려받기**로 표시된 질문 원문을 저장할 수 있습니다. 회신 항목이 하나인 질문지 양식에는 문항별 답변을 줄바꿈과 함께 붙여 넣을 수 있습니다.
- **회신 기한** · 기본 목록에서 **입력 양식·추가 질문**을 추가하면 회신 기한이 꺼져 있습니다. 속성에서 **회신 기한 사용**을 켜면 60분이 제안됩니다. ‘회신 기다리기’를 검색해 설명에 ‘회신 기한 60분’이 표시된 항목을 추가하면 처음부터 60분 기한이 적용됩니다. 기한은 1~10,080분으로 정할 수 있습니다. 처음 회신을 요청할 때 화면에 마감 시각이 표시됩니다. 필수 항목을 보완하거나 실행을 재개해도 원래 회신 번호와 마감 시각은 같습니다. 마감 시각 전에 접수한 유효한 회신은 처리가 늦어도 유효합니다. 정확히 마감 시각부터 접수가 종료되며, 그전에 유효한 회신이 없으면 연결한 **오류 처리** 경로로 진행합니다.
- **예시** · “어느 지점에서 수령하시겠어요?”라는 질문에 필수 항목 `지점`과 기한 30분을 지정합니다. 이용자가 30분 안에 **지점** 칸에 ‘중앙관’을 입력해 보내면 다음 블록이 `{"지점":"중앙관"}`을 받아 예약 준비를 이어갑니다. 이전 설계의 **회신 기다리기** 또는 **조건 기다리기** 블록을 열면 저장한 기한을 확인할 수 있습니다.

### 06. 파일 입력

질문과 함께 보낸 파일을 받습니다. 실행이 이 블록에 도착했을 때 파일이 없거나 허용 형식에 맞지 않으면 파일을 요청하고 기다립니다.

두 문서를 비교할 때는 두 번째 블록의 **사용할 파일**을 **이 단계에서 새 파일 요청**으로 설정하세요. 다음 문답에서 사용할 JSON 항목은 **다음 문답에 남길 첨부 JSON 항목**에서 정합니다. 문서 읽기 다음에 **값 변환 → 항목 선택**으로 연결한 값도 대화 이력에 남습니다. 원문 전체가 필요하면 `*`를 입력하세요.

- **설정과 결과** · 첨부할 수 있는 파일은 이름의 확장자로 제한하며, 본문은 텍스트로 읽습니다. 기본 확장자는 `.txt`, `.md`, `.json`, `.csv`입니다. PDF나 Word 문서는 먼저 허용된 텍스트 형식으로 변환해 첨부하세요. 편집기에서 **시험 파일 내용**을 작성한 뒤 **시험 실행 → 예시 파일로 시험 → 질문 실행**으로 확인할 수 있습니다. 파일 요청을 받은 이용자가 **요청받은 파일**을 선택하고 **첨부하고 같은 실행 이어가기**를 누르면 다음 블록에 파일 이름과 본문이 전달됩니다.
- **예시** · 이용자가 올린 `지점.csv`를 받아 **문서 내용 읽기**에 연결합니다.

### 07. 문서 내용 읽기

**파일 입력**이 파일을 받으면 이 블록이 파일 본문을 읽어 다음 블록에 넘깁니다.

인용 위치가 필요하면 **원래 행 번호와 본문** 출력을 연결하세요. 첫 행은 1이며 빈 행도 번호에 포함됩니다. 따옴표 안에 줄바꿈이 있는 CSV 셀은 하나의 셀로 읽고, 인용 위치에서는 줄바꿈 양쪽을 별도 행으로 셉니다. **파일 만들기** 결과를 전달하면 메모리에 있는 파일의 본문을 읽습니다. 하위 Workflow의 **파일 입력 → 첫 질문에 첨부한 파일 사용**은 처음 사용자가 첨부한 파일을 읽습니다.

- **설정과 결과** · **자동**은 확장자의 대소문자를 구분하지 않습니다. 텍스트는 본문을, JSON은 해석한 값을 반환합니다. CSV는 각 행의 셀 값을 목록으로 만들고, 그 목록들을 배열에 담아 반환합니다.
- **예시** · `[{"지점":"중앙관"},{"지점":"호수관"}]`이 담긴 JSON 파일을 읽으면 **반복 처리**에서 지점을 하나씩 꺼내 쓸 수 있습니다.

### 08. 파일 만들기

완성된 결과를 이용자가 내려받을 수 있는 파일로 만듭니다.

- **설정과 결과** · 파일 이름을 입력하고 파일 형식으로 **텍스트**, **JSON**, **CSV**, **Markdown** 중 하나를 고릅니다. JSON 파일은 두 칸 들여쓰기를 사용합니다. CSV로 읽은 표를 다시 저장하면 행과 열, 빈 셀, 셀 안의 쉼표·따옴표·줄바꿈이 보존됩니다. 객체 목록을 CSV로 저장하면 처음 등장한 키 순서가 머리글이 됩니다. 실제로 만든 파일이 최종 답변에 포함되면 실행이 완료된 뒤 다운로드가 표시됩니다.
- **예시** · AI 작업이 작성한 도서관 안내문을 이 블록에 연결하면 기본 파일명인 `결과.txt`로 내려받을 수 있습니다. 지점별 운영 시간을 표로 저장하려면 같은 항목을 가진 객체 목록을 연결하고 CSV를 선택합니다.

## 중급

### 09. AI 분류

AI가 입력에 맞는 범주를 골라 해당 경로로 보냅니다. 등록된 범주로 분류하지 못하면 **미분류** 경로로 진행합니다.

- **설정과 결과** · 등록한 범주와 **미분류**의 다음 블록을 각각 연결합니다. 여러 범주가 같은 블록으로 가도 됩니다. 빠진 경로가 있으면 **설계 검사**에서 해당 이름을 눌러 도착 블록을 고릅니다. 기본 **결과** 데이터선은 원래 입력을 전달합니다. 분류 이름이 필요하면 **선택한 범주** 데이터선을 연결하세요. 미분류이면 그 값은 `null`입니다.
- **범주 바꾸기** · **이름 변경**에서 새 이름을 적용해도 기존 도착 블록으로 이어집니다. 삭제할 때는 확인 창에서 함께 끊어지는 실행선의 개수와 도착 블록을 확인할 수 있습니다.
- **예시** · “빌린 책을 더 오래 보고 싶어요.”를 ‘대출’로 분류해 대출 규정 검색으로 보냅니다.

### 10. 조건 분기

앞 단계에서 받은 값이나 그 안의 항목을 정해진 규칙으로 비교해 두 경로 중 하나를 실행합니다.

- **설정과 결과** · 입력값 전체를 비교하려면 **비교할 항목**을 비워 두세요. 객체 안의 값만 비교하려면 해당 항목의 경로를 입력하세요. **비교 방식**에서는 **같음**, **포함**, **보다 큼**, **값이 있음** 중 하나를 고릅니다. **값이 있음**을 선택하면 비교할 값이 `0`, `false`, 빈 문자열 또는 빈 배열일 때 **그 밖의 경우**로 진행합니다. 어느 경로로 가더라도 이 블록이 받은 입력값을 그대로 전달합니다.
- **예시** · **결과 평가**의 **통과 점수**를 80점으로 둡니다. **조건 분기**에서 **비교할 항목**에 `passed`를 적고 **같음**을 선택한 뒤 **비교 기준**에 `true`를 입력합니다. **맞음** 경로에서는 **값 변환**으로 `input`을 꺼내 원래 답변을 전달합니다. **그 밖의 경우**에는 분기의 결과를 **사람 검토**의 입력값에 연결하면 검토자가 초안과 점수, 평가 이유를 함께 봅니다. 초안만 보여 주려면 이 경로에도 **값 변환**을 두고 `input`을 꺼내 연결하세요.

### 11. 자료 검색

질문에 답하는 데 사용할 만한 원문 구절을 찾습니다. 결과를 읽는 사람이 출처를 다시 찾아갈 수 있습니다.

- **설정과 결과** · 입력값을 검색어로 쓰거나 속성의 **검색어 또는 질의**에 직접 입력합니다. 검색할 원문을 연결하거나 발행한 자료집의 이름과 버전을 지정합니다. 관련도순으로 찾거나 검색어가 그대로 있는 원문 행을 고를 수 있습니다. 검색 결과마다 자료 제목, 버전, 위치, 발췌문이 담깁니다. **최대 결과 수**의 기본값은 5개이고, **고급 설정**에서 1~30개로 바꿀 수 있습니다.
- **예시** · ‘토요일’이 있는 규정 행을 찾아 “토요일에는 오전 10시부터 오후 4시까지 엽니다.”라는 구절과 그 위치를 **근거·출처 확인**에 전달합니다.

### 12. 근거·출처 확인

찾아낸 구절이 질문에 실제로 답하는지 판단합니다. 비슷한 단어가 검색됐어도 필요한 사실이 없으면 추가 질문으로 보낼 수 있습니다.

- **설정과 결과** · 원래 질문과 검색 후보를 연결하고 근거 충족 기준을 정합니다. **근거 있음**, **근거 부족**, **근거 상충** 중 한 경로로 진행하며 후보에서 그대로 가져온 인용과 판단 이유를 전달합니다. **근거 상충**으로 분류하려면 서로 다른 출처 위치에서 가져온 인용이 두 개 이상 필요합니다.
- **확인 수준** · 후보 문구에서만 인용을 찾으면 결과의 `status`는 `candidate_match`입니다. 같은 판의 원문에서 인용 위치까지 확인하면 `verified`입니다. 두 결과 모두 기존 **근거 있음** 경로로 진행합니다. 후속 블록에서 구분하려면 **조건 분기**의 **비교할 항목**에 `status`를 지정하세요.
- **원문 대조 필수** · 채택한 인용의 판이 비어 있으면 **판 번호**에 원문의 판 번호 또는 판 이름을 입력하세요. Studio는 회신을 받은 같은 실행에서 해당 판의 연결 원문을 찾고, 원문이 필요하면 파일을 요청합니다. 첫 줄은 1행입니다. 다른 행에만 같은 인용이 있으면 **근거 부족**으로 진행합니다. 결과에서 연결한 원문과 회신으로 받은 원문을 구분할 수 있습니다. 기본값은 꺼짐입니다.
- **원문 연결하기** · **자료 검색**이 찾은 결과를 **검색된 구절**로 받습니다. 원문을 바로 연결해 둔 설계에서는 이 블록의 **자료 검색 추가**를 누르세요. 편집기가 검색 블록을 앞에 넣고 원문을 연결합니다. 질문이 이미 연결돼 있거나 캔버스에 **사용자 입력** 블록이 하나뿐이면 질문도 연결합니다. 그 밖의 경우에는 검색에 쓸 질문을 직접 연결하세요. 새 원문은 검색 블록의 **도구 및 자료 → 참고 자료**에서 선택할 수 있습니다.
- **예시** · “토요일 몇 시에 닫나요?”라는 질문에 평일 안내만 있으면 **근거 부족**으로 진행합니다. 서로 다른 두 규정이 토요일 마감 시각을 다르게 명시하면 **근거 상충** 경로에서 확인을 요청할 수 있습니다.

### 13. 도구 사용

예약 조회나 취소처럼 정해진 기능을 호출하고 그 도구가 돌려준 결과를 받습니다.

- **설정과 결과** · **일반 도구 호출**에서는 도구 이름과 보낼 인자를 지정합니다. **보상 작업**은 이미 일어난 변경을 되돌릴 도구와 대상을 지정하는 방식입니다. 전문가 추천 또는 **전체 32종**에서 선택할 수 있습니다. 읽기 전용으로 분류되지 않은 도구를 실행하려면 해당 도구와 인자에 대한 승인이 필요합니다.
- **예시** · 예약 생성 후 취소할 필요가 생기면, 설계한 후속 경로에서 **보상 작업**으로 취소 도구를 호출합니다. 이때 생성 결과로 받은 예약 번호를 인자로 넘깁니다.

### 14. 행동 승인

도서 예약을 만들거나 취소하는 등 외부 서비스의 데이터를 바꾸기 전에 이용자가 작업과 대상을 확인하도록 합니다.

- **설정과 결과** · 도구와 인자를 정하고 **승인**과 **거절** 출구를 연결합니다. **승인 안내**에 적은 내용은 실행 화면에 작업명, 실제 인자와 함께 표시됩니다. 승인 결과에는 승인 여부, 승인 식별자, 인자가 들어갑니다. **승인** 출구에서 **도구 사용**으로 실행선을 연결하고 승인 결과도 데이터선으로 전달합니다. 승인 한 건은 한 번의 도구 호출에 사용합니다. 도구와 인자가 승인한 요청과 일치해야 하며, 외부 MCP 도구라면 연결 버전도 같아야 합니다. 후속 도구 인자가 비어 있거나 승인 단계와 같은 식이면 확인한 실제 인자를 그대로 씁니다. 다른 식은 그 단계에서 평가합니다. 인자를 바꾸거나 다른 블록이 같은 작업을 다시 호출하면 새 승인이 필요합니다.
- **예시** · 예약 번호 `R-17`의 취소를 요청합니다. 승인하면 해당 예약을 취소하고, 거절하면 종료 안내를 보여 줍니다.

### 15. 값 변환

앞 단계의 결과에서 필요한 부분을 골라 다음 블록에 맞는 데이터 형식으로 바꿉니다.

- **설정과 결과** · **가져올 항목**에 `예약.번호`처럼 항목의 위치를 적어 값을 꺼냅니다. 꺼낸 값에 새 이름을 붙여 객체로 만들거나 문자열로 변환할 수 있습니다. `0.id`처럼 배열 위치도 읽습니다. **새 항목 이름**에 넣은 점은 이름에 포함됩니다. 읽을 때는 중첩 경로를 먼저 찾고 같은 이름의 단일 키도 확인합니다. 지정한 항목이 없으면 블록 이름과 찾던 항목이 실행 오류에 표시됩니다. **오류 처리**를 연결하면 대체 안내를 전달할 수 있습니다.
- **예시** · `{"예약":{"번호":"R-17","지점":"중앙관"}}`에서 예약 번호를 꺼내려면 **변환 방식**에서 **이름 바꾸기**를 고르세요. **가져올 항목**에 `예약.번호`, **새 항목 이름**에 `reservationId`를 입력하면 `{"reservationId":"R-17"}`을 받습니다.

### 16. 데이터 검증

입력 데이터에 필요한 항목이 들어 있고 값의 형식이 맞는지 검사합니다.

웹 개발 기초 실습에서는 고급 속성의 **장비 반납 실습 검증**을 사용합니다. **수신 전 장비 목록**은 초기 목록과 현재 목록이 같고 수신·처리 이력이 비었는지 확인합니다. **검수 완료 알림 한 건의 전후 기록**은 장비 번호로 각 행을 대조하고 수신한 알림과 처리 이력의 ID가 일치하는지 확인합니다. 통과하면 **검수 알림 전후 검증표** 출력에서 장비별 비교 결과를 받을 수 있습니다.

- **설정과 결과** · 반드시 받아야 하는 이름은 **필수 항목**에 넣으세요. **항목별 기대 형식**에만 적은 이름은 값이 들어왔을 때 형식을 검사합니다. `0.id` 같은 배열 경로도 검사합니다. 필수 항목의 누락, `null`, 공백뿐인 문자열, 빈 배열은 오류입니다. 숫자 0과 `false`는 값으로 인정합니다. 검사를 통과하면 객체나 배열의 구조를 유지해 전달합니다.
- **예시** · 지점은 문자열(`string`), 권수는 숫자(`number`)로 지정합니다. `{"지점":"중앙관","권수":3}`은 통과하고, 권수가 문자열 `"세 권"`이면 오류 처리로 보낼 수 있습니다.

### 17. 오류 처리

앞 단계가 실패했을 때 이용자에게 안내하거나 다른 절차로 이어가는 경로를 만듭니다.

- **설정과 결과** · 실패할 수 있는 블록의 속성에서 **연결 추가**를 열어 **오류 처리**로 이어지는 연결을 설정합니다. 성공했을 때 진행할 경로도 연결하세요. 분기·분류·승인·근거 확인은 각 결과에 다음 단계가 필요합니다. 분류 자체가 실패했을 때 실행할 처리기는 분류 블록에 직접 연결하세요. **값 변환**에서 항목을 찾지 못하거나 도구 호출이 실패하거나 **반복 처리**의 입력이 최대 반복 횟수를 넘으면 연결된 오류 처리기로 이동합니다. **후속 단계로 계속**은 설정한 안내나 실제 실패 정보를 전달합니다. `{{error}}`는 여러 경로에서 실패하면 단계별 사유를 함께 표시합니다. **중단**은 설정한 안내를 실행 오류로 남깁니다. 이전 설계의 **안내**와 **대체 경로**는 모두 **후속 단계로 계속**으로 표시됩니다.
- **예시** · 예약 조회가 실패했을 때 보여 줄 문구로 **이용자 안내**에 “조회 서비스를 사용할 수 없습니다. 안내데스크로 문의해 주세요.”를 적습니다. **후속 단계로 계속**을 고르고 **오류 처리**에서 **답변 전달**로 실행선과 데이터선을 연결하면 이용자가 이 문구를 봅니다.

### 18. 민감정보 검사·처리

전달할 입력 전체에서 지정한 종류의 민감정보를 검사합니다. JSON 객체에서는 모든 필드의 이름과 값, 중첩된 배열을 확인합니다. 파일을 연결하면 파일명과 본문도 검사합니다.

- **설정과 결과** · 이메일 주소(`email`)와 국내 전화번호 형식 일부(`phone`)를 검사합니다. **가리기**는 발견한 값을 `[이메일 가림]` 또는 `[전화번호 가림]`으로 바꿉니다. **전달 중단**은 오류를 발생시킵니다. 발견한 값의 처리는 양식·파일·변환의 이력 보존 설정보다 우선합니다. 같은 실행을 재개하거나 다음 문답에서 모델을 부를 때도 적용됩니다. 검사할 텍스트가 지나가는 위치에 블록을 배치하세요.
- **예시** · `{"caseId":"reader@example.com","content":"문의","count":0}`을 가리면 다음 블록은 `{"caseId":"[이메일 가림]","content":"문의","count":0}`을 받습니다. 가린 필드 이름끼리 겹치면 두 번째 이름부터 번호를 붙여 각 값을 보존합니다.

## 고급

### 19. Agent 팀

여러 담당자의 협업 과정을 하나의 블록 안에 설계합니다. 바깥에서는 팀에 일을 맡기고 팀의 최종 결과를 받습니다.

- **설정과 결과** · 팀의 목표와 **최종 응답 담당**을 적고, 내부 설계를 열어 누가 무엇을 맡고 어떤 순서로 결과를 주고받을지 연결합니다. 팀 안에서 **답변 전달**로 반환한 결과가 바깥 캔버스의 **Agent 팀** 블록의 출력이 됩니다. 결과를 사용할 다음 블록에 데이터선을 연결하세요.
- **팀 지침** · 팀 목표는 모든 하위 Agent에게 전달됩니다. **도구 및 자료 → 팀에 연결할 Skill**에서 공통으로 쓸 Skill과 버전을 연결하세요. 각 담당자의 **전달받을 상위 Skill**에는 팀에 연결된 Skill의 이름과 버전이 표시됩니다. 그중 해당 담당자가 사용할 항목을 선택하세요.
- **예시** · 도서관 공지 초안을 팀에 넘깁니다. 사실 확인 담당과 문장 검토 담당이 초안을 교차 검토하고, 팀이 수정된 공지 한 건을 반환합니다.

### 20. Agent에게 작업 전달

특정 역할에 일을 맡깁니다. **작업 방식**에서 기존 담당자가 후속 단계를 맡을지, 새 담당자에게 넘길지 정합니다.

- **설정과 결과** · 역할과 맡길 일을 적고 필요하면 내부 설계를 지정합니다. **결과 돌려받기**는 일을 맡긴 쪽에 결과를 반환해 기존 담당자가 후속 단계를 맡습니다. **담당 넘기기**를 고르면 그 경로의 다음 단계부터 새 담당자가 맡습니다. 서로 다른 담당자의 경로가 합쳐지면 팀의 **최종 응답 담당**이나 상위 설계의 담당자가 이어받습니다.
- **내부 설계** · 담당자가 맡은 일, 직접 연결한 Skill, 선택한 상위 Skill이 내부 AI 작업에도 전달됩니다. **이 블록이 받는 지침**에서 상위 팀 목표와 적용되는 Skill을 확인할 수 있습니다.
- **예시** · 규정 한 줄의 해석만 확인할 때는 사실 확인 담당에게 맡기고 결과를 돌려받습니다. 이후 문의 전체를 대출 담당자가 처리해야 할 때는 담당을 넘깁니다.

### 21. 병렬 작업

여러 경로에서 독립적인 작업을 함께 시작합니다. **병렬 작업**에서 각 경로의 첫 블록으로 실행선을 연결하세요. 같은 입력값을 모든 경로에 보내려면 **병렬 작업**의 결과를 각 블록의 입력에 데이터선으로 연결하세요.

- **설정과 결과** · 후속 경로를 둘 이상 연결하고 **동시 실행 수**를 정합니다. 블록 기본값은 2입니다. **성공 결과 수집**은 다른 경로의 결과를 합류할 수 있게 하고, **전체 중단**은 오류 시 실행 전체를 멈춥니다.
- **ZIP 실행 한도** · 상위 Workflow와 모든 하위 역할이 모델 호출 72회와 동시 실행 4개를 공유합니다. 클라이언트 한도가 더 낮으면 그 값을 적용합니다. 회신 뒤 재개할 때도 같은 실행의 잔여 횟수를 사용합니다.
- **예시** · 같은 공지문을 한 경로에서는 운영 시간의 정확성, 다른 경로에서는 문장의 읽기 쉬운 정도를 검토하게 합니다.

### 22. 결과 모으기

실행된 경로의 결과를 모아 하나의 값으로 반환합니다.

- **설정과 결과** · 각 경로의 출력을 연결하고 **목록**, **텍스트**, **제목과 본문** 중 한 형식을 고릅니다. **제목과 본문**은 이름이 붙은 항목을 제목과 그 아래 내용으로 표시합니다. 동료 검토 실습에서는 이 형식으로 최종 안내에 검토자별 의견을 붙입니다. 실패한 경로가 연결돼 있으면 **일부 실패** 설정을 적용합니다. **미확인 항목과 함께**는 해당 블록의 이름과 오류를 결과에 포함합니다. **실패 처리**는 실패한 항목이 들어왔을 때 **결과 모으기**에서 오류를 냅니다.
- **예시** · 두 지점의 운영 시간을 조사하다가 한 지점의 조사 블록에서 오류가 났다면 **미확인 항목과 함께**를 선택하세요. 최종 담당자가 다른 지점의 운영 시간과 실패한 블록의 오류를 한 목록에서 확인할 수 있습니다.

### 23. Workflow 재사용

이미 만든 여러 단계의 설계를 하나의 기능처럼 다시 사용합니다.

- **ZIP에서 재사용** · 같은 Workflow의 같은 저장판을 여러 번 부르면 각 호출 단계는 한 벌의 하위 지침을 참조합니다. 지금 호출한 단계의 입력, Skill, 참고 자료, 도구 범위로 작업한 뒤 해당 호출 위치로 결과를 반환하세요. 펼치기 한도에 걸린 하위 참조는 내보내기 화면과 ZIP의 `README.md`에서 해당 호출 단계를 찾아 준비할 수 있습니다.

- **설정과 결과** · 이 블록 안에 설계를 작성하거나 접근 가능한 Workflow와 버전을 선택합니다. **정해진 단계에서 호출**은 이 블록이 실행될 때 호출해 결과를 돌려줍니다. **Agent가 도구로 호출**을 고르면 **도구 이름**과 **사용할 때**를 입력하고, **목표까지 반복**으로 설정한 **AI 작업**에 참조선으로 연결합니다. 같은 Agent에 연결한 도구는 이름이 서로 달라야 합니다. 모델은 **사용할 때**에 적은 설명을 읽고 도구를 선택합니다. 전용 하위 Agent는 위임된 입력이 담당 업무에 속하는지도 확인합니다.
- **예시** · 모든 안내문에 공통 검사를 적용하려면 ‘공지 검사’ Workflow 2판을 정해진 단계에서 호출합니다. 필요한 문의에만 검사하려면 같은 Workflow를 Agent가 고를 수 있는 도구로 연결합니다.

### 24. 사람 검토

실행을 시작한 이용자가 초안이나 판단 결과를 읽고 검토 의견을 보낼 때까지 기다립니다. 의견을 보내면 같은 실행이 이어집니다.

- **설정과 결과** · 초안을 입력값에 연결하고 **검토할 사항**에 확인할 내용을 적습니다. 회신 화면에서 초안과 검토할 사항을 읽고 **검토 의견**을 입력합니다. **검토할 사항**에 `{{input}}`을 쓰면 초안이 그 자리에 들어갑니다. 이 기호를 생략하면 별도의 **검토할 초안** 칸에 표시됩니다. 다음 단계에는 **회신 내용**이 전달됩니다.
- **초안과 의견 함께 넘기기** · 초안을 만든 블록의 결과와 **사람 검토**의 회신 내용을 각각 **결과 모으기**의 입력값에 데이터선으로 연결하세요. **사람 검토 → 결과 모으기 → AI 작업** 순서로 실행선을 잇고, 모은 결과를 **AI 작업**의 **입력값**에 데이터선으로 연결하세요.
- **예시** · 안내문 초안을 연결하고 ‘토요일 마감 시각을 확인해 주세요.’라고 적습니다. 검토자가 “오후 4시로 고쳐 주세요.”라고 회신하면 그 의견을 다음 AI 작업에 넘깁니다.

### 25. 기억 읽기·쓰기

나중에 다시 꺼내 쓸 값에 이름을 붙여 저장합니다. 이용자의 선호처럼 질문이 바뀌어도 재사용할 정보를 다룹니다.

- **설정과 결과** · **쓰기**는 문자열, 숫자, 참·거짓, null, 객체, 배열을 입력 형식 그대로 저장합니다. **읽기**는 같은 **기억 이름**에 저장된 값을 반환하므로 CSV의 행·열과 빈 셀도 유지됩니다. 이전 버전에서 저장한 텍스트는 문자열로 읽습니다. 저장한 값이 없으면 빈 문자열을 돌려줍니다. 실제 사용에서는 같은 이용자의 같은 프로젝트에서 값을 다시 읽을 수 있습니다. 새 시험 대화마다 기억을 따로 저장합니다. 중지되거나 실패한 시험을 재시도하면 원래 시험의 기억을 이어 씁니다.
- **예시** · ‘선호 지점’이라는 이름으로 ‘중앙관’을 저장합니다. 같은 이용자가 이 Agent에서 다음 문의를 보낼 때 이를 읽어 수령 지점의 기본 후보로 사용합니다.

### 26. 시작 조건

어떤 계기로 **새 실행**을 시작할지 정합니다. 수동으로 시작하거나, 지정한 시각 또는 외부 이벤트를 시작점으로 삼습니다.

- **설정과 결과** · **시작 방식**에서 **수동**, **예약**, **이벤트** 중 하나를 고릅니다. **수동**은 현재 초안에서 시험 질문을 보내도 실행됩니다. 자동으로 시작하려면 최상위 캔버스에 이 블록을 두고 **예약**의 **실행 일정**이나 **이벤트**의 **이벤트 이름**을 입력하세요. 소유자가 버전을 게시한 뒤 자동 시작을 활성화합니다. 시작할 때 받은 값을 쓰려면 다음 블록의 입력에 데이터선을 연결하세요.
- **예시** · ‘매일 09:00’을 지정해 한국 시각 오전 9시마다 공지 요약을 시작합니다. 진행 중인 문의에서 이용자의 답을 기다릴 때는 **입력 양식·추가 질문**을 연결합니다. [예약·이벤트 설정 방법](triggers.md)

### 27. 반복 처리

목록의 각 항목에 **같은 내부 Workflow**를 순서대로 적용합니다.

- **설정과 결과** · 반복할 내부 설계와 최대 반복 횟수를 지정합니다. 기본 한도는 5회입니다. 단일 값은 한 번 처리하며, 목록 길이가 한도를 넘으면 한도 오류가 발생합니다. 완료하면 항목별 결과가 순서대로 담긴 목록을 받습니다.
- **예시** · `["중앙관","호수관","숲도서관"]`을 받아 각 지점의 공지를 같은 형식으로 정리하고, 공지 세 건을 입력 순서대로 모읍니다.

### 28. 담당자·작업 선택

AI가 판단 기준에 따라 후보 중 담당자 한 명을 고르거나 허용된 작업의 순서를 정합니다. 이 블록은 고른 담당자 이름이나 작업 순서만 반환합니다.

- **설정과 결과** · **담당자 한 명 선택**은 후보와 기준을 받아 이름 하나를 반환합니다. **작업 순서 정하기**는 허용 작업, 목표, 선택 한도를 받아 중복을 제거한 순서 목록을 반환합니다. 실제 배정이나 실행은 결과를 받은 후속 블록에서 설계합니다. 이전 메뉴 이름은 각각 ‘후보 탐색·선택’, ‘작업 조정’입니다.
- **예시** · “예약한 책을 어디서 받나요?”라는 문의에서 **담당자 한 명 선택**은 `예약 담당`, **작업 순서 정하기**는 `["예약 조회","수령 지점 안내"]`를 반환할 수 있습니다.

### 29. 결과 평가

AI가 산출물을 설계자의 평가 기준으로 채점합니다. 그 점수를 사용해 초안을 보낼지, 다시 검토할지 결정할 수 있습니다.

- **설정과 결과** · 평가 기준과 통과 점수(기본 70점)를 정합니다. 점수(`score`), 적용한 통과 점수(`threshold`), 이유(`reason`), 통과 여부(`passed`), 평가한 원래 입력(`input`)을 반환합니다. 텍스트 답변과 JSON에 점수·통과 기준·이유·판정이 표시됩니다. 결과에 따라 경로를 바꾸려면 **조건 분기**를 연결합니다.
- **예시** · “수령 지점과 운영 시간을 모두 안내했는가?”를 **평가 기준**에 적고 **통과 점수**를 80점으로 둡니다. 다음 **조건 분기**에서는 `passed`를 `true`와 비교합니다. **맞음** 경로에서는 공지를 전달하고, **그 밖의 경우**에는 평가 이유를 사용해 수정을 요청합니다.

## 전문가

### 30. 필요한 Agent 만들기

실행 입력에서 처리 대상을 읽고 **대상마다 담당 Agent를 생성**합니다. 설계할 때 대상 수를 알 수 없는 조사에 적합합니다.

- **생성 한도와 대상 선택** · 담당자에게 허용할 역할과 지시, **전체 생성 상한**, **동시 실행 상한**을 정합니다. **전체 생성 상한**은 같은 실행 안에서 이 블록이 만든 담당자를 누적해 셉니다. 입력 목록이나 구분 문자로 나눈 텍스트에서 중복 대상을 제거합니다. 남은 생성 한도가 1명 이상이고 대상이 더 많으면 이용자가 남은 인원수만큼 대상을 고릅니다. 남은 한도가 0명이면 한도 오류로 끝납니다.
- **원문 근거 확인** · 하위 설계가 확인한 원문 근거를 완료 조건으로 지정하면 각 담당자가 반환한 인용을 확인합니다. 판을 모르면 판 번호를 묻고, 같은 판의 원문이 필요하면 해당 대상의 배정에서 파일을 기다립니다.
- **미완료 시 처리** · **새 담당자 생성과 후속 정리 중단**을 고르면 미완료가 나온 차수에서 새 담당자 생성과 후속 정리가 중단됩니다. 실행 기록에서 해당 문답의 **실행 경로**를 열면 중단 사유와 **선택 후 미시작** 대상을 볼 수 있습니다. **확인된 결과와 미완료 사유 수집**을 고르면 미완료 사유도 결과에 담습니다. 모두 완료했거나 미완료 사유를 수집한 경우, 출력에는 담당자별 결과와 선택에서 제외된 대상이 따로 표시됩니다. 생성 한도 때문에 대상을 골랐다면 후속 블록은 선택이 필요했던 이유와 처음 요청한 대상 수, 실제 선택한 대상 수도 받습니다.
- **예시** · 지점 4곳을 입력하고 전체 한도를 3, 동시 한도를 2로 둡니다. 이용자가 고른 3곳을 먼저 2곳, 이어서 1곳 조사합니다. 완료 조건을 ‘하위 설계가 확인한 원문 근거 필요’로 두면 인용을 확인한 지점과 근거가 부족한 지점을 구분할 수 있습니다.

### 31. 지식 저장소 관리

여러 실행에서 반복 검색할 원문을 **이름과 버전이 있는 자료집**으로 관리합니다. 실제 사용 환경에서 색인하고 발행한 자료집은 같은 프로젝트의 다른 실행에서도 **자료 검색**으로 이름과 버전을 지정해 찾을 수 있습니다. 시험에서 발행한 버전은 그 시험의 저장 공간에서만 쓸 수 있습니다.

- **설정과 결과** · **준비**는 연결한 원문을 모읍니다. 자료집 이름과 버전을 지정하면 모은 원문을 초안으로 저장합니다. 나중에 같은 자료집과 버전으로 **색인**하면 저장한 원문에서 검색할 구절과 위치를 만듭니다. **발행**과 **철회**에는 자료집 이름이 필수입니다. 색인한 버전을 **발행**하거나, 이미 발행한 버전을 **철회**하려면 소유자가 승인해야 합니다. 발행했던 내용을 바꿀 때는 새 버전을 만듭니다.
- **예시** · 개정 운영 규정을 ‘도서관 규정’ 2판으로 색인하고 승인해 발행합니다. 같은 프로젝트의 **자료 검색**에서 자료집 ‘도서관 규정’과 2판을 지정해 질문에 맞는 구절을 찾습니다.

### 32. 문맥 정리·압축

긴 대화나 여러 담당자의 결과에서 앞으로 필요한 정보를 짧은 텍스트로 요약합니다.

- **설정과 결과** · **보존할 내용**에 필요한 사실과 참조를 적습니다. 쉼표나 줄바꿈으로 구분한 항목 중 `파일 이름`·`파일명`·`fileName` 또는 `원문 위치`·`location`을 지정하면, 입력 객체와 목록에 있는 해당 필드의 값이 요약에도 들어 있는지 실행기가 확인합니다. 나머지 자연어 요구는 모델에 전달합니다. 글자 수는 한글 조합 자소처럼 함께 표시되는 문자 묶음을 한 글자로 셉니다. 공백뿐인 요약, 참조 누락, 길이 초과는 실패로 처리합니다.
- **예시** · 지점 조사 결과를 300자 이내로 요약해 넘기려면 **보존할 내용**에 ‘지점명, 확인 날짜, 원문 위치’를 적고 **고급 설정 → 최대 글자 수**에 `300`을 입력하세요.

## 비슷한 블록 중 무엇을 고를까요?

| 만들려는 흐름 | 고를 블록 | 판단 기준 |
|---|---|---|
| 문의에 맞는 경로를 정한다 | **AI 분류** 또는 **조건 분기** | “책을 더 보고 싶어요”의 의미를 해석하면 AI 분류, ‘대출 일수 > 14’처럼 비교식이 정해져 있으면 조건 분기입니다. |
| 사람이 참여하는 단계를 둔다 | **입력 양식·추가 질문**, **사람 검토**, **행동 승인** | 빠진 값을 받으면 추가 질문을 쓰고 필요할 때 기한을 켭니다. 초안에 대한 의견이면 사람 검토, 특정 외부 변경에 동의를 받으면 행동 승인입니다. |
| 질문에 답할 근거를 찾고 확인한다 | **자료 가져오기 → 자료 검색 → 근거·출처 확인** | 참조선으로 원문을 **자료 검색**에 전달합니다. 질문과 관련된 구절을 찾고, 그 구절이 질문에 답할 근거가 되는지 확인합니다. 답변까지 만들려면 **근거 있음** 경로에서 인용할 구절을 **AI 작업**에 전달합니다. |
| 여러 작업을 처리한다 | **병렬 작업**, **반복 처리**, **필요한 Agent 만들기** | 미리 정한 여러 경로를 함께 시작하려면 **병렬 작업**, 목록의 각 항목에 같은 절차를 순서대로 적용하려면 **반복 처리**를 씁니다. 미리 정한 역할을 맡을 담당자를 입력 대상마다 한 명씩 만들려면 **필요한 Agent 만들기**를 씁니다. |
