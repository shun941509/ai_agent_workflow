# 자료함·계정·버전 관리 정밀 검토

자료를 등록하고, 저장한 판을 골라 공유하고, 휴지통에서 복구하는 과정과 로그인부터 권한별 화면까지 Windows Chrome에서 확인했다. [화면 전후 비교 갤러리](precision-data.html)

## 화면별 변경

| 화면 | 발견한 점 | 적용한 변경 |
| --- | --- | --- |
| 로그인·가입 | 인증 실패 후 어떤 입력과 관련된 안내인지 읽기 어려웠다. 좁은 화면에서 입력한 비밀번호를 확인할 수 없었다. | 서버 오류를 아이콘과 문구로 표시하고 자격 증명 오류와 입력란을 연결했다. 입력을 고치면 이전 오류가 사라진다. 비밀번호 표시 버튼은 현재 상태를 읽어 주고 로그인·가입을 전환하면 다시 숨긴다. |
| 내 자료·공유 자료 | 360px에서 새 자료의 종류 버튼 네 개가 세로로 365px를 차지했다. 운영자 전용 MCP 등록이 비활성인 이유도 보이지 않았다. | 모바일은 네 종류를 2열 96px에 배치했다. 선택한 종류의 설명과 MCP 권한은 아래에 표시하고, 스크린리더는 각 버튼의 설명을 읽을 수 있다. 등록·수정 폼 끝에는 취소와 저장을 모았다. |
| 자료 원문·공유 주소 | 현재 공개 상태, 적용 전 변경, 실제 적용 버튼의 구분이 약했다. | 공유 범위를 선택하는 필드에 보이는 레이블을 연결했다. 현재 상태와 적용 전 변경을 구분하고, 공유 실행과 링크 철회·재발급을 별개 동작으로 표시한다. 처리 중에는 범위 선택도 잠긴다. 수신자는 실제 공개된 판에서 연결 또는 사본 만들기를 선택한다. |
| 가져오기·초안 비교·삭제 | 간단한 확인과 부속 파일 목록이 같은 너비로 열렸다. 긴 본문 아래에 확인 버튼이 묻힐 수 있었다. | 단순 확인은 416px, 변경 파일 선택은 640px, 초안 비교는 864px를 기준으로 한다. 자료 삭제는 영향을 받는 Agent를 읽을 수 있는 일반 너비를 쓴다. 공통 헤더·본문·푸터를 사용하여 긴 내용만 스크롤된다. |
| 프로젝트 선택·버전·공유 | 대상 버전과 공개 범위가 한 줄씩 길게 쌓였다. 게시와 현재 링크 철회가 인접했다. | 프로젝트 목록에 목록 의미를 부여하고 취소를 하단에 고정했다. 프로젝트 게시 설정은 내부 너비가 620px 이상이면 버전과 범위를 나란히 보여 준다. 1440px 화면에서 설정 창은 640×648px에서 864×505px가 됐다. 실습의 판단 근거는 독립된 입력 영역에 쓰고, 철회는 위험 동작으로 표시한다. |
| 자료·프로젝트 휴지통 | 모바일에서 복구 버튼 옆의 좁은 공간에 삭제 시각과 기한이 여러 줄로 끊겼다. | 이름·선택·복구 다음에 날짜 두 개를 행 전체 너비에 표시했다. 체크하면 해당 자료 행이 강조된다. 영구 삭제 창은 선택 개수에 맞는 너비로 열리고 취소 버튼에 먼저 초점을 둔다. |
| 개발용 도서관 시안 | 실습 안내와 결과 창의 닫기 버튼이 36px·32px였다. 긴 원문을 읽으면 창 머리글도 함께 올라갔다. | 닫기 버튼에 공통 조작 크기를 적용하고, 모바일에서는 44px를 확보했다. 실습 안내는 목록만 스크롤하고 결과 미리보기는 머리글을 유지한다. 두 창에서 Tab과 Shift+Tab이 내부를 순환한다. |

## 검증 조건

화면 폭은 360·390·768·1024·1280·1440 CSS px다. 작은 두 너비는 Chrome 모바일 터치 에뮬레이션을 사용했다. 각 회차는 새 로컬 SQLite 데이터베이스에서 자료를 저장·조회·공유했다. 같은 제목·원문·판·권한 상태를 재현했고, 계정 식별자·링크·삭제 시각은 독립된 회차마다 새로 생성됐다. 오류·대기 화면은 해당 브라우저의 특정 요청만 지연하거나 503으로 응답한 뒤 원래 서버 응답으로 복구했다.

접근성 자동 검사는 axe-core 4.10.3의 WCAG A·AA 태그로 실행했다. 자동 검사와 별도로 실제 키 입력, 다이얼로그 포커스 순환, 푸터가 화면 안에 있는지, 선택과 저장 결과, 문서 가로 넘침을 확인했다. 개발 시안은 운영 경로가 404를 반환하므로 동일 소스의 개발 모드에서 검증했다. 실물 단말과 스크린리더를 이용한 수동 낭독 검사는 이번 기록에 포함되지 않는다.

## 최종 결과

2026년 11월 27일 운영 빌드 `dfqtlr4Ku6o72eG1oxIJu`에서 검증했다. 개발 시안에는 해당 빌드의 공통 스타일과 시안 소스를 사용했다.

| 점검 | 1차 | 2차 |
| --- | ---: | ---: |
| 일반 자료·계정·공유 화면 | 120 | 120 |
| 운영자·충돌·버전·복구 화면 | 48 | 48 |
| 개발 시안 화면 | 30 | 30 |
| Tab·Shift+Tab 다이얼로그 순환 | 42/42 | 42/42 |
| 다이얼로그 푸터 화면 내부 표시 | 30/30 | 30/30 |
| axe 위반 / 가로 넘침 / 예상 밖 브라우저 오류 | 0 / 0 / 0 | 0 / 0 / 0 |

1차는 기본 모션 설정으로, 2차는 모션 감소 설정으로 진행했다. 별도 실조작 시험에서는 여섯 폭 모두 이전 게스트 작업 선택, 세 가지 파일 선택기, 개별 파일·ZIP 다운로드를 통과했다. 모바일 메뉴를 연 뒤 `aria-controls`가 가리키는 탐색 영역이 표시되는 것도 확인했다. axe는 접힌 메뉴 참조와 일부 요소의 색 대비를 수동 검토 항목으로 남겼다.

360px와 1024px 자료 등록 화면에서 axe가 부분적으로 가려졌다고 분류한 원문 필드에 포커스를 놓고 중앙을 확인했다. 두 너비 모두 실제 입력란이 해당 좌표의 최상위 요소였다. 렌더링 색의 대비는 흰 배경 대비 본문 15.04:1, 입력 힌트 4.61:1이었다.

기존 Chrome 회귀 네 개가 최종 빌드에서 모두 종료 코드 0을 반환했다. [자료 등록·수정·휴지통](../../tests/resource-library-browser.ts), [공유 자료 갤러리와 가입 복귀](../../tests/shared-resource-gallery-browser.ts), [공유 MCP 독립 사본과 권한](../../tests/shared-mcp-copy-browser.ts), [프로젝트 생성·게시·철회](../../tests/creation-sharing-browser.ts)

후보 빌드에서 발견한 두 회귀도 수정 후 검증했다. 프로젝트·자료 공유 범위의 명칭은 해당 select 하나만 가리킨다. 모바일의 Skill 종류 버튼은 화면을 컴팩트하게 유지하면서 기존 접근 가능한 이름과 설명으로도 작동한다.

비교 갤러리에서 33개 화면과 여섯 폭을 조합해 전체·상세 372쌍의 이미지 744장을 실제로 디코딩했다. 360·768·1440px에서 기본·원본 크기 전환 시 가로 넘침, axe 위반, 외부 요청, 페이지 오류는 0건이었다.
