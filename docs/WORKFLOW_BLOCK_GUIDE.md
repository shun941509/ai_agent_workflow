# Workflow 설계 블록 32종 사용 안내서

도서관에 “토요일에 문을 여나요?”라는 질문이 들어왔다고 생각해 보세요. **사용자 입력**이 질문을 받고, **AI 작업**이 **자료 가져오기**로 연결한 운영 규정을 읽어 답을 작성하고, **답변 전달**이 이용자에게 보여 줍니다. 캔버스의 블록 하나는 이처럼 입력을 받거나, 작업을 수행하거나, 다음에 일어날 일을 정하는 한 단계입니다.

## 원하는 수준부터 찾아보기

초안에 대한 의견을 받을 때는 고급의 **사람 검토**를, 다음 담당자에게 넘길 요약의 최대 길이를 정할 때는 전문가의 **문맥 정리·압축**을 캔버스에 독립 블록으로 추가합니다.

| 처음 소개되는 수준 | 새 메뉴 | 누적 메뉴 | 이 수준에서 설계할 수 있는 일 |
|---|---:|---:|---|
| [입문](#입문) | 4 | 4 | 질문을 받고 자료를 참고해 답하기 |
| [초급](#초급) | 4 | 8 | 추가로 질문하고, 첨부 파일을 읽어 결과를 파일로 내려받기 |
| [중급](#중급) | 10 | 18 | 경로 나누기, 근거 찾기, 도구 오류 처리와 민감정보 가리기 |
| [고급](#고급) | 11 | 29 | 담당자 선택, 병렬 협업, 팀 결과 평가와 자동 시작 |
| [전문가](#전문가) | 3 | 32 | 담당자 동적 생성, 자료판 관리와 문맥 압축 |

팔레트의 **추천**은 선택한 수준까지의 메뉴를 보여 줍니다. **전체 32종**에서는 모든 메뉴를 찾을 수 있습니다. 다섯 메뉴는 속성의 **작업 방식**에서 두 가지 방식 중 하나를 고릅니다. **답변 전달**은 **종료 방식**에서 네 가지 중 하나를 고릅니다. **작업 지침·Skill**과 **MCP 연결**은 블록 속성에서 연결하는 참조입니다. Skill은 작업 절차를, MCP 연결은 사용할 도구가 등록된 서버를 지정합니다.

**연결선 읽는 법** · 실선은 **실행 순서**, 파선은 **전달할 값**, 점선은 **참고할 자료·지침·도구**를 뜻합니다. 예를 들어 검색 결과를 AI에 넘길 때는 검색이 끝나면 AI를 실행하도록 순서를 연결하고, 찾은 구절도 AI의 입력값에 연결합니다. 같은 두 블록 사이의 연결은 화면에서 한 선으로 묶일 수 있습니다. 선을 선택하면 전달 항목을 확인할 수 있습니다.

## 입문

**첫 입력 연결하기** · **답변 전달**을 먼저 놓았다면 속성의 **입력값 받기**를 누르세요. 값을 보낼 블록이 없을 때 **사용자 입력 추가 및 연결**을 누르면 질문을 받는 블록과 답변으로 가는 연결이 생깁니다. 연결 창을 취소하거나 `Esc`로 닫으면 **입력값 받기**에서 키보드 작업을 이어갈 수 있습니다.

### 01. 사용자 입력

이용자가 실행을 시작하며 보낸 질문이나 요청을 Workflow의 첫 값으로 전달합니다.

- **설정과 결과** · 속성에 적은 ‘예시 질문’이 편집기의 첫 시험 입력칸에 표시됩니다. 예시가 비어 있으면 실습의 질문을 사용하며, 이용자가 고쳐 쓴 문장이 실행에 전달됩니다. 질문에 파일을 첨부한 경우 파일 본문은 **파일 입력**으로 받을 수 있습니다.
- **예시** · 이용자가 “회원증을 만들려면 무엇을 가져가나요?”라고 보내면 그 문장이 다음 AI 작업의 입력이 됩니다.

### 02. AI 작업

질문, 참고 자료, 작업 지시를 모델에 전달해 답변이나 초안을 만듭니다. 입문 수준의 **추천**에서 **AI 작업**을 추가하면 **한 번 답하기**로 시작합니다. 속성의 **작업 방식**에서 **목표까지 반복**을 선택할 수 있습니다.

- **설정과 결과** · **한 번 답하기**는 모델에 한 번 요청합니다. **목표까지 반복**은 허용된 도구나 연결된 Workflow를 선택해 사용하고 그 결과로 다음 판단을 할 수 있습니다. 최대 판단 횟수 안에 답을 완성해야 합니다.
- **예시** · 규정 한 문장을 읽고 회원증 준비물을 알려줄 때는 **한 번 답하기**를 씁니다. 문의 내용에 따라 예약 조회가 필요할 때는 **목표까지 반복**을 선택하고 조회 도구를 허용합니다.

### 03. 답변 전달

경로 마지막에 놓고 결과를 어떻게 전달할지 정합니다. 팀이나 하위 Workflow 안에서 반환한 결과는 호출한 쪽이 받습니다.

| 종료 방식 | 실행 결과 |
|---|---|
| **답변 반환** (기본) | 실행선이 도착하면 데이터선으로 연결한 답변을 반환합니다. |
| **완료 안내** | 설정한 문구로 경로를 마칩니다. 문구가 비어 있으면 받은 값을 반환합니다. |
| **실행 중지** | 전체 실행을 중지 상태로 끝냅니다. |
| **실패 처리** | 설정한 문구로 해당 경로에 오류를 발생시킵니다. 처리되는 경로가 없으면 실행은 실패로 끝납니다. |

- **예시** · 예약 승인 경로에서는 **답변 반환**으로 예약 내역을 돌려주고, 거절 경로에서는 **완료 안내**로 “예약을 변경하지 않았습니다.”를 표시합니다. 이전 설계의 **종료·중단**을 선택하면 저장된 상태에 맞는 종료 방식과 원래 연결선을 볼 수 있습니다.

### 04. 자료 가져오기

설계자가 정한 원문을 다른 블록이 읽을 수 있게 합니다. 여러 이용자가 같은 규정을 참고해야 할 때 유용합니다.

- **설정과 결과** · 블록에 원문을 적거나 자료 라이브러리의 항목과 버전을 고릅니다. 참조선으로 연결하면 자료의 정체와 본문을 함께 참고하고, 데이터선으로 연결하면 본문을 값으로 전달합니다.
- **원문 편집** · 직접 적은 원문은 이 브라우저에 임시 보관되어 프로젝트를 다시 열면 이어 쓸 수 있습니다. **변경 적용**이나 **프로젝트 저장**을 누르면 시험 실행에 반영됩니다.
- **예시** · ‘도서관 이용규정’ 1판을 AI 작업의 참고 자료에 연결해, 답변할 때 사용할 운영 시간을 정합니다.

## 초급

### 05. 입력 양식·추가 질문

실행 도중 필요한 정보가 빠졌을 때 이용자에게 질문하고, 답이 오면 같은 실행을 이어갑니다.

- **설정과 결과** · 질문 문구만 설정하면 회신한 글이 다음 입력이 됩니다. ‘입력 항목’에 이름을 추가하고 필수 여부를 정하면 이용자에게 항목별 입력칸이 열립니다. 빠진 필수 항목은 같은 실행에서 보완하고, 다음 블록은 항목 이름과 값이 담긴 객체를 받습니다.
- **회신 기한** · 새 질문은 기한 없이 시작합니다. 속성의 **회신 기한 사용**을 켜면 60분이 제안됩니다. 1~10,080분 사이로 정할 수 있으며, 시간은 실행이 이 질문에 도착할 때부터 계산됩니다. 회신 화면에는 마감 시각이 표시됩니다. 기한 안에 접수한 회신은 처리가 늦어도 유효하며, 기한이 지나면 연결한 **오류 처리** 경로로 대응할 수 있습니다.
- **예시** · “어느 지점에서 수령하시겠어요?”라는 질문에 필수 항목 `지점`과 기한 30분을 함께 지정합니다. 이용자가 30분 안에 `{"지점":"중앙관"}`으로 답하면 같은 실행에서 예약 준비를 이어갑니다. 기존 설계의 **회신 기다리기** 또는 **조건 기다리기**도 저장된 기한으로 열립니다.

### 06. 파일 입력

이용자가 이번 실행에 첨부한 파일을 받습니다. 실행할 때마다 다른 자료를 처리할 수 있습니다.

- **설정과 결과** · 허용할 확장자를 지정합니다. 기본값은 `.txt`, `.md`, `.json`, `.csv`입니다. 편집기에서 시험 파일 내용을 작성하면 **시험 실행 → 예시 파일로 시험 → 질문 실행**으로 확인할 수 있습니다. 게시된 Agent는 파일 입력 단계에 도달했을 때 첨부가 필요하면 기다립니다. 이용자가 **요청받은 파일**을 선택하고 **첨부하고 같은 실행 이어가기**를 누르면 해당 파일의 이름과 본문을 다음 블록에 전달합니다.
- **예시** · 이용자가 올린 `지점.csv`를 받아 **문서 내용 읽기**에 연결합니다.

### 07. 문서 내용 읽기

파일의 내용을 다음 단계에서 사용할 형식으로 해석합니다. 파일을 받는 일은 **파일 입력**, 받은 데이터를 읽는 일은 이 블록이 맡습니다.

- **설정과 결과** · ‘자동’은 확장자의 대소문자를 구분하지 않습니다. 텍스트는 본문을, JSON은 해석한 값을, CSV는 각 행이 열 목록으로 구성된 배열을 반환합니다.
- **예시** · `[{"지점":"중앙관"},{"지점":"호수관"}]`이 담긴 JSON 파일을 읽으면 **반복 처리**에서 지점을 하나씩 꺼내 쓸 수 있습니다.

### 08. 파일 만들기

완성된 결과를 이용자가 내려받을 수 있는 파일로 만듭니다.

- **설정과 결과** · 파일 이름과 텍스트, JSON, CSV, Markdown 중 형식을 고릅니다. CSV로 읽은 표를 다시 저장하면 행과 열, 셀 안의 쉼표·따옴표·줄바꿈이 보존됩니다. 출력에는 파일 이름, 형식, 내용이 들어가고 실행 화면에 다운로드가 표시됩니다.
- **예시** · AI 작업이 작성한 도서관 안내문을 이 블록에 연결하면 기본 파일명인 `결과.txt`로 내려받을 수 있습니다. 지점별 운영 시간을 표로 저장하려면 같은 항목을 가진 객체 목록을 연결하고 CSV를 선택합니다.

## 중급

### 09. AI 분류

AI가 문의의 의미를 읽고 설계자가 등록한 범주 중 하나를 골라 해당 경로로 보냅니다.

- **설정과 결과** · 등록한 범주와 ‘미분류’의 다음 블록을 각각 연결합니다. 여러 범주가 같은 블록으로 가도 됩니다. 빠진 경로가 있으면 **설계 검사**에서 해당 이름을 눌러 도착 블록을 고릅니다. 데이터선은 이용자의 원래 문의를 전달합니다.
- **범주 바꾸기** · **이름 변경**에서 새 이름을 적용하면 기존 도착 블록으로 이어집니다. 삭제할 때는 확인 창에서 함께 끊어지는 진행 연결의 개수와 도착 블록을 확인할 수 있습니다.
- **예시** · “빌린 책을 더 오래 보고 싶어요.”를 ‘대출’로 분류해 대출 규정 검색으로 보냅니다.

### 10. 조건 분기

이미 알 수 있는 값을 정해진 규칙으로 비교해 두 경로 중 하나를 실행합니다.

- **설정과 결과** · 비교할 항목과 ‘같음’, ‘포함’, ‘보다 큼’, ‘값이 있음’ 중 하나를 정합니다. 조건에 맞는 출구로 진행하면서 입력값을 그대로 넘깁니다.
- **예시** · **결과 평가**가 반환한 `score`가 79보다 크면 ‘맞음’ 경로로, 나머지는 사람 검토 경로로 보냅니다. ‘맞음’ 경로에서는 **값 변환**으로 평가 결과의 `input` 항목을 꺼내 원래 답변을 전달합니다.

### 11. 자료 검색

질문에 답하는 데 사용할 만한 원문 구절을 찾습니다. 결과를 읽는 사람이 출처를 다시 찾아갈 수 있습니다.

- **설정과 결과** · 검색어와 참고할 원문 또는 발행한 자료집의 이름·판을 지정합니다. 관련도순으로 찾거나 검색어가 그대로 있는 행을 고를 수 있습니다. 기본 최대 5개까지 자료 제목, 판, 위치, 발췌문을 담은 목록을 반환합니다.
- **예시** · ‘토요일’이 있는 규정 행을 찾아 “토요일에는 오전 10시부터 오후 4시까지 엽니다.”라는 구절과 그 위치를 **근거·출처 확인**에 전달합니다.

### 12. 근거·출처 확인

찾아낸 구절이 질문에 실제로 답하는지 판단합니다. 비슷한 단어가 검색됐어도 필요한 사실이 없으면 추가 질문으로 보낼 수 있습니다.

- **설정과 결과** · 원래 질문과 검색 후보를 연결하고 근거 충족 기준을 정합니다. **근거 있음·근거 부족·근거 상충** 중 한 경로로 진행하며 채택한 인용과 이유를 전달합니다. 인용은 후보 원문에서 확인되어야 하고, 상충 판단에는 서로 다른 원문 위치 두 곳 이상이 필요합니다.
- **원문 연결하기** · **자료 검색**이 찾은 결과를 **검색된 구절**로 받습니다. 원문을 바로 연결해 둔 설계에서는 이 블록의 **자료 검색 추가**를 누르세요. 편집기가 앞에 검색 블록을 넣고 원문과 질문을 연결합니다. 새 원문은 검색 블록의 **도구 및 자료 → 참고 자료**에서 선택할 수 있습니다.
- **예시** · “토요일 몇 시에 닫나요?”라는 질문에 평일 안내만 있으면 **근거 부족**으로 진행합니다. 서로 다른 두 규정이 토요일 마감 시각을 다르게 명시하면 **근거 상충** 경로에서 확인을 요청할 수 있습니다.

### 13. 도구 사용

예약 조회나 취소처럼 정해진 기능을 호출하고 그 도구가 돌려준 결과를 받습니다.

- **설정과 결과** · **일반 도구 호출**에서는 도구 이름과 보낼 인자를 지정합니다. **보상 작업**은 이미 일어난 변경을 되돌릴 도구와 대상을 지정하는 방식입니다. 전문가 추천 또는 전체 보기에서 선택할 수 있습니다. 외부 상태를 바꾸는 호출에는 해당 도구와 인자에 대한 승인이 필요합니다.
- **예시** · 예약 생성 후 취소할 필요가 생기면, 설계한 후속 경로에서 **보상 작업**으로 취소 도구를 호출합니다. 이때 생성 결과로 받은 예약 번호를 인자로 넘깁니다.

### 14. 행동 승인

외부에 변경을 보내기 전에 이용자가 **어떤 행동을 어떤 대상으로 수행할지** 확인하도록 합니다.

- **설정과 결과** · 도구와 인자를 정하고 **승인**과 **거절** 출구를 연결합니다. ‘승인 안내’에 적은 내용은 실행 화면에서 작업명과 실제 대상 인자와 함께 보입니다. 승인 결과에는 승인 여부, 승인 식별자, 인자가 들어갑니다. 승인 출구 뒤의 **도구 사용**에 실행선과 결과값을 함께 연결하면 같은 요청을 수행할 수 있습니다. 인자가 바뀌면 새 승인이 필요합니다.
- **예시** · 예약 번호 `R-17`의 취소를 요청합니다. 승인하면 해당 예약을 취소하고, 거절하면 종료 안내를 보여 줍니다.

### 15. 값 변환

앞 단계의 결과에서 필요한 부분을 골라 다음 블록이 기대하는 모양으로 바꿉니다.

- **설정과 결과** · 경로로 값을 꺼내거나, 꺼낸 값에 새 이름을 붙여 객체로 만들거나, 문자열로 변환합니다. 지정한 항목이 없으면 블록 이름과 찾던 항목이 실행 오류에 표시됩니다. **오류 처리**를 연결하면 대체 안내를 전달할 수 있습니다.
- **예시** · `{"예약":{"번호":"R-17","지점":"중앙관"}}`에서 경로 `예약.번호`를 고르고 새 이름을 `reservationId`로 정하면 `{"reservationId":"R-17"}`을 받습니다.

### 16. 데이터 검증

입력 데이터에 필요한 항목이 들어 있고 값의 형식이 맞는지 검사합니다.

- **설정과 결과** · ‘필수 항목’과 ‘항목별 기대 형식’을 지정합니다. 조건을 충족하면 검사한 객체를 통과시키고, 항목이 빠지거나 형식이 맞지 않으면 오류를 냅니다.
- **예시** · 지점은 문자열(`string`), 권수는 숫자(`number`)로 지정합니다. `{"지점":"중앙관","권수":3}`은 통과하고, 권수가 문자열 `"세 권"`이면 오류 처리로 보낼 수 있습니다.

### 17. 오류 처리

앞 단계가 실패했을 때 이용자에게 안내하거나 다른 절차로 이어가는 경로를 만듭니다.

- **설정과 결과** · 오류가 날 수 있는 블록 뒤에 연결합니다. **후속 단계로 계속**은 설정한 문구나 받은 오류 정보를 다음 블록에 전달합니다. 대체할 행동은 그 다음 블록으로 연결합니다. **중단**은 오류를 다시 발생시킵니다. 기존 설계의 **안내**와 **대체 경로**는 모두 **후속 단계로 계속**으로 표시되며 원래 연결을 따라 실행됩니다.
- **예시** · 예약 조회에 실패하면 “조회 서비스를 사용할 수 없습니다.”라고 안내하고, 다음 블록에서 안내데스크 연락 방법을 보여 줍니다.

### 18. 민감정보 검사·처리

전달할 텍스트에 지정된 종류의 민감정보가 있는지 검사하고 발견 시 조치합니다.

- **설정과 결과** · 검사할 형식으로 이메일 주소(`email`)와 전화번호(`phone`)를 지정할 수 있습니다. **가리기**는 인식한 부분을 표시 문구로 바꾼 텍스트를 반환하고, **전달 중단**은 발견 시 오류를 발생시킵니다. 검사할 텍스트가 지나가는 위치에 배치합니다.
- **예시** · 문의를 파일로 내보내기 전에 `reader@example.com`을 `[이메일 가림]`으로 바꾸고, 처리한 텍스트를 **파일 만들기**에 전달합니다.

## 고급

### 19. Agent 팀

여러 담당자의 협업 과정을 하나의 블록 안에 설계합니다. 바깥에서는 팀에 일을 맡기고 팀의 최종 결과를 받습니다.

- **설정과 결과** · 팀의 목표와 최종 응답 담당을 적고, 내부 설계를 열어 누가 무엇을 맡고 어떤 순서로 결과를 주고받을지 연결합니다. 팀 내부의 마지막 결과가 바깥 블록의 입력으로 이어집니다.
- **팀 지침** · 팀 목표는 모든 하위 Agent에게 전달됩니다. **도구 및 자료 → 팀에 연결할 Skill**에서 공통 지침을 추가하고, 각 담당자의 **전달받을 상위 Skill**에서 필요한 자료판을 선택합니다.
- **예시** · 도서관 공지 초안을 팀에 넘깁니다. 사실 확인 담당과 문장 검토 담당이 초안을 교차 검토하고, 팀이 수정된 공지 한 건을 반환합니다.

### 20. Agent에게 작업 전달

특정 역할에 일을 맡깁니다. 두 작업 방식의 차이는 **담당자가 결과를 낸 다음 누가 책임을 이어받는가**입니다.

- **설정과 결과** · 역할, 맡길 일, 필요하면 내부 설계를 지정합니다. **결과 돌려받기**는 하위 담당자의 결과를 원래 담당자에게 돌려줍니다. **담당 넘기기**는 다음 경로의 응답 책임까지 새 담당자에게 인계합니다.
- **내부 설계** · 담당자가 맡은 일, 직접 연결한 Skill, 선택한 상위 Skill이 내부 AI 작업에도 전달됩니다. **이 블록이 받는 지침**에서 상위 팀 목표와 적용되는 자료판을 확인할 수 있습니다.
- **예시** · 규정 한 줄의 해석만 확인할 때는 사실 확인 담당에게 맡기고 결과를 돌려받습니다. 이후 문의 전체를 대출 담당자가 처리해야 할 때는 담당을 넘깁니다.

### 21. 병렬 작업

미리 그려 둔 여러 경로에 같은 입력을 보내 독립적인 일을 함께 시작합니다.

- **설정과 결과** · 후속 경로를 둘 이상 연결하고 동시 실행 수를 정합니다. 기본값은 2입니다. 일부 경로가 실패했을 때 성공한 결과를 수집할지, 전체 작업을 중단할지도 정할 수 있습니다. 각 경로의 결과는 **결과 모으기**에서 합칩니다.
- **예시** · 같은 공지문을 한 경로에서는 운영 시간의 정확성, 다른 경로에서는 문장의 읽기 쉬운 정도를 검토하게 합니다.

### 22. 결과 모으기

여러 경로에서 실제로 도착한 결과를 하나의 값으로 합칩니다.

- **설정과 결과** · 각 경로의 출력을 연결하고 목록, 텍스트, 제목과 본문 중 한 형식을 고릅니다. ‘제목과 본문’은 이름이 붙은 항목을 제목과 그 아래 내용으로 표시합니다. 동료 검토 실습에서는 이 형식으로 최종 안내에 검토자별 의견을 붙입니다. 일부 작업이 실패하면 역할과 오류를 포함하거나 합류 단계에서 실패로 처리할 수 있습니다.
- **예시** · 두 지점의 운영 시간을 조사했는데 한 곳만 확인되었다면, 확인된 안내와 다른 지점의 오류를 목록으로 모아 최종 담당자가 읽게 합니다.

### 23. Workflow 재사용

이미 만든 여러 단계의 설계를 하나의 기능처럼 다시 사용합니다.

- **설정과 결과** · 이 블록 안에 설계를 작성하거나 접근 가능한 Workflow와 버전을 선택합니다. **정해진 단계에서 호출**은 그 지점에서 실행해 결과를 돌려줍니다. **Agent가 도구로 호출**은 이름과 사용 시점을 적어 AI 작업에 참조선으로 연결하고, Agent가 선택했을 때 실행합니다.
- **예시** · 모든 안내문에 공통 검사를 적용하려면 ‘공지 검사’ Workflow 2판을 정해진 단계에서 호출합니다. 필요한 문의에만 검사하려면 같은 Workflow를 Agent가 고를 수 있는 도구로 연결합니다.

### 24. 사람 검토

사람이 초안이나 판단 결과를 읽고 의견을 작성할 때까지 실행을 멈춥니다. 검토 의견을 반영할 때 유용합니다.

- **설정과 결과** · 초안을 입력값에 연결하고 ‘검토할 사항’에 확인할 내용을 적습니다. 회신 화면에서 초안과 검토할 사항을 읽고 **검토 의견**을 입력합니다. 기존 문구에 `{{input}}`이 있으면 그 위치에 초안을 한 번 표시합니다. 다음 단계에는 **회신 내용**이 전달되므로, 원문과 의견이 모두 필요하면 원문도 연결합니다.
- **예시** · 안내문 초안을 연결하고 ‘토요일 마감 시각을 확인해 주세요.’라고 적습니다. 검토자가 “오후 4시로 고쳐 주세요.”라고 회신하면 그 의견을 다음 AI 작업에 넘깁니다.

### 25. 기억 읽기·쓰기

나중에 다시 꺼내 쓸 값을 이름을 붙여 저장합니다. 이용자의 선호처럼 질문이 바뀌어도 재사용할 정보를 다룹니다.

- **설정과 결과** · **쓰기**는 입력을 텍스트로 저장하고, **읽기**는 같은 기억 이름의 값을 반환합니다. 저장한 값이 없으면 빈 문자열을 돌려줍니다. 실제 사용 기억은 이용자와 프로젝트별로 구분되고, 시험 기억은 시험 대화 범위에서 다룹니다.
- **예시** · ‘선호 지점’이라는 이름으로 ‘중앙관’을 저장합니다. 같은 이용자가 이 Agent에서 다음 문의를 보낼 때 이를 읽어 수령 지점의 기본 후보로 사용합니다.

### 26. 시작 조건

어떤 계기로 **새 실행**을 시작할지 정합니다. 수동으로 시작하거나, 지정한 시각 또는 외부 이벤트를 시작점으로 삼습니다.

- **설정과 결과** · **수동·예약·이벤트** 중에서 고릅니다. 예약과 이벤트는 버전을 게시하고 소유자가 ‘자동 시작’을 활성화해야 합니다. 일치하는 조건으로 시작되면 그 실행의 입력을 후속 블록에 전달합니다.
- **예시** · ‘매일 09:00’을 지정해 한국 시각 오전 9시마다 공지 요약을 시작합니다. 진행 중인 문의에서 이용자의 답을 기다릴 때는 **입력 양식·추가 질문**을 연결합니다. [예약·이벤트 설정 방법](triggers.md)

### 27. 반복 처리

목록의 각 항목에 **같은 내부 Workflow**를 순서대로 적용합니다.

- **설정과 결과** · 반복할 내부 설계와 최대 반복 횟수를 지정합니다. 기본 한도는 5회입니다. 단일 값은 한 번 처리하며, 목록 길이가 한도를 넘으면 한도 오류가 발생합니다. 완료하면 항목별 결과가 순서대로 담긴 목록을 받습니다.
- **예시** · `["중앙관","호수관","숲도서관"]`을 받아 각 지점의 공지를 같은 형식으로 정리하고, 공지 세 건을 입력 순서대로 모읍니다.

### 28. 담당자·작업 선택

AI가 설계자가 허용한 목록과 판단 기준을 보고 적합한 이름이나 실행할 작업의 순서를 고릅니다. 이 블록의 출력은 **선택 결과**입니다.

- **설정과 결과** · **담당자 한 명 선택**은 후보와 기준을 받아 이름 하나를 반환합니다. **작업 순서 정하기**는 허용 작업, 목표, 선택 한도를 받아 중복을 제거한 순서 목록을 반환합니다. 실제 배정이나 실행은 결과를 받은 후속 블록에서 설계합니다. 이전 메뉴 이름은 각각 ‘후보 탐색·선택’, ‘작업 조정’입니다.
- **예시** · “예약한 책을 어디서 받나요?”라는 문의에 첫 방식은 `예약 담당`을, 둘째 방식은 `["예약 조회","수령 지점 안내"]`를 선택할 수 있습니다.

### 29. 결과 평가

AI가 산출물을 설계자의 평가 기준으로 채점합니다. 그 점수를 사용해 초안을 보낼지, 다시 검토할지 결정할 수 있습니다.

- **설정과 결과** · 평가 기준과 통과 점수(기본 70점)를 정합니다. 점수(`score`), 이유(`reason`), 통과 여부(`passed`), 평가한 원래 입력(`input`)을 반환합니다. 결과에 따라 경로를 바꾸려면 **조건 분기**를 연결합니다.
- **예시** · “수령 지점과 운영 시간을 모두 안내했는가?”를 기준으로 80점을 통과선으로 둡니다. 다음 **조건 분기**에서 `passed`가 참이면 공지 전달 경로로 보내고, 거짓이면 평가 이유를 사용해 수정을 요청합니다.

## 전문가

### 30. 필요한 Agent 만들기

실행 입력에서 처리 대상을 읽고 **대상마다 담당 Agent를 생성**합니다. 설계할 때 대상 수를 알 수 없는 조사에 적합합니다.

- **설정과 결과** · 허용 역할과 지시, 전체 생성 상한, 동시 실행 상한을 정합니다. 입력 목록이나 구분 문자로 나눈 텍스트에서 중복 대상을 제거합니다. 대상 수가 생성 한도를 넘으면 이용자가 이번에 포함할 대상을 고릅니다. 일부 미완료 시 중단하거나, 확인된 결과와 미완료 사유를 함께 수집하도록 설정합니다. 출력에는 담당 결과와 선택에서 제외된 대상이 구분됩니다. 한도를 넘어 대상을 골랐다면 후속 블록에 선택 사유와 요청·선택 건수도 전달됩니다.
- **예시** · 지점 4곳을 입력하고 전체 한도를 3, 동시 한도를 2로 둡니다. 이용자가 고른 3곳을 먼저 2곳, 이어서 1곳 조사합니다. 완료 조건을 ‘하위 설계가 확인한 원문 근거 필요’로 두면 인용을 확인한 지점과 근거가 부족한 지점을 구분할 수 있습니다.

### 31. 지식 저장소 관리

여러 실행에서 반복 검색할 원문을 **이름과 버전이 있는 자료집**으로 관리합니다. 여기서 자료판을 만들어 두면 **자료 검색**이 특정 판을 지정해 조회할 수 있습니다.

- **설정과 결과** · **준비**는 원문을 정리하고, **색인**은 검색에 쓸 구절과 위치를 만듭니다. 다음 실행에서도 쓰려면 자료집 이름과 판을 지정합니다. **발행**과 **철회**에는 자료집 이름이 필수입니다. 소유자가 승인한 뒤 색인한 판을 검색 대상으로 열거나 발행 중인 판을 철회하면 완료됩니다. 발행했던 내용을 바꿀 때는 새 판을 만듭니다.
- **예시** · 개정 운영 규정을 ‘도서관 규정’ 2판으로 색인하고 승인해 발행합니다. 같은 프로젝트의 **자료 검색**에서 자료집 ‘도서관 규정’과 2판을 지정해 질문에 맞는 구절을 찾습니다.

### 32. 문맥 정리·압축

긴 대화나 여러 담당자의 결과에서 앞으로 필요한 정보를 짧은 텍스트로 요약합니다.

- **설정과 결과** · 보존할 내용과 최대 글자 수를 지정합니다. AI가 입력을 요약하고 길이 한도를 확인합니다. 결과가 한도를 넘으면 오류로 처리합니다.
- **예시** · 지점 조사 결과를 다음 담당자에게 넘기기 전에 “지점명, 확인 날짜, 원문 위치를 남기고 300자 이내로 요약”하도록 설정합니다.

## 블록을 고를 때 자주 갈리는 지점

| 만들려는 흐름 | 고를 블록 | 판단 기준 |
|---|---|---|
| 문의에 맞는 경로를 정한다 | **AI 분류** 또는 **조건 분기** | “책을 더 보고 싶어요”의 의미를 해석하면 AI 분류, ‘대출 일수 > 14’처럼 비교식이 정해져 있으면 조건 분기입니다. |
| 사람이 참여하는 단계를 둔다 | **입력 양식·추가 질문**, **사람 검토**, **행동 승인** | 빠진 값을 받으면 추가 질문을 쓰고 필요할 때 기한을 켭니다. 초안에 대한 의견이면 사람 검토, 특정 외부 변경에 동의를 받으면 행동 승인입니다. |
| 자료에 근거한 답을 만든다 | **자료 가져오기 → 자료 검색 → 근거·출처 확인** | 설계에 원문을 제공하고, 질문과 관련된 구절을 찾은 뒤, 그 구절이 답을 뒷받침하는지 판단합니다. 첫 연결은 원문을 제공하는 참조선입니다. |
| 여러 작업을 처리한다 | **병렬 작업**, **반복 처리**, **필요한 Agent 만들기** | 미리 정한 여러 경로를 함께 열면 병렬 작업, 같은 절차를 목록 순서대로 적용하면 반복 처리, 입력된 대상마다 역할을 생성하면 필요한 Agent 만들기입니다. |

메뉴와 속성은 블록 정의에서, 입력이 실제로 어떻게 처리되는지는 실행기에서 확인할 수 있습니다. 도서관 실습에는 질문 입력부터 근거 확인과 병렬 조사까지 연결된 설계 예시가 들어 있습니다. [블록 정의](../src/domain/catalog.ts) · [블록 실행기](../src/engine/operations.ts) · [수준별 실습](../src/domain/templates.ts)
